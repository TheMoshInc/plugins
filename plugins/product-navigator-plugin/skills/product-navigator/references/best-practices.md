# 商品参照のベストプラクティス

## ID 参照の確認手順

| ID | MCP で取得できるか | 取得経路 |
|---|---|---|
| `productId` | ✅ | `getCreatorProducts` の結果の `id` |
| `productPlanId` | ✅ | `getCreatorProductPlans` の結果の `id` |

ユーザーに ID を尋ねない。商品名・プラン名で特定し、曖昧なら候補を提示して選んでもらう。

## 提示の組み立て方

- **一覧の提示**は「商品名 / 公開ステータス / プラン数 / 公開 URL（あれば）」程度に絞り、全項目を並べない
- **プランの提示**は「プラン名 / 価格 / 課金サイクル / 販売状態 / 定員・残り枠」を基本に、質問に応じて追加する
- 件数が多い**商品一覧**は最初の 1 ページ（20 件）を提示し、続きが必要か確認してから追加取得する（プラン一覧は 1 回で全件返るため分割しない）
- 「価格」はサブスクリプションなら課金サイクル・課金回数・初回価格まで添えて誤解を防ぐ
- 受付停止（`isSuspended`）と非公開（`PRIVATE`）は意味が違う。混ぜずに書き分ける（停止=公開されたまま受付だけ停止）

## セルフレビューチェックリスト

提示の直前に確認する。

| # | 確認項目 |
|---|---|
| 1 | 生の内部 ID・Tiptap JSON・enum の英字値が提示に混ざっていないか |
| 2 | enum は変換表どおりの日本語になっているか |
| 3 | `publicUrl: null` を異常として説明していないか |
| 4 | プラン一覧の 0 件を「商品が存在しない」と断定していないか |
| 5 | ページングの続きがあるのに「全 ◯ 件」と言い切っていないか（商品一覧の `totalCount` と照合） |
| 6 | 更新系の依頼に対して、参照専用である旨と管理画面の案内を返しているか |
