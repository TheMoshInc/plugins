# レポート完成形: 構造レビューのみ（下書き・実績ゼロ）

Step 4 で、対象が下書き（または一度も稼働していない）ときの見本。**実在の誤設定パターン（順序矛盾・合流の見落とし・LINE起点のメール配信・受け皿の無いタグ）を1本に合成した架空例**で、名称はそのまま使わない。

体裁の要点:

- **「このワークフローの動き」を必ず書く**。分岐は両側とも書き下す（構造レビューの主成果物。ユーザーはここでズレに気づく）
- 実績が無いことを言い訳にしない。構造から確定できることは断定してよい（S-2 のような順序矛盾）
- 構造から確定できないこと（意図）は必ず質問にする。`serviceId` は商品・プラン一覧と突き合わせて**名前が分かることもある**（この例では分かった前提）が、旧来のサービス（商品化されていないもの）だと分からないことも多く、その場合も含めて**名前が意図と合っているか**は必ず質問にする
- 内部表現（ワークフローID・ステージID・タグID・JSON）を1つも出さない

## ワークフローレビュー: 「LINE登録後フォロー」（下書き）

### 総合判定: 要修正（1件）／要確認（4件）

**このまま公開すると、3ステップ目の「診断結果フォロー」は誰にも届きません**。分岐で見ているタグを、最後のステップで付けているためです。あわせて、LINEの友だち追加から始まるワークフローに終盤メール配信が入っており、対象者の大半に届かない可能性があります。この2点を直すのが公開前の最優先です。

### 見た範囲

- このワークフローは**まだ公開されていません（下書き）**。実際に動いた記録はないため、**構造だけを見たレビュー**です
- 同じアカウントの他のワークフロー（全12本）とのタグの受け渡しも確認しています
- 「体験レッスン」のようなプラン・サービスの指定先は、商品一覧と突き合わせて実在・名前を確認済みです。名前が意図通りかだけ確認をお願いしています（下記4）

### このワークフローの動き

1. LINE公式アカウント「◯◯サロン公式」に友だち追加された方が対象
2. すぐに、ごあいさつのLINEを配信
3. 1日待つ
4. **「診断済み」タグが付いているかで分岐**
   - 付いている人 → 「診断結果のフォロー」をLINE配信
   - 付いていない人 → 何もしない（この分岐では止まらず、5に進みます）
5. 5日待つ
6. **「体験レッスン」に申し込んでいるかで分岐**
   - 申し込んでいる人 → 何もしない（この分岐では止まらず、7に進みます）
   - 申し込んでいない人 → 再案内をLINE配信
7. 14日待つ
8. 特典のご案内を**メール**で配信
9. 「フォロー完了」タグを付ける

### 指摘

#### 1.【要修正】4ステップ目の分岐は必ず「付いていない」側に進む（診断結果フォローが誰にも届かない）

- **何がそうなっているか**: 4ステップ目は「診断済み」タグの有無で分けていますが、そのタグを付けているのは**最後の9ステップ目**です。判定の時点ではまだ誰にも付いていないため、構造上100%「付いていない」側に進みます
- **考えられる原因**: タグを付けるステップを分岐より後ろに置いてしまったか、別のワークフローで付ける想定が抜けています
- **次の一手**: ①このワークフロー内で付けるなら、タグ付与を4ステップ目より前に移動する ②別のワークフロー・管理画面で付ける運用なら、そちらが先に動く設計になっているか確認する。修正は `workflow-builder`（「ワークフローを編集して」）へ

#### 2.【要確認】8ステップ目のメール配信が、ほとんどの方に届かない可能性

- **何がそうなっているか**: このワークフローはLINEの友だち追加から始まります。LINE経由で登録された方はメールアドレスを持たないことが多く、その場合メール配信は1通も届きません
- **なぜ重要か**: 他のクリエイターでも**最も多い失敗要因**です（1本のワークフローで配信失敗が極端に集中した例もあります）。さらに、**配信に失敗した方はそこから先のステップにも進みません**（このワークフローでは9ステップ目のタグ付与が行われません）
- **確認したいこと**: **この方々はメールアドレスを登録していますか？** 登録していない場合はLINE配信への変更をおすすめします

#### 3.【要確認】6ステップ目で「申し込んでいる人」も、そのあとの配信を受け取ります

- **何がそうなっているか**: 「申し込んでいる人」側は何も実行しない設定ですが、**ここで終了にはならず**、7ステップ目以降（14日後のメール）には全員が進みます
- **あわせて**: この分岐はMOSHアカウントの申込状況を見ています。LINEの友だち追加だけで、MOSHアカウントに紐付いていない方は、このステップで処理できず**そこから先が止まります**
- **確認したいこと**: **申し込み済みの方には、そのあとの特典案内を送らない（ここで終わらせる）つもりでしたか？**

#### 4.【要確認】分岐が見ている「体験レッスン」が意図したものか確認をお願いします

- **何がそうなっているか**: 6ステップ目はプラン・サービス「体験レッスン」（商品一覧と突き合わせて名前を確認済み）の申込状況を見ています
- **確認したいこと**: **この分岐で見たいのは「体験レッスン」で合っていますか？** 名前は確認済みですが、意図した対象かどうかはお答えください

#### 5.【要確認】9ステップ目で付ける「フォロー完了」タグの受け皿がありません

- **何がそうなっているか**: 他の11本を確認しましたが、「フォロー完了」タグで始まるワークフローはありません
- **考えられる原因**: 集計・絞り込み用のタグであれば正常です。次のワークフローにつなげる想定なら、まだ作られていません
- **確認したいこと**: **このタグは何に使う想定でしょうか？**

### 問題が見つからなかった箇所

- 配信に使うLINE公式アカウントは、トリガーのアカウントと一致しています
- 待機の日数（1日 → 5日 → 14日）に、配信が前後する矛盾はありません
- ごあいさつ・事例紹介のLINE配信に、重複や空のメッセージはありません

### 確認したいこと（まとめ）

1. 「診断済み」タグはどこで付く想定でしょうか（上記1）
2. 対象の方はメールアドレスを登録していますか（上記2）
3. 申し込み済みの方は6ステップ目で終了させたいですか（上記3）
4. 6ステップ目が見ているのは「体験レッスン」で合っていますか（上記4）
5. 「フォロー完了」タグの用途（上記5）

## 実績がある場合との差分

対象が公開済みで実績があるときは、この構成に**実測を重ねる**（構成・順序・書き方は同じ）。

- 「見た範囲」に**最後に公開した日と観測期間**を足す（実績は最後に公開した時点からの集計であることも書く）
- 各指摘の冒頭に実測を足す（「8ステップ目のメール配信は102件が対象になり、成功0件・失敗102件」）。**構造からの疑いが実測で裏付けられたら `要確認` → `要修正` に格上げする**
