# レポート完成形: 構造レビュー＋実績（公開済み）

Step 4 で、対象が公開済みで実行実績があるときの見本。**実在の誤設定パターン（下流未公開・メール全滅・分岐が常に false）を1本に合成した架空例**で、数値・名称はそのまま使わない。下書きのときの見本は [structure-review-report.md](structure-review-report.md)。

体裁の要点:

- 構造の書き下し（「このワークフローの動き」）は実績があるときも省かない
- 内部表現（ワークフローID・ステージID・エラーコード）を1つも出さない
- 実測（事実）と原因（仮説）を文の中で言い分ける
- `要確認` は必ず質問文で終える。「見なかった範囲」も書く

## ワークフローレビュー: 「体験セッション案内（LINE登録者向け）」

### 総合判定: 要修正（2件）／要確認（1件）

LINEに登録した方のうち **296人が、3ステップ目で付けたタグの先で行き止まり**になっています。振り分け先のワークフローが停止中であることと、3通目のメールが全員に届いていないことが原因です。この2つを直すと、現状ほぼ機能していない後半のフォローが動き出します。

### 見た範囲

- 稼働中のワークフローです。**最後に公開（稼働ON）したのは 2026-08-14**。それ以降の14日間の実績を見ています
- 8/14 より前の実績は、公開のたびにリセットされるため集計対象外です
- 構造（組み方）と実績（実際に動いた記録）の両方を確認し、同じアカウントの他のワークフロー8本との受け渡しも見ています

### このワークフローの動き

1. LINE公式アカウント「◯◯サロン公式」に友だち追加された方が対象
2. すぐに1通目のごあいさつをLINE配信
3. 希望ルート別のタグを付ける（「デジタル販売ルート」ほか4種）
4. 1日待って、2通目をLINE配信
5. 2日待って、3通目を**メール**で配信
6. **「特典タグ」が付いているかで分岐**
   - 付いている人 → 4通目（追加のご案内）をLINE配信
   - 付いていない人 → 何もしない（ここで終わり）

### 指摘

#### 1.【要修正】振り分け先の5本が停止中で、296人が行き止まりになっている

- **実測**: 3ステップ目でルート別のタグを付けた方が296人。そのタグで始まるはずのワークフロー5本（「デジタル販売ルート」「対面鑑定ルート」ほか3本）は、いずれも**停止中**です
- **考えられる原因**: 振り分け元は公開したが、振り分け先の公開を忘れている状態です。他のクリエイターでも最も多い連携ミスです
- **次の一手**: 5本をそれぞれ公開してください。公開は `workflow-builder`（「ワークフローを有効化して」）から行えます。**なお、すでに行き止まりになった296人は公開しても遡って進みません**。改めて配信したい場合は一斉配信の検討をおすすめします

#### 2.【要修正】3通目のメールが1通も届いていない（102件すべて失敗）

- **実測**: 5ステップ目（3通目）のメール配信は102件が対象になり、**成功0件・失敗102件**。他のクリエイターではメール配信の失敗率は中央値0%、上位10%でも0%なので、明らかな外れ値です
- **考えられる原因**: このワークフローはLINEの友だち追加から始まっているため、対象者にメールアドレスが登録されていない可能性が高いです。メールの宛先は配信時にコンタクトのメールアドレスから解決されるため、アドレスがない方は全員失敗します
- **あわせて重要**: 失敗した方は**そこから先のステップも進みません**。6ステップ目以降が0件なのはこれが原因です
- **次の一手**: 3通目をLINE配信に変更するのが最短です。メールで送りたい場合は、メールアドレスを取得できる導線（申込フォーム経由など）を起点にする必要があります。変更は `workflow-builder` へ

#### 3.【要確認】「特典タグあり」の分岐に誰も進んでいない

- **実測**: 6ステップ目の条件分岐を通過した296人のうち、「特典タグあり」側の配信に進んだのは**0人**でした（「付いていない人」側は何もせず終わる設定なので、296人全員がそちらに進んだことになります）
- **考えられる原因**: ①分岐で見ているタグと、実際に付けているタグが別のものである ②タグを付けるのがこの分岐より後のステップになっている ③そもそも該当者がまだいない
- **参考**: タグ条件の分岐は、他のクリエイターでも「一度も条件に合致しない」ケースが一定数見られる、比較的よくある誤設定候補です。**必ずしも誤りとは限りません**（「クリックした人だけ除外する」など、ごく少数だけが該当する設計は正常です）
- **確認したいこと**: **この分岐は「特典を受け取った人だけに追加のご案内を送る」意図でしょうか？** そうであれば、特典タグが付くタイミングがこの分岐より前になっているか一緒に確認させてください

### 問題が見つからなかった箇所

- トリガー（LINE友だち追加）は14日間で312件発火しており、他のクリエイターと比べても十分な水準です
- 1通目・2通目のLINE配信は失敗0件で正常に届いています
- 待機ステップに滞留や取りこぼしはありません

### 確認したいこと

1. 6ステップ目の分岐の意図（上記3）
2. 3通目は「メールで送ること」自体が要件でしょうか。それともLINEでも問題ないでしょうか
3. 停止中の5本は、あえて止めているものはありますか

## 書けないことの扱い

- **失敗の原因（エラーコード）は取得できない**。指摘2のように「102件すべて失敗」という事実は書けても、原因は「〜の可能性が高いです」までにとどめる
- **実績と分岐の対応づけが取れない場合**（[../references/data-model.md](../references/data-model.md)）は、「片側に偏っている可能性がありますが、実績からはどちらの側かを確定できません」と明記し、構造から確定している内容（どちら側で何が起きるか）だけを断定する
- **待機中の人数は見えない**。待機ステップの直後で件数が減っていても「離脱」と書かない
