# MOSH 商品ビルダー

## Overview

MCP ツール（以下ツール名は OpenAPI の operationId で記す。実際のツール名にはサーバー識別子の接頭辞（例: `mcp__<server>__postCreatorProduct`）が付くが、その形は環境により異なるため本書では付けない）を使って、MOSH クリエイターの商品とプランを作成・更新・公開・削除する。

**扱えるのは商品とプラン**（商品名・説明・画像・注意事項・キャンセルポリシー・申し込み後の流れ・公開状態と、プランの価格・課金サイクル・決済方法・分割払い・受付期間・定員・特典・表示順・公開状態）である。ゲストの購入者情報・決済情報・売上は扱わない。

商品とプランは別々に扱える。**既存の商品にプランを追加する・既存のプランを直すのが最も多い依頼**で、商品の新規作成を伴わない。プランの操作では、まず対象の商品を一覧から特定する。

商品を公開するには**公開中のプランが 1 つ以上必要**である。商品も新しく作る依頼では「商品を作る → プランを作る → 商品を公開する」の順になることを最初に伝える。

リクエストの構造・制約は [references/content-schema.md](references/content-schema.md) を、ツールのパラメータは [references/mcp-tools.md](references/mcp-tools.md) を参照してから送信を組み立てる。

## 前提条件

| 必要なもの | MCP で実在確認できるか | できない場合の扱い |
|---|---|---|
| 商品 ID | できる（`getCreatorProducts` の一覧から名前で特定） | — |
| プラン ID | できる（`getCreatorProductPlans` の一覧から名前で特定） | — |
| 商品画像の ID（`imageIds` / `steps[].imageId`） | **できない**（画像を一覧・検索するツールが無い） | ユーザーに直接確認する。既存商品の画像を残す場合のみ `getCreatorProduct` の値をそのまま使える |
| 公開中のプランの有無 | できる（`getCreatorProductPlans` で公開状態を確認） | — |
| クリエイターの決済代行会社 | **できない**（確認するツールが無い） | 課金回数・初回価格・価格の上限は決済代行会社で変わる。拒否されて初めて分かるため事前に断定しない |
| 事業者情報の登録 | **できない**（確認するツールが無い） | 公開時に拒否されて初めて分かる。事前に断定しない |

## When to use

- 商品を新しく作りたいとき
- 既存商品の名前・説明・画像・注意事項・キャンセルポリシー・申し込み後の流れを変えたいとき
- **既存の商品にプランを追加したいとき**（商品を作り直す必要はない）
- 商品の新規作成に続けてプランを作りたいとき
- 既存プランの価格・定員・受付期間・特典・決済方法などを変えたいとき
- プランの表示順を並び替えたいとき
- 商品やプランを公開・限定公開・非公開に切り替えたいとき
- 商品やプランを削除したいとき

## When NOT to use

- 商品・プランの内容を**見るだけ** → `product-navigator` スキル
- 売上・購入者の確認 → `sales-reporter` スキル
- LP（ランディングページ）の作成・編集 → `lp-builder` スキル
- ワークフロー（ステップ配信） → `workflow-builder` スキル

## Workflow

### 1. 要件ヒアリング

ユーザーに以下を確認する（自明なら聞き直さない）:

- 商品とプランのどちらの話か。新規作成か、変更か、削除か
- **プランの話なら、どの商品のプランか**（プランは必ず商品に属する）。名前・キーワードで良い。ID をユーザーに求めない
- 既存プランが対象なら、どのプランか
- 変えたい項目と、その内容
- 公開状態を変えるか

**商品の新規作成**なら、必須 4 項目（商品名・商品説明・注意事項・キャンセルポリシー）をこの段で揃える。**空欄を仮の文言で埋めない**。決まっていない項目があれば、そのまま聞く。

**プランの新規作成**は、次の順で確認する。作成後に変えられない項目（課金サイクル・課金回数・初回価格・課金開始日）が先に来る順序になっている。

1. 課金サイクル（買い切り / 月額 / 年額）
2. 価格
3. 決済方法（クレジットカード / 銀行振込）
4. 分割払いにするか（買い切りのみ）
5. 受付期間（買い切りは販売受付期間、サブスクリプションは申込期間）
6. 定員と残席表示
7. 公開状態

聞き取れなかった項目は [references/content-schema.md](references/content-schema.md) の既定値で埋めてよい。埋めた項目は保存前にユーザーへ提示する。

### 2. 対象の特定（商品の新規作成以外はすべて）

**既存商品へのプラン追加も含む。** プランは必ず商品に属するので、作成でも先に商品を特定する。

1. `getCreatorProducts` で一覧を取得し、ユーザーが言った名前から対象の商品を特定する
2. 完全一致しない場合は候補を提示して選んでもらう（**勝手に決めない**）
3. `getCreatorProductPlans` でその商品のプランを取得する。既存プランが対象ならプラン名から特定し、プランを追加するなら**既にある同じ内容のプランと重複しないか**を確認する
4. 既存の商品・プランを変更するなら、`getCreatorProduct` / `getCreatorProductPlan` で現在の内容を取得し、**変更前の値を控える**。差分をユーザーに示すために使う

商品を新しく作る依頼だけ、この手順を飛ばして手順 3 へ進む。

### 3. 商品の作成または更新

**新規作成**は `postCreatorProduct` を呼ぶ。作成された商品は**必ず非公開**で始まる。作成時に公開状態は指定できない。

**更新**は `patchCreatorProduct` を呼ぶ。送ったフィールドだけが変わる。ただし次の 2 つは**配列まるごとの置き換え**になる:

- `imageIds` … 送った配列がそのまま新しい画像一覧になる。**1 枚追加したいときも、既存の ID を含めた全件を送る**
- `steps` … 同上。1 ステップだけ直したいときも全ステップを送る

既存の値を保つには `getCreatorProduct` で取得した値をそのまま含めて送る。ここを省くと**黙って消える**。

送信前に [references/best-practices.md](references/best-practices.md) 末尾のセルフレビューチェックリストを確認する。`steps` を送る場合は [examples/update-product-steps.json](examples/update-product-steps.json)、新規作成は [examples/create-product.json](examples/create-product.json) の形を参照する。

### 4. プランの作成

手順 2 で特定した商品（新しく作った商品でも、既存の商品でもよい）に対して `postCreatorProductPlan` を呼ぶ。**1 つの商品に複数のプランを並べられる**ので、プランを足すために商品を作り直さない。リクエストの形は [examples/create-plan-one-time.json](examples/create-plan-one-time.json)（買い切り）と [examples/create-plan-subscription.json](examples/create-plan-subscription.json)（サブスクリプション）を参照する。

- **依頼に「公開で」と書かれていても、まず `PRIVATE` で作成する。** 読み戻して内容を確認してもらい、承認を得てから公開に切り替える
- `orderNum` は必須項目だが、作成時は自動採番されるため送った値は無視される。並び替えは手順 6 で行う
- 課金回数（`iterations`）は Stripe、初回価格（`initialPrice`）は fincode のクリエイターだけが使える。どちらの決済代行会社かは事前に分からないので、拒否されたら理由をそのまま伝えて代案を相談する
- **同じ内容を再送すると別のプランがもう 1 つ作られる。** 失敗したように見えても、再試行の前に `getCreatorProductPlans` で重複を確認する

### 5. プランの更新

`patchCreatorProductPlan` を呼ぶ。**部分更新には対応していない。** 必ず `getCreatorProductPlan` で現在値を読み、**変えない項目もそのまま含めた全項目**を送る。

次の項目は作成後に変更できない。現在値と違う値を送ると拒否される。

| 項目 | 扱い |
|---|---|
| 課金サイクル・課金回数・初回価格 | 現在値をそのまま送る。変えたいなら新しいプランを作る |
| 課金開始日 | 更新リクエストに項目自体が無い。作成時の設定のまま変わらない |

**公開中または購入者がいるサブスクリプションプランは、プラン名と価格を変更できない。** 取得したプランの `isNameEditable` / `isPriceEditable` で事前に判定できる。変更できないときは送り直さず、**「新しいプランを作成して、このプランを非公開にする」**を案内する。

定員は現在の購読者数未満にできない。

### 6. プランの表示順を並び替える

`patchCreatorProductProductPlansReorder` を呼ぶ。

- **`productId` は数値で渡す**（他のプラン操作は文字列）
- 先に `getCreatorProductPlans` で全プランを取得し、**非公開を含む全件**を並べたい順に並べて送る
- 含めなかったプランは既存の相対順のまま末尾に回る。一部だけ送ると意図しない順序になる

### 7. 読み戻してレビュー

保存に成功したら `getCreatorProduct` / `getCreatorProductPlan` で**読み戻し**、意図どおり保存されたかを確認してからユーザーに報告する。商品の `imageIds` と `steps` は置き換えなので、**消えていないこと**をここで確かめる。プランは価格・課金サイクル・受付期間を確かめる。

変更点を「変更前 → 変更後」の形で提示する。

### 8. 公開状態の変更（ユーザー承認が必須）

公開状態の変更は `patchCreatorProduct` / `patchCreatorProductPlan` に `publishingStatus` を渡して行う。**この操作の直前に必ずユーザーの承認を取る**。

商品を公開（`PUBLIC` / `LIMITED`）にする前に確認すること:

1. `getCreatorProductPlans` で**公開中のプランが 1 つ以上あるか**を確認する。無ければ公開できないので、先にプランを作るか公開する
2. プランの公開状態は**販売期間を反映した実効値**で判定される。販売期間が終了したプランは「公開中」に数えられない
3. 事業者情報が未登録だと拒否される。事前に確認する手段が無いため、拒否されたらその旨を伝える

商品を非公開（`PRIVATE`）にするときは、次をユーザーに伝えてから承認を取る:

- **紐づくプランもすべて非公開になる**（公開中の別商品も同じ内容を参照しているプランは非公開にしない）
- 公開に戻しても、プランの公開設定は自動では戻らない

`PUBLIC` / `LIMITED` への変更ではプランの公開設定は変わらない。商品が限定公開のときは、プランに `PUBLIC` を指定しても限定公開として扱われる。

変更後は読み戻し、`publishingStatus` と `publicUrl` を確認して報告する。

### 9. 削除（ユーザー承認が必須）

削除は取り消せない。商品でもプランでも次の順で進める。

1. `getCreatorProduct` / `getCreatorProductPlan` で対象を読み戻し、**商品名・プラン名でユーザーに提示**して本当にこれで良いか確かめる
2. `isDeletable` を確認する。`false` なら購入者がいるため削除できない。**ツールを呼ばずに**その旨を伝える
3. 「この操作は取り消せないこと」、商品の削除では「紐づくプランも同時に削除されること」を伝え、**明示的な承認を取る**
4. 承認を得てから `deleteCreatorProduct` / `deleteCreatorProductPlan` を呼ぶ
5. 一覧を取得し直し、消えたことを確認して報告する

`isDeletable` が `true` でも、削除の直前に購入が入っていれば拒否される。拒否理由はそのまま伝える。

## ユーザーへの提示・コミュニケーション規約

1. JSON をそのまま見せない。表または箇条書きに整形して提示する（ユーザーが明示的に求めた時だけ JSON を出す。ただし生の内部 ID・リッチテキストの内部形式・enum の英字値は、明示的に求められても出さない）
2. HTTP 用語・ステータスコードを文面に出さない。「保存できました」「◯◯のため公開できませんでした」のように平易な日本語で伝える
3. 生の内部 ID（`id` / `productId` / `productPlanId` / `moshServiceId` / `imageIds` の値 / `slug`）を提示に出さない。商品は商品名、プランはプラン名で示す。公開ページの案内には `publicUrl` を使う
4. enum 値は日本語に変換して出す（変換表は [references/content-schema.md](references/content-schema.md)）。`PUBLIC` `MONTHLY` 等の英字をそのまま見せない
5. **商品の** `description` / `precautions` / `cancellationPolicy` はリッチテキストの内部形式で返ることがある。内部形式のまま見せず、本文テキストを取り出して提示する（プランの `description` はプレーンテキスト）
6. 金額は「3,000 円」のように単位を付けて示す。定員 `0` は「定員なし」と言い換える
7. 書き込みの前後で「何をこれから変えるか」「何が実際に変わったか」を必ず言葉にする。黙って保存しない

## 必須ルール

- **公開・非公開の切り替えと削除は、直前にユーザーの承認を取ってから実行する。** 依頼文に含まれていても、実行前にもう一度確かめる
- **保存したら必ず読み戻して確認する。** 保存が成功したことと、意図どおりの内容になっていることは別
- **プランの更新は全項目を送る。** 部分更新に対応していないため、必ず `getCreatorProductPlan` で現在値を読んでから組み立てる
- **商品の `imageIds` と `steps` は全件送る。** 部分的に送ると送らなかったものが消える
- **作成後に変えられない項目（課金サイクル・課金回数・初回価格・課金開始日）は、プランを作る前に確定させる**
- **プラン名・価格がロックされていたら送り直さない。** 新しいプランを作成し、旧プランを非公開にする流れを案内する
- **並び替えの `productId` は数値、全プランを並べて送る**
- **画像 ID を捏造しない。** ユーザーから示された ID か、`getCreatorProduct` で取得した既存の値だけを使う。それらしい文字列を作らない
- **必須項目を仮の文言で埋めない。** 決まっていなければユーザーに聞く
- **プランの作成をやり直す前に一覧で重複を確認する。** 同じ内容を再送すると別のプランが増える
- 拒否されたら再試行しない。返ってきた理由を平易な日本語に言い換えて伝える

## よくあるミス

| NG | OK |
|---|---|
| 画像を 1 枚足すのに新しい ID だけを `imageIds` に送る | 既存の ID を含めた全件を送る。送らなかった画像は消える |
| ステップを 1 つ直すのに、そのステップだけ送る | 全ステップを送る。`steps` は置き換え |
| プランを追加するために商品を作り直す | 既存の商品にそのままプランを足せる。1 つの商品に複数のプランを並べられる |
| どの商品のプランか確かめずに作成へ進む | プランは商品に属する。先に `getCreatorProducts` で商品を特定する |
| プランの価格だけを送って更新する | プランは部分更新できない。現在値を読んで全項目を送る |
| 課金サイクルを月額から年額に変更しようとする | 作成後は変えられない。新しいプランを作る |
| 価格の変更が拒否されたので何度も送り直す | 公開中・購入者ありのサブスクは価格がロックされている。新プラン作成 + 旧プラン非公開を案内する |
| 並び替えで `productId` を文字列で渡す | 並び替えだけ数値。他のプラン操作は文字列 |
| 動かしたいプランだけを並び替えに送る | 非公開を含む全プランを並べて送る。含めないと末尾に回る |
| プラン作成が失敗したように見えたので同じ内容を再送する | 一覧で確認する。同じ内容でもプランがもう 1 つ増える |
| `capacity: 0` を「定員 0 人」と説明する | `0` は「定員なし（無制限）」 |
| 作成直後に「公開しました」と報告する | 作成された商品・プランは非公開。公開は `publishingStatus` の更新が必要 |
| 公開できないので `PUBLIC` を何度も送り直す | 公開中のプランが無いか事業者情報が未登録。原因を伝える |
| `isDeletable: false` の商品・プランに削除を実行して確かめる | 実行せずに「購入者がいるため削除できない」と伝える |
| 承認を取らずに非公開へ切り替える | 商品を非公開にするとプランも非公開になることを伝えて承認を取る |
| `publicUrl` が `null` → 「URL の取得に失敗」 | 非公開の商品では公開ページが存在しないため `null` が正常 |
| `steps` の `imageId` が無いので項目ごと省く | `imageId` は省略できない。画像が無いなら `null` を入れる |
| 説明文が長いので適当に切り詰める | 表示テキストは 10,000 文字まで。超えるならユーザーに相談して削る |

## エラーが返ったとき

拒否された理由は返ってきたメッセージに入っている。**再試行せず**、理由をそのまま平易な日本語で伝える。主なものは [references/content-schema.md](references/content-schema.md) の「拒否されたときのメッセージ」にまとめてある。

存在しない商品・プランや他のユーザーのものを指定すると「見つからない」旨のエラーが返る。対象の特定からやり直すか、ユーザーに名前を確認する。認証エラーの場合は、MOSH との接続（API トークンの設定）を見直すよう案内する。
