# MOSH 商品ビルダー

## Overview

MCP ツール（以下ツール名は OpenAPI の operationId で記す。実際のツール名にはサーバー識別子の接頭辞（例: `mcp__<server>__postCreatorProduct`）が付くが、その形は環境により異なるため本書では付けない）を使って、MOSH クリエイターの商品とプランを作成・更新・公開・削除する。

**扱えるのは商品とプラン、そしてプランに紐づく設定**（商品名・説明・画像・注意事項・キャンセルポリシー・申し込み後の流れ・公開状態、プランの価格・課金サイクル・決済方法・分割払い・受付期間・定員・特典・表示順・公開状態、プランの提供コンテンツ（会員サイトの紐付け）・購入後設定（サンクスページ／メール・自動リダイレクト・感想レポート）・会員サイトのライセンス設定（閲覧できるフォルダ・閲覧期限））である。ゲストの購入者情報・決済情報・売上は扱わない。

商品とプランは別々に扱える。**既存の商品にプランを追加する・既存のプランを直すのが最も多い依頼**で、商品の新規作成を伴わない。プランの操作では、まず対象の商品を一覧から特定する。

商品を公開するには**公開中のプランが 1 つ以上必要**である。商品も新しく作る依頼では「商品を作る → プランを作る → 商品を公開する」の順になることを最初に伝える。

プランの設定（提供コンテンツ・購入後設定・ライセンス）は、プランを作ったあとに個別のツールで行う。**会員サイトの紐付けと解除は、申込者向けサイト（旧会員サイト）が非公開になる**など他の設定にも影響するため、実行前に必ず影響を伝えて承認を取る。

プロダクトの呼称と API の項目名の対応: 申込者向けサイト（旧会員サイト）↔ `isUsingLegacySite` / `useLegacyMembershipSite`、提供コンテンツ ↔ `offeredContents`、ライセンス ↔ `LicenseSetting`（ツール名の一部）。ユーザーにはプロダクトの呼称で話す。

リクエストの構造・制約は [references/content-schema.md](references/content-schema.md) を、ツールのパラメータは [references/mcp-tools.md](references/mcp-tools.md) を参照してから送信を組み立てる。

## 前提条件

| 必要なもの | MCP で実在確認できるか | できない場合の扱い |
|---|---|---|
| 商品 ID | できる（`getCreatorProducts` の一覧から名前で特定） | — |
| プラン ID | できる（`getCreatorProductPlans` の一覧から名前で特定） | — |
| 商品画像の ID（`imageIds` / `steps[].imageId`） | **できない**（画像を一覧・検索するツールが無い） | ユーザーに直接確認する。既存商品の画像を残す場合のみ `getCreatorProduct` の値をそのまま使える |
| 公開中のプランの有無 | できる（`getCreatorProductPlans` で公開状態を確認） | — |
| クリエイターの決済代行会社 | **できない**（確認するツールが無い） | 課金回数・初回価格・価格の上限は決済代行会社で変わる。拒否されて初めて分かるため事前に断定しない |
| 事業者情報の登録 | **できない**（確認するツールが無い） | 公開時に拒否されて初めて分かる。事前に断定しない |
| 会員サイト ID（`membershipSiteId`） | できる（`getCreatorMembershipSites` の一覧から名前で特定。プランに紐付き済みなら `getCreatorProductPlanOfferedContents` の `membershipSiteId`） | — |
| 会員サイトのフォルダ | できる（`getCreatorMembershipSiteProductPlanLicenseSetting` の `folders` にフォルダ名付きで全件返る） | — |
| 会員サイトの閲覧順の固定 | できる（`getCreatorMembershipSite` の `isFixedViewingOrder`） | — |
| プランの購入者の有無 | 部分的にできる（`getCreatorProductPlan` の `isDeletable` が `false` なら購入者がいるか、判定できなかった） | `false` は「購入者がいる可能性がある」と扱う。`true` でも解約済みの購入者がいると提供コンテンツの変更・解除は拒否される。拒否されたら理由をそのまま伝える |
| サンクスページのバナー画像の ID（`bannerMediaId`） | **できない**（画像を一覧・検索するツールが無い） | ユーザーに直接確認する。既存のバナーを残す場合は項目を省略する（省略＝維持） |
| 自動リダイレクトの現在値 | **できない**（取得するツールが無い） | 変更前の値は示せない。上書きになることを伝えて承認を取り、必要なら管理画面で確認してもらう |

## When to use

- 商品を新しく作りたいとき
- 既存商品の名前・説明・画像・注意事項・キャンセルポリシー・申し込み後の流れを変えたいとき
- **既存の商品にプランを追加したいとき**（商品を作り直す必要はない）
- 商品の新規作成に続けてプランを作りたいとき
- 既存プランの価格・定員・受付期間・特典・決済方法などを変えたいとき
- プランの表示順を並び替えたいとき
- 商品やプランを公開・限定公開・非公開に切り替えたいとき
- 商品やプランを削除したいとき
- プランに会員サイトを紐付けたい・別の会員サイトに変えたい・紐付けを外したいとき
- 会員サイト経由で購入したゲストが閲覧できるフォルダや閲覧期限（ライセンス）を変えたいとき
- 購入直後の画面と完了メール（サンクスページ／メール）の本文やバナーを設定したいとき
- 購入完了後に指定したページへ自動で移動させたい（自動リダイレクト）・止めたいとき
- 感想レポートの投稿依頼を自動で送るかどうかを切り替えたいとき

## When NOT to use

- 商品・プランの内容を**見るだけ** → `product-navigator` スキル
- 売上・購入者の確認 → `sales-reporter` スキル
- 会員サイトそのもの（フォルダ・コンテンツ・タグ・サイト設定）の作成・編集 → `membership-site-builder` スキル
- 予約メニューをプランに**紐付ける** → 管理画面（このスキルでできるのは解除だけ）
- 自動リダイレクトの**現在値を確認する** → 管理画面（このスキルでできるのは作成／更新と削除だけ）
- LP（ランディングページ）の作成・編集 → `lp-builder` スキル
- ワークフロー（ステップ配信） → `workflow-builder` スキル

## Workflow

### 1. 要件ヒアリング

ユーザーに以下を確認する（自明なら聞き直さない）:

- 商品とプランのどちらの話か。新規作成か、変更か、削除か
- **プランの話なら、どの商品のプランか**（プランは必ず商品に属する）。名前・キーワードで良い。ID をユーザーに求めない
- 既存プランが対象なら、どのプランか
- 変えたい項目と、その内容
- 公開状態を変えるか

**商品の新規作成**なら、必須 4 項目（商品名・商品説明・注意事項・キャンセルポリシー）をこの段で揃える。**空欄を仮の文言で埋めない**。決まっていない項目があれば、そのまま聞く。

**プランの新規作成**は、次の順で確認する。作成後に変えられない項目（課金サイクル・課金回数・初回価格・課金開始日）が先に来る順序になっている。

1. 課金サイクル（買い切り / 月額 / 年額）
2. 価格
3. 決済方法（クレジットカード / 銀行振込）
4. 分割払いにするか（買い切りのみ）
5. 受付期間（買い切りは販売受付期間、サブスクリプションは申込期間）
6. 定員と残席表示
7. 公開状態

聞き取れなかった項目は [references/content-schema.md](references/content-schema.md) の既定値で埋めてよい。埋めた項目は保存前にユーザーへ提示する。

**プランの設定**（提供コンテンツ・ライセンス・購入後設定）の話なら、次の順で確認する。会員サイトの紐付けが他の設定の前提になり、ライセンスは紐付けたあとにしか設定できないため、この並びになっている。

1. 会員サイトを紐付けるか。紐付けるならどの会員サイトか（名前で良い）。外す・別のサイトに変えるなら、申込者向けサイト（旧会員サイト）が非公開になる影響を先に伝える
2. ライセンス（閲覧できるフォルダ・今後追加されるフォルダを含めるか・閲覧期限）
3. サンクスページ／メール（本文 → バナー画像 → バナーのリンク先）
4. 自動リダイレクト（移動先の URL と待機秒数。0〜15 秒）。現在値を読むツールが無いので、いま設定があるかどうかもここで聞く
5. 感想レポートの投稿依頼を自動で送るか

依頼された設定だけを扱えばよく、全部を聞き直す必要はない。ただし依頼が「会員サイトを紐付けて」だけのときは、ライセンスの既定値（全フォルダ閲覧可・今後追加分も含む・無期限）で良いかを一言確認する。

### 2. 対象の特定（商品の新規作成以外はすべて）

**既存商品へのプラン追加も含む。** プランは必ず商品に属するので、作成でも先に商品を特定する。

1. `getCreatorProducts` で一覧を取得し、ユーザーが言った名前から対象の商品を特定する
2. 完全一致しない場合は候補を提示して選んでもらう（**勝手に決めない**）
3. `getCreatorProductPlans` でその商品のプランを取得する。既存プランが対象ならプラン名から特定し、プランを追加するなら**既にある同じ内容のプランと重複しないか**を確認する
4. 既存の商品・プランを変更するなら、`getCreatorProduct` / `getCreatorProductPlan` で現在の内容を取得し、**変更前の値を控える**。差分をユーザーに示すために使う
5. プランの設定を変えるなら、対応する取得ツール（`getCreatorProductPlanOfferedContents` / `getCreatorMembershipSiteProductPlanLicenseSetting` / `getCreatorProductPlanSettingsThanks` / `getCreatorProductPlanSettingsReviewReport`）で**現在の設定を読み、変更前の値を控える**。**自動リダイレクトだけは現在値を読むツールが無い**ので、有無と内容をユーザーに確認する

商品を新しく作る依頼だけ、この手順を飛ばして手順 3 へ進む。

### 3. 商品の作成または更新

**新規作成**は `postCreatorProduct` を呼ぶ。作成された商品は**必ず非公開**で始まる。作成時に公開状態は指定できない。

**更新**は `patchCreatorProduct` を呼ぶ。送ったフィールドだけが変わる。ただし次の 2 つは**配列まるごとの置き換え**になる:

- `imageIds` … 送った配列がそのまま新しい画像一覧になる。**1 枚追加したいときも、既存の ID を含めた全件を送る**
- `steps` … 同上。1 ステップだけ直したいときも全ステップを送る

既存の値を保つには `getCreatorProduct` で取得した値をそのまま含めて送る。ここを省くと**黙って消える**。

送信前に [references/best-practices.md](references/best-practices.md) 末尾のセルフレビューチェックリストを確認する。`steps` を送る場合は [examples/update-product-steps.json](examples/update-product-steps.json)、新規作成は [examples/create-product.json](examples/create-product.json) の形を参照する。

### 4. プランの作成

手順 2 で特定した商品（新しく作った商品でも、既存の商品でもよい）に対して `postCreatorProductPlan` を呼ぶ。**1 つの商品に複数のプランを並べられる**ので、プランを足すために商品を作り直さない。リクエストの形は [examples/create-plan-one-time.json](examples/create-plan-one-time.json)（買い切り）と [examples/create-plan-subscription.json](examples/create-plan-subscription.json)（サブスクリプション）を参照する。

- **依頼に「公開で」と書かれていても、まず `PRIVATE` で作成する。** 読み戻して内容を確認してもらい、承認を得てから公開に切り替える
- `orderNum` は必須項目だが、作成時は自動採番されるため送った値は無視される。並び替えは手順 6 で行う
- 課金回数（`iterations`）は Stripe、初回価格（`initialPrice`）は fincode のクリエイターだけが使える。どちらの決済代行会社かは事前に分からないので、拒否されたら理由をそのまま伝えて代案を相談する
- **同じ内容を再送すると別のプランがもう 1 つ作られる。** 失敗したように見えても、再試行の前に `getCreatorProductPlans` で重複を確認する

### 5. プランの更新

`patchCreatorProductPlan` を呼ぶ。**部分更新には対応していない。** 必ず `getCreatorProductPlan` で現在値を読み、**変えない項目もそのまま含めた全項目**を送る。

次の項目は作成後に変更できない。現在値と違う値を送ると拒否される。

| 項目 | 扱い |
|---|---|
| 課金サイクル・課金回数・初回価格 | 現在値をそのまま送る。変えたいなら新しいプランを作る |
| 課金開始日 | 更新リクエストに項目自体が無い。作成時の設定のまま変わらない |

**公開中または購入者がいるサブスクリプションプランは、プラン名と価格を変更できない。** 取得したプランの `isNameEditable` / `isPriceEditable` で事前に判定できる。変更できないときは送り直さず、**「新しいプランを作成して、このプランを非公開にする」**を案内する。

定員は現在の購読者数未満にできない。

### 6. プランの表示順を並び替える

`patchCreatorProductProductPlansReorder` を呼ぶ。

- **`productId` は数値で渡す**（他のプラン操作は文字列）
- 先に `getCreatorProductPlans` で全プランを取得し、**非公開を含む全件**を並べたい順に並べて送る
- 含めなかったプランは既存の相対順のまま末尾に回る。一部だけ送ると意図しない順序になる

### 7. 提供コンテンツ（会員サイト）の紐付け（ユーザー承認が必須）

プランで提供する会員サイトを紐付ける・変える・外す。予約メニューは**解除だけ**できる（紐付けは管理画面を案内する）。リクエストの形は [examples/link-membership-site.json](examples/link-membership-site.json) を参照する。例の `membershipSiteId` はダミー値なので、取得した値に置き換えてから送る。

1. `getCreatorProductPlanOfferedContents` で現状を読む。会員サイトと予約メニューが同じ一覧に並ぶ。`isUsingLegacySite` が `true` なら、いま申込者向けサイト（旧会員サイト）を使っている
2. 紐付ける会員サイトは `getCreatorMembershipSites` の一覧から**名前で**特定する。`membershipSiteId` は**数値**。完全一致しなければ候補を提示して選んでもらう
3. **すでに何か紐付いているプラン**を変える・外すなら、`getCreatorProductPlan` の `isDeletable` を見る。`false` なら購入者がいる可能性があり、紐付けの変更・解除は拒否される。**ツールを呼ばずに**その旨を伝える。何も紐付いていないプランへの初回の紐付けは、購入者がいてもできる
4. 何が起きるかを伝えて承認を取る。特に次の 2 点は必ず言葉にする
   - 会員サイトを紐付ける・会員サイトを使わない設定にすると、**申込者向けサイト（旧会員サイト）が非公開になる**。あとで申込者向けサイトに戻しても自動では公開に戻らない（公開は管理画面で行う）
   - 別の会員サイトへ変えると、いままでの会員サイトの紐付けは外れる
5. 承認後に `postCreatorProductPlanOfferedContent` を呼ぶ。3 通りの使い分けは [references/content-schema.md](references/content-schema.md) の「会員サイトの紐付けリクエスト」を参照する
   - **同じ会員サイトを再指定すると「変更がないためスキップしました」で成功する。** 失敗ではないので、そのまま「すでに紐付いています」と伝える
   - 会員サイトを新しく紐付けると、そのプランのライセンスが**全フォルダ閲覧可・今後追加されるフォルダも含む・無期限**で自動作成される。変えたいときは手順 8 へ進む
6. 会員サイトや予約メニューの紐付けを 1 件だけ外すときは `deleteCreatorProductPlanOfferedContent` を使う。対象を**タイトルで**提示して承認を取ってから呼ぶ。申込者向けサイトの紐付けはこの方法では外せない（`postCreatorProductPlanOfferedContent` で「会員サイトを使わない」を選ぶ）
7. `getCreatorProductPlanOfferedContents` で読み戻し、紐付いている会員サイト名・予約メニュー名を提示する

### 8. ライセンス設定（閲覧できるフォルダ・閲覧期限）（フォルダを外すときはユーザー承認が必須）

会員サイトが紐付いたプランで、購入したゲストが閲覧できるフォルダと期間を決める。`membershipSiteId` は手順 7 の一覧で得た**数値**を使う。リクエストの形は [examples/update-license-setting.json](examples/update-license-setting.json) を参照する（`viewableFolderIds` はダミー値。取得した `folders` の ID に置き換える）。

1. `getCreatorMembershipSiteProductPlanLicenseSetting` で現在値を読む。`folders` に会員サイトの全フォルダが**フォルダ名と閲覧可否付き**で返るので、フォルダはこの名前で提示する
2. 変更内容を組み立てる。`putCreatorMembershipSiteProductPlanLicenseSetting` は `viewableFolderIds` / `isNewFoldersIncluded` / `accessDurationDays` の**3 項目すべてが必須で、送った内容に置き換わる**。1 つのフォルダを足すときも、閲覧可能にするフォルダの ID を全件送る
3. 会員サイトで**閲覧順の固定**（`getCreatorMembershipSite` の `isFixedViewingOrder`）が有効なら、全フォルダを閲覧可能にし `isNewFoldersIncluded: true` にしないと拒否される。フォルダを分けたい依頼なら、先に閲覧順の固定を外す必要があることを伝える（サイト設定の変更は `membership-site-builder` スキル）。閲覧順の固定を外すとゲストの閲覧完了状態が消えて元に戻せないことも併せて伝える
4. **公開中・限定公開のプラン**（`publishingStatus` が `PUBLIC` / `LIMITED`）、または **`isDeletable: false`（購入者がいる可能性のある）プラン**で、いま閲覧可能なフォルダを外すときは、**そのフォルダを購入済みのゲストも見られなくなる**ことを伝えて承認を取る
5. 閲覧期限 `accessDurationDays` は 1〜1000 日。無期限は `null`（省略はできない）
6. 送信後に同じ取得ツールで読み戻し、閲覧できるフォルダ名・今後追加分の扱い・閲覧期限を提示する

### 9. 購入後設定（サンクスページ → 自動リダイレクト → 感想レポート）

購入完了後にゲストが見るもの・受け取るものの設定。3 つは独立しているので、依頼されたものだけを扱う。リクエストの形は [examples/update-thanks-setting.json](examples/update-thanks-setting.json)（バナー画像の ID はユーザーから受け取った値に置き換える）/ [examples/update-redirect-setting.json](examples/update-redirect-setting.json) / [examples/update-review-report-setting.json](examples/update-review-report-setting.json) を参照する。

**サンクスページ／メール**（購入直後の画面と完了メールに載る）

1. `getCreatorProductPlanSettingsThanks` で現在値（本文・バナー画像・リンク先）を読む
2. `patchCreatorProductPlanSettingsThanks` を呼ぶ。**`content`（本文）は毎回必須**なので、本文を変えないときも現在値をそのまま送る。`bannerMediaId` / `bannerLinkUrl` は**省略すると維持、`null` を送ると削除**
3. `bannerLinkUrl` は `http://` か `https://` で始まる URL だけ。**バナー画像が無い状態ではリンク先を指定できない**（先に画像を設定するか、リンク先も `null` にする）
4. `bannerMediaId` はユーザーがアップロードした画像の ID を受け取って使う。**それらしい ID を作らない**
5. 読み戻して、本文の要約・バナーの有無・リンク先を提示する

**自動リダイレクト**（購入完了後に指定ページへ自動で移動させる）

1. **現在値を読むツールは無い。** いま設定があるか・移動先の URL・待機秒数をユーザーに確認する。設定済みなら上書きになることを伝え、正確な現在値が要るなら管理画面で確認してもらう
2. `patchCreatorProductPlanSettingsRedirect` に `redirectUrl` と `pendingSecond`（待機秒数、0〜15）の**両方**を送る。作成も更新も同じツール
3. やめるときは `deleteCreatorProductPlanSettingsRedirect`。「自動リダイレクトを解除します（あとから再設定できます）」と伝えて**承認を取ってから**呼ぶ。未設定でも成功するので、有無を確かめるためだけに呼ばない
4. 銀行振込で支払ったゲストにはリダイレクトが働かないことを添えて伝える
5. 読み戻せないので、**送った値**（移動先の URL と待機秒数。削除なら「未設定にしました」）を提示する

**感想レポート**（購入後に感想レポートの投稿依頼メールを自動で送るか）

1. `getCreatorProductPlanSettingsReviewReport` で現在値を読む。**一度も設定していないプランは有効（`true`）として返る**
2. `patchCreatorProductPlanSettingsReviewReport` に `isAutoRequestEnabled` を送る
3. 読み戻して「自動送信: 有効 / 無効」で提示する

### 10. 読み戻してレビュー

保存に成功したら `getCreatorProduct` / `getCreatorProductPlan` で**読み戻し**、意図どおり保存されたかを確認してからユーザーに報告する。商品の `imageIds` と `steps` は置き換えなので、**消えていないこと**をここで確かめる。プランは価格・課金サイクル・受付期間を確かめる。プランの設定は手順 7〜9 の各取得ツールで読み戻す。**自動リダイレクトだけは取得ツールが無い**ので、保存が成功したことと送った値を提示する。

変更点を「変更前 → 変更後」の形で提示する。

### 11. 公開状態の変更（ユーザー承認が必須）

公開状態の変更は `patchCreatorProduct` / `patchCreatorProductPlan` に `publishingStatus` を渡して行う。**この操作の直前に必ずユーザーの承認を取る**。

商品を公開（`PUBLIC` / `LIMITED`）にする前に確認すること:

1. `getCreatorProductPlans` で**公開中のプランが 1 つ以上あるか**を確認する。無ければ公開できないので、先にプランを作るか公開する
2. プランの公開状態は**販売期間を反映した実効値**で判定される。販売期間が終了したプランは「公開中」に数えられない
3. 事業者情報が未登録だと拒否される。事前に確認する手段が無いため、拒否されたらその旨を伝える

商品を非公開（`PRIVATE`）にするときは、次をユーザーに伝えてから承認を取る:

- **紐づくプランもすべて非公開になる**（公開中の別商品も同じ内容を参照しているプランは非公開にしない）
- 公開に戻しても、プランの公開設定は自動では戻らない

`PUBLIC` / `LIMITED` への変更ではプランの公開設定は変わらない。商品が限定公開のときは、プランに `PUBLIC` を指定しても限定公開として扱われる。

変更後は読み戻し、`publishingStatus` と `publicUrl` を確認して報告する。

### 12. 削除（ユーザー承認が必須）

削除は取り消せない。商品でもプランでも次の順で進める。

1. `getCreatorProduct` / `getCreatorProductPlan` で対象を読み戻し、**商品名・プラン名でユーザーに提示**して本当にこれで良いか確かめる
2. `isDeletable` を確認する。`false` なら購入者がいるため削除できない。**ツールを呼ばずに**その旨を伝える
3. 「この操作は取り消せないこと」、商品の削除では「紐づくプランも同時に削除されること」を伝え、**明示的な承認を取る**
4. 承認を得てから `deleteCreatorProduct` / `deleteCreatorProductPlan` を呼ぶ
5. 一覧を取得し直し、消えたことを確認して報告する

`isDeletable` が `true` でも、削除の直前に購入が入っていれば拒否される。拒否理由はそのまま伝える。

## ユーザーへの提示・コミュニケーション規約

1. JSON をそのまま見せない。表または箇条書きに整形して提示する（ユーザーが明示的に求めた時だけ JSON を出す。ただし生の内部 ID・リッチテキストの内部形式・enum の英字値は、明示的に求められても出さない）
2. HTTP 用語・ステータスコードを文面に出さない。「保存できました」「◯◯のため公開できませんでした」のように平易な日本語で伝える
3. 生の内部 ID（`id` / `productId` / `productPlanId` / `moshServiceId` / `imageIds` の値 / `slug` / `membershipSiteId` / `offeredContentId` / `calendarBookingItemId` / `folders[].id` / `bannerMediaId`）を提示に出さない。商品は商品名、プランはプラン名、会員サイトはサイト名、フォルダはフォルダ名、予約メニューはタイトルで示す。公開ページの案内には `publicUrl` を使う
4. enum 値は日本語に変換して出す（変換表は [references/content-schema.md](references/content-schema.md)）。`PUBLIC` `MONTHLY` `FREE_SLOT` 等の英字をそのまま見せない
5. **商品の** `description` / `precautions` / `cancellationPolicy` はリッチテキストの内部形式で返ることがある。内部形式のまま見せず、本文テキストを取り出して提示する（プランの `description` はプレーンテキスト）
6. 金額は「3,000 円」のように単位を付けて示す。定員 `0` は「定員なし」、閲覧期限 `null` は「無期限」、待機秒数は「5 秒」のように言い換える
7. 書き込みの前後で「何をこれから変えるか」「何が実際に変わったか」を必ず言葉にする。黙って保存しない
8. `isUsingLegacySite: true` は「申込者向けサイト（旧会員サイト）を使っています」と伝える。自動リダイレクトは現在値を読めないので、「いまは◯◯に設定されています」と断定せず、送った値（削除なら「未設定にしました」）だけを提示する

## 必須ルール

- **公開・非公開の切り替えと削除は、直前にユーザーの承認を取ってから実行する。** 依頼文に含まれていても、実行前にもう一度確かめる
- **保存したら必ず読み戻して確認する。** 保存が成功したことと、意図どおりの内容になっていることは別
- **プランの更新は全項目を送る。** 部分更新に対応していないため、必ず `getCreatorProductPlan` で現在値を読んでから組み立てる
- **商品の `imageIds` と `steps` は全件送る。** 部分的に送ると送らなかったものが消える
- **作成後に変えられない項目（課金サイクル・課金回数・初回価格・課金開始日）は、プランを作る前に確定させる**
- **プラン名・価格がロックされていたら送り直さない。** 新しいプランを作成し、旧プランを非公開にする流れを案内する
- **並び替えの `productId` は数値、全プランを並べて送る**
- **画像 ID を捏造しない。** ユーザーから示された ID か、`getCreatorProduct` で取得した既存の値だけを使う。それらしい文字列を作らない
- **必須項目を仮の文言で埋めない。** 決まっていなければユーザーに聞く
- **プランの作成をやり直す前に一覧で重複を確認する。** 同じ内容を再送すると別のプランが増える
- **会員サイトの紐付け・変更・解除は、「申込者向けサイト（旧会員サイト）が非公開になる」影響を伝えてから承認を取る。** 依頼文に含まれていても、実行前にもう一度確かめる
- **購入者がいるプランでは、紐付いている提供コンテンツの変更・解除を試さない。** `isDeletable: false` なら呼ばずに「購入者がいるため変更できない」と伝える。何も紐付いていないプランへの初回の紐付けは購入者がいてもできる
- **同じ会員サイトの再指定は「変更なし」で成功する。** エラー扱いにせず、すでに紐付いていることを伝える
- **サンクスページ／メールは `content` を毎回送る。** `bannerMediaId` / `bannerLinkUrl` は省略＝維持・`null`＝削除。リンク先は `http(s)` のみで、バナー画像が無いと指定できない
- **バナー画像の ID を捏造しない。** ユーザーから示された ID だけを使う。既存のバナーを残すなら項目を省略する
- **自動リダイレクトの現在値は読めない。** 有無・URL・秒数はユーザーに確認し、上書きになることを伝えてから送る。待機秒数は 0〜15
- **自動リダイレクトの削除は「解除します（あとから再設定できます）」と伝えて承認を取ってから呼ぶ。** 未設定でも成功するので、有無を確かめるためだけに呼ばない
- **感想レポートは一度も設定していないプランでは「有効」として返る。** 「未設定」とは言わない
- **ライセンスの `accessDurationDays` は 1〜1000、無期限は `null`。** `membershipSiteId` は数値で渡す
- **閲覧順の固定が有効な会員サイトでは、全フォルダ + 今後追加分を含める設定しか保存できない。** フォルダを分けたい依頼には、先に閲覧順の固定を外す必要があることと、外すと閲覧完了状態が消えて元に戻せないことを伝える
- **公開中・限定公開のプラン、または購入者がいる可能性のある（`isDeletable: false`）プランで閲覧できるフォルダを外す前に承認を取る。** 購入済みのゲストがそのフォルダを見られなくなる
- **プランの設定を書き込んだら、対応する取得ツールで読み戻して提示する。** 保存の成功と意図どおりの内容は別。自動リダイレクトだけは取得ツールが無いので、送った値を提示する
- 拒否されたら再試行しない。返ってきた理由を平易な日本語に言い換えて伝える

## よくあるミス

| NG | OK |
|---|---|
| 画像を 1 枚足すのに新しい ID だけを `imageIds` に送る | 既存の ID を含めた全件を送る。送らなかった画像は消える |
| ステップを 1 つ直すのに、そのステップだけ送る | 全ステップを送る。`steps` は置き換え |
| プランを追加するために商品を作り直す | 既存の商品にそのままプランを足せる。1 つの商品に複数のプランを並べられる |
| どの商品のプランか確かめずに作成へ進む | プランは商品に属する。先に `getCreatorProducts` で商品を特定する |
| プランの価格だけを送って更新する | プランは部分更新できない。現在値を読んで全項目を送る |
| 課金サイクルを月額から年額に変更しようとする | 作成後は変えられない。新しいプランを作る |
| 価格の変更が拒否されたので何度も送り直す | 公開中・購入者ありのサブスクは価格がロックされている。新プラン作成 + 旧プラン非公開を案内する |
| 並び替えで `productId` を文字列で渡す | 並び替えだけ数値。他のプラン操作は文字列 |
| 動かしたいプランだけを並び替えに送る | 非公開を含む全プランを並べて送る。含めないと末尾に回る |
| プラン作成が失敗したように見えたので同じ内容を再送する | 一覧で確認する。同じ内容でもプランがもう 1 つ増える |
| `capacity: 0` を「定員 0 人」と説明する | `0` は「定員なし（無制限）」 |
| 作成直後に「公開しました」と報告する | 作成された商品・プランは非公開。公開は `publishingStatus` の更新が必要 |
| 公開できないので `PUBLIC` を何度も送り直す | 公開中のプランが無いか事業者情報が未登録。原因を伝える |
| `isDeletable: false` の商品・プランに削除を実行して確かめる | 実行せずに「購入者がいるため削除できない」と伝える |
| 承認を取らずに非公開へ切り替える | 商品を非公開にするとプランも非公開になることを伝えて承認を取る |
| `publicUrl` が `null` → 「URL の取得に失敗」 | 非公開の商品では公開ページが存在しないため `null` が正常 |
| `steps` の `imageId` が無いので項目ごと省く | `imageId` は省略できない。画像が無いなら `null` を入れる |
| 説明文が長いので適当に切り詰める | 表示テキストは 10,000 文字まで。超えるならユーザーに相談して削る |
| 会員サイトを紐付けるだけなので承認を取らずに実行する | 申込者向けサイト（旧会員サイト）が非公開になる。影響を伝えてから承認を取る |
| 「変更がないためスキップしました」を失敗として報告する | 同じ会員サイトを再指定したときの正常な応答。すでに紐付いていることを伝える |
| 購入者がいるプランで会員サイトの変更を試して拒否を確かめる | `isDeletable: false` なら呼ばずに「購入者がいるため変更できない」と伝える |
| 購入者がいるので、何も紐付いていないプランへの初回の紐付けも断る | 初回の紐付けは購入者がいてもできる。拒否されるのは紐付いているものの変更・解除 |
| 予約メニューをプランに紐付けようとする | このスキルでは紐付けできない。管理画面を案内する（解除はできる） |
| 会員サイトを紐付けたあとライセンスを設定せずに終える | 自動作成されるのは「全フォルダ・今後追加分も含む・無期限」。希望と違えばライセンス設定を続ける |
| ライセンスで足したいフォルダの ID だけを `viewableFolderIds` に送る | 送った内容に置き換わる。閲覧可能にするフォルダを全件送る |
| 閲覧順の固定が有効なサイトで一部のフォルダだけ閲覧可にして送る | 拒否される。全フォルダ + `isNewFoldersIncluded: true` にするか、先に閲覧順の固定を外してもらう |
| 公開中・限定公開のプランや購入者がいる可能性のあるプランからフォルダを外すのに承認を取らない | 購入済みのゲストも見られなくなる。伝えてから承認を取る |
| 閲覧期限を無期限にするのに `accessDurationDays` を省く | 省略できない。`null` を送る |
| バナー画像だけ変えたいので `content` を省いて送る | `content` は毎回必須。本文を変えないなら現在値をそのまま送る |
| バナー画像を消すために `bannerMediaId` を省略する | 省略は「維持」。消すなら `null` を送る（リンク先も `null` にする） |
| バナー画像が無いのにリンク先 URL だけ設定する | 拒否される。先にバナー画像を設定するか、リンク先を `null` にする |
| 自動リダイレクトの秒数だけを送る | `redirectUrl` と `pendingSecond` は両方必須。待機秒数は 0〜15 |
| 自動リダイレクトの現在値を確かめようとして削除を呼ぶ・「いまは◯◯に設定されています」と推測で伝える | 現在値を読むツールは無い。有無・URL・秒数はユーザーに確認し、上書きになることを伝える |
| 「止めたい」と言われて承認を取らずに自動リダイレクトを削除する | 「解除します（あとから再設定できます）」と伝えて承認を取ってから呼ぶ |
| 感想レポートの取得結果が `true` なので「設定済み」と断定する | 一度も設定していないプランも `true` で返る。「自動送信は有効です」とだけ伝える |
| `membershipSiteId` を文字列で渡す | 数値で渡す（会員サイト ID は数値） |

## エラーが返ったとき

拒否された理由は返ってきたメッセージに入っている。**再試行せず**、理由をそのまま平易な日本語で伝える。主なものは [references/content-schema.md](references/content-schema.md) の「拒否されたときのメッセージ」にまとめてある。

存在しない商品・プランや他のユーザーのものを指定すると「見つからない」旨のエラーが返る。対象の特定からやり直すか、ユーザーに名前を確認する。ライセンス設定では、会員サイトが紐付いていないプランを指定したときも「見つからない」旨になるので、先に提供コンテンツの一覧で紐付きを確かめる。認証エラーの場合は、MOSH との接続（API トークンの設定）を見直すよう案内する。
