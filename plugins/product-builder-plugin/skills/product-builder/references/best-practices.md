# 商品を作る・直すときの進め方

## 商品作成の組み立て

### 必須 4 項目を先に揃える

商品名・商品説明・注意事項・キャンセルポリシーは作成時に必須。**空欄を仮の文言で埋めない。** 「未定」「後で記入」のような placeholder も入れない。決まっていない項目があれば、そのまま聞く。

ユーザーが文面を持っていない場合は、こちらから案を出してよい。ただし**案であることを明示し、そのまま保存せず確認を取る**。

### 画像は ID をユーザーから受け取る

画像を一覧・検索する MCP ツールは無い。画像 ID はユーザーから受け取るか、既存商品の値を `getCreatorProduct` で取得するしかない。

それらしい文字列を作らない。ユーザーが「画像を付けたい」と言っただけで ID が分からない場合は、管理画面での画像アップロードと ID の確認を案内する。

### 作成後の流れを最初に伝える

作成された商品は非公開で始まり、公開には**公開中のプランが 1 つ以上**必要になる。プランはこのスキルでは作れない。

新規作成の依頼を受けた時点でこの前提を伝えておくと、「作ったのに公開できない」という行き違いを避けられる。

## 更新の組み立て

### 変更前の値を必ず取得する

`getCreatorProduct` で現在の内容を取得してから組み立てる。理由は 2 つ。

1. `imageIds` と `steps` は置き換えなので、既存の値を含めないと消える
2. 「変更前 → 変更後」をユーザーに示せる

### 送る項目を最小限にする

`patchCreatorProduct` は送ったフィールドだけを更新する。変えない項目は**送らない**のが安全。

例外は `imageIds` と `steps` で、これらは「変えないなら送らない」「変えるなら全件送る」のどちらかにする。一部だけ送るのが一番危ない。

### 長い本文は文字数を確認してから送る

表示テキストの上限は 10,000 文字。超えると拒否される。長文を扱うときは送る前におおよその長さを見て、超えそうならユーザーと削る内容を相談する。

## 公開・非公開の切り替え

### 公開できるかを先に確かめる

`getCreatorProductPlans` で公開中のプランがあるかを確認してから `PUBLIC` / `LIMITED` を送る。無ければ拒否されるので、先に管理画面でプランを公開してもらう。

販売期間が終了したプランは公開中に数えられない。プラン一覧の公開状態をそのまま信じず、販売期間も見る。

事業者情報の登録状況は事前に確認できない。**「公開できます」と断定しない。**

### 非公開にする影響を伝えてから承認を取る

非公開にすると紐づくプランもすべて非公開になる。公開に戻してもプランは自動では戻らない。この 2 点を伝えてから承認を取る。

「商品を一時的に隠したいだけ」という意図なら、限定公開（`LIMITED`）で足りることもある。選択肢として示す。

## 削除

削除は取り消せず、紐づくプランも同時に消える。次の順を崩さない。

1. `getCreatorProduct` で対象を読み戻し、**商品名で提示して**本当にこれで良いか確かめる
2. `isDeletable` を見る。`false` なら実行せずに理由を伝える
3. 取り消せないこと・プランも消えることを伝え、明示的な承認を取る
4. 実行する
5. 読み戻して消えたことを確認する

「削除して」と言われても、2 と 3 を飛ばさない。

## 提示の組み立て

- 変更点は「変更前 → 変更後」の形にする。項目名は日本語（商品名 / 商品説明 / 注意事項 / キャンセルポリシー / 申し込み後の流れ / 公開状態）
- 公開状態は日本語（公開 / 限定公開 / 非公開）で示す
- 公開した商品は `publicUrl` を添えて「このページで見られます」と伝える
- 本文が長い項目は全文を貼らず、要約と文字数で示す

## セルフレビューチェックリスト

送信前と読み戻し後の両方で確認する。

| # | 確認項目 |
|---|---|
| 1 | 必須項目（商品名・商品説明・注意事項・キャンセルポリシー）が実際の内容で埋まっているか。placeholder が残っていないか |
| 2 | `imageIds` を送るなら、既存の画像を含めた**全件**になっているか |
| 3 | `steps` を送るなら、変えないステップを含めた**全件**になっているか |
| 4 | `steps` の `orderNum` が重複していないか |
| 5 | `steps` の各要素に `imageId` があるか（無いなら `null`） |
| 6 | 画像 ID がユーザー由来か取得した既存値か。捏造していないか |
| 7 | 本文の表示テキストが 10,000 文字以内か |
| 8 | 変えないつもりの項目を送っていないか |
| 9 | 公開する前に、公開中のプランがあることを確認したか |
| 10 | 公開状態の変更・削除の直前に、ユーザーの承認を取ったか |
| 11 | 削除の前に `isDeletable` を確認したか |
| 12 | 保存後に読み戻して、意図どおりの内容になっていることを確認したか |
| 13 | 提示に生の内部 ID・enum の英字値・リッチテキストの内部形式が混じっていないか |
