# クーポン（発行・一覧・有効／無効・削除）

**いつ読むか**: プランのクーポン（割引コード）を発行する・一覧や詳細を見る・有効／無効を切り替える・削除するとき、「クーポンの内容を変えたい」と言われたとき。SKILL.md 手順 11 の本体と、項目・既定値・拒否メッセージの正本。

## ヒアリング順（発行）

内容は作成後に変えられないため、作成前に全部を確定させる。次の順で確認する。ゲストに配る値（割引とコード）を先に確定させ、あとから「やっぱり」が出やすい制限（枚数・期限）を最後に聞く並びになっている。値引額の上限はプランの価格なので、プランの価格を変える予定があるなら先に変えてからクーポンを作る。「全額無料にしたい」なら値引額をプランの価格と同額にするか割引率 100 にする。

1. 割引方法（割引率 (%) / 値引額 (円)）
2. その値（割引率は 1〜100、値引額は 1 円以上かつプランの価格以下）
3. クーポンコード（4〜20 文字の半角英数字と記号「-」「_」。ユーザーが指定しなければ案を出して確認する）
4. クーポン名（1〜40 文字。一覧で見分けるための名前。ゲストに配るのはコード）
5. 発行枚数（何枚まで使えるか）
6. 有効期限（いつまで使えるか）
7. サブスクリプションプランなら回数設定（初回割引 / 永久割引）

聞き取れなかった項目は下の「クーポンを作るときの既定値」（発行枚数は無制限・有効期限なし・初回割引）で埋めてよい。埋めた項目は保存前にユーザーへ提示する。

## 手順 11. クーポンの発行・管理（発行・削除・無効化はユーザー承認が必須）

プランに紐づくクーポン（割引コード）を発行し、一覧・詳細を確認し、有効／無効を切り替え、削除する。**クーポンの内容（コード・割引・枚数・期限・回数設定）は作成後に変更できない。** 変えたい依頼には更新ツールを送らず（有効／無効しか送れない）、「新しいクーポンを作成して、古いクーポンを無効にする」流れを案内する。古いクーポンを削除するかどうかは別に確認し、使用実績（使用回数）を残したいなら無効化に留める。項目の意味と制約は下の「クーポンの項目」を、リクエストの形は [../examples/create-coupon-amount.json](../examples/create-coupon-amount.json)（買い切りプランに値引額のクーポン）を参照する。

対象が旧サービス（商品一覧・詳細で `isLegacyService: true`）なら書き込まず、[content-schema.md](content-schema.md) の「旧サービス（isLegacyService: true）」の案内文で返す。

**発行**

1. SKILL.md 手順 2 でプランを特定し、`getCreatorProductPlan` で課金サイクルと価格を読む。値引額の上限（プランの価格）と、回数設定を聞くかどうか（サブスクリプションのみ）がここで決まる
2. `getCreatorProductPlanCoupons` で既存のクーポンを読み、**同じコードや同じ内容のクーポンが無いか**を確認する。あれば「すでに同じクーポンがあります」と伝えて意図を確かめる
3. 上の「ヒアリング順（発行）」で内容を確定し、埋めた既定値（発行枚数は無制限・有効期限なし・初回割引）を含めて**作成前に全項目を提示して承認を得る**。作成後は変えられないこと（変えたいときは新しいクーポンを作って古いものを無効にすること）をこのときに伝える
4. `postCreatorProductPlanCoupon` を呼ぶ。`amountOff`（値引額）と `percentOff`（割引率）は**どちらか一方だけ**を入れ、使わない方は `null` にする。買い切りプランでは `subscriptionDurationType` を送らない（送るなら `once`）
5. 返ってきた `couponId` で `getCreatorProductPlanCoupon` を読み戻し、クーポン名・コード・割引・発行枚数・有効期限・有効／無効を提示する。回数設定は取得項目に無いので、送った値を提示する
6. 商品が公開中なら、`getCreatorProduct` の `publicUrl` に `?couponCode=<コード>&openExternalBrowser=1` を付けた URL を「このリンクから申し込むとクーポンが自動で適用されます」として提示する。`publicUrl` が `null`（商品が非公開）、またはプランが非公開（複製直後のプランを含む）なら URL を出さず、公開後に案内できることを伝える
7. **同じ内容を再送しない。** コードが MOSH 全体で一意なため、成功していれば 2 回目はコードの重複で拒否される。失敗したように見えたら、先に一覧で作られていないかを確認する。コードの重複で拒否されたら（他のクリエイターのコードとも重複できない）、別のコードを提案する

**一覧・詳細**

- `getCreatorProductPlanCoupons` はページングされる（`limit` は既定 20、`offset` は既定 0）。`totalCount` はページに依らない総件数で、削除済みは含まない。取得済み件数より多ければ `offset` をずらして続きを取得する
- 提示は「クーポン名・コード・割引（10% OFF / 1,000 円 OFF）・使用状況（25/100 回使用、無制限なら 25 回使用）・有効期限（なしなら「無期限」）・有効／無効」の形にする。ID は出さない
- **過去の複製で共有されているクーポン**（同じ商品の他のプランのクーポン一覧に、同じ `id` のクーポンがあるもの。現在の複製ではクーポンを引き継がないので新たには生じない）は、使用回数も発行枚数の上限も共有しているプランの合算になる。提示のときに「<他のプラン名> と共有しているクーポンで、使用状況は両方のプランの合算です」と添える

**有効／無効の切り替え**

1. 一覧からクーポン名またはコードで対象を特定し、現在の状態（有効／無効）を提示する。同じ商品の他のプランのクーポン一覧も取得し、**同じ `id` のクーポンが無いか**（過去の複製で共有されていないか）を確かめる
2. **無効にするときは影響を伝えて承認を取る**: 「無効にすると、このコードを持っているゲストがその場で使えなくなります（あとから有効に戻せます）」。共有されているクーポンなら「<他のプラン名> でも同時に無効になります」を添える
3. `patchCreatorProductPlanCoupon` に `isEnabled` を送る。送れるのはこの 1 項目だけ
4. **無効化・有効化のあとは必ず `getCreatorProductPlanCoupon`（または一覧）で読み戻し、読み戻した値で「有効 / 無効」を伝える。** 更新の応答にはクーポンの状態が含まれないので、事前に取得した値や送った値で「無効になりました」と報告しない

**削除**

削除は取り消せない。無効化で足りることが多い（コードを一時的に止めたい・あとで再開したい）ので、削除の依頼でも**無効化を先に選択肢として示す**。

1. 一覧からクーポン名またはコードで対象を特定し、**クーポン名とコードで**提示して本当にこれで良いか確かめる。使用状況（使用回数）も添える。同じ商品の他のプランのクーポン一覧も取得し、**同じ `id` のクーポンが無いか**（過去の複製で共有されていないか）を確かめる
2. 「この操作は取り消せないこと」「このコードを持っているゲストが使えなくなること」「使用回数などの記録も一覧から消えること」を伝え、**明示的な承認を取る**（削除したクーポンのコードは、新しいクーポンで使い直せる）。共有されているクーポンなら「<他のプラン名> からも同時に消えること」も伝える（削除も無効化もプラン単位ではできず、共有しているすべてのプランに効く）
3. 承認を得てから `deleteCreatorProductPlanCoupon` を呼ぶ
4. `getCreatorProductPlanCoupons` を取得し直し、消えたことを確認して報告する。削除済みのクーポンは詳細を読むと「見つからない」旨になる

## 使用するツール

パスの `productId` / `productPlanId` / `couponId` はいずれも文字列。送る項目の必須・制約は下の「クーポンの項目」が正本。

| ツール | 用途 | 注意 |
|---|---|---|
| `getCreatorProductPlanCoupons` | 一覧 | `limit` は 1〜40。応答は `{ coupons, totalCount }`。存在しない・自分のものでないプランは「見つからない」旨のエラー |
| `postCreatorProductPlanCoupon` | 発行 | 返るのは `couponId` のみ。`getCreatorProductPlanCoupon` で読み戻す |
| `getCreatorProductPlanCoupon` | 詳細 | 応答は一覧の 1 件と同じ形 |
| `patchCreatorProductPlanCoupon` | 有効／無効の切り替えのみ | 応答は完了メッセージだけ |
| `deleteCreatorProductPlanCoupon` | 削除 | 削除したクーポンは一覧と `totalCount` から除かれる |

## クーポンの項目

`getCreatorProductPlanCoupons` / `postCreatorProductPlanCoupon` / `getCreatorProductPlanCoupon` / `patchCreatorProductPlanCoupon` / `deleteCreatorProductPlanCoupon`。パスは `productId` / `productPlanId` / `couponId`（いずれも文字列）。**作成後に内容は変更できない**。更新で送れるのは `isEnabled` だけ。

| 項目 | 作成 | 更新 | 取得 | 意味・扱い |
|---|---|---|---|---|
| `code` | 必須 | — | ○ | クーポンコード。**4〜20 文字の半角英数字と記号「-」「_」**。削除済みを除く MOSH 全体（他のクリエイターを含む）で一意。ゲストに配る値なので**提示してよい** |
| `name` | 必須 | — | ○ | クーポン名（**1〜40 文字**）。一覧で見分けるための名前。提示の主キーにする |
| `amountOff` | 任意 | — | ○ | 値引額（円）。1 円以上、**プランの価格以下**。`percentOff` と**どちらか一方を必ず指定**。使わないときは `null` |
| `percentOff` | 任意 | — | ○ | 割引率（%）。**1〜100**、整数推奨。`amountOff` と排他。使わないときは `null` |
| `maxRedemptions` | 任意 | — | ○ | 発行枚数（最大使用回数）。1 以上。**`null` は無制限** |
| `redemptionCount` | — | — | ○ | 使用回数 |
| `expiresAt` | 任意 | — | ○ | 有効期限。**現在より後の日時**。タイムゾーン付きの ISO 8601（例 `2027-04-30T23:59:59+09:00`）。**`null` は無期限** |
| `subscriptionDurationType` | 任意 | — | **無い** | 回数設定（適用期間）。`once`（初回割引）/ `forever`（永久割引）。**サブスクリプションプランのみ `forever` を指定できる**。買い切りプランは `once` のみ。省略時は `once`。**取得項目に無い**ので、既存のクーポンの回数設定は読めない |
| `isEnabled` | — | 必須 | ○ | 有効／無効。作成直後は有効 |
| `id` | — | — | ○ | クーポン ID。パスの `couponId` に使う。**提示しない** |
| `createdAt` | — | — | ○ | 作成日時 |

## クーポンを作るときの既定値

作成では `code` と `name` が必須で、割引方法（`amountOff` / `percentOff` のどちらか）も必ず要る。ユーザーが言及しなかった項目は次で埋め、**埋めた内容を保存前に提示する**。作成後に変えられないため、提示を省かない。

| 項目 | 既定値 | 理由 |
|---|---|---|
| `maxRedemptions` | `null` | 発行枚数の制限なし（無制限） |
| `expiresAt` | `null` | 有効期限なし（無期限） |
| `subscriptionDurationType` | 送らない（`once`） | 初回割引。買い切りでは `forever` を指定できず、サブスクリプションでも「永久割引」は明示的な希望があるときだけ |

`code` に既定値は無い。ユーザーが指定しなければ、4〜20 文字の半角英数字で案を出して確認を取る（管理画面ではランダムな英数字が初期値として入る）。

## 割引方法と回数設定

| 割引方法（管理画面の呼称） | 送る項目 | 制約 |
|---|---|---|
| 割引率 (%) | `percentOff` に 1〜100、`amountOff` は `null` | 整数推奨 |
| 値引額 (円) | `amountOff` に 1 以上、`percentOff` は `null` | プランの価格（`getCreatorProductPlan` の `price.amount`）以下 |

両方入れる・両方 `null` にすると拒否される。

| 回数設定（管理画面の呼称） | `subscriptionDurationType` | 使えるプラン |
|---|---|---|
| 初回割引 | `once` | 買い切り・サブスクリプションの両方 |
| 永久割引 | `forever` | サブスクリプションのみ（買い切りに指定すると拒否される） |

**fincode のクリエイターのサブスクリプションプランではクーポンを作れない。** 決済代行会社は事前に確認できないので、拒否されたらメッセージをそのまま伝える。買い切りプランは決済代行会社に関わらず作れる。

## 拒否されたときのメッセージ（クーポン）

クーポンの作成が拒否されたときは、理由が項目ごとのメッセージ（コードの重複・割引方法の指定誤り・価格超過・過去の有効期限・fincode のサブスクリプションなど）で返る。項目名（`code` / `amountOff` など）は見せず、メッセージの内容を日本語で伝えて、直した内容で作り直すかをユーザーに確認する。**削除済みのクーポン**を指定したときは「見つからない」旨のエラーになる。

| メッセージ | 意味 | 案内すること |
|---|---|---|
| 入力されたクーポンコードは既に使用されています。別のコードをご入力ください。 | コードが MOSH 全体（他のクリエイターを含む）で重複。同じ内容の再送でも起きる | 一覧で作られていないかを確認し、別のコードを提案する |
| 割引金額と割引率はどちらか一方だけを指定してください。 | `amountOff` と `percentOff` を両方指定した | どちらの割引方法にするかを確かめ、使わない方を `null` にする |
| 割引金額または割引率を指定してください。 | 割引方法が未指定（両方 `null`） | 割引方法を聞く |
| 割引率は1〜100の範囲で指定してください。 | `percentOff` が範囲外 | 1〜100 で設定し直す |
| 割引金額は1円以上で指定してください。 | `amountOff` が 0 以下 | 1 円以上にする |
| 割引金額はプランの価格以下で設定してください。 | `amountOff` がプランの価格を超えた | プランの価格を提示し、値引額を下げるか割引率に切り替える |
| 有効期限は現在より後の日時を指定してください。 | `expiresAt` が過去 | 日時を取り直す |
| 有効な有効期限をご設定ください | 有効期限が 5 年（60 ヶ月）より先（サブスクリプションのクーポンでのみ起きる） | 有効期限を近づけるか、無期限（`null`）にする |
| 買い切りプランのクーポンは適用期間に once しか指定できません。 | 買い切りプランに `forever` を指定した | 回数設定を送らない（初回割引） |
| fincode のサブスクリプションプランではクーポンを利用できません。 | 決済代行会社が対応していない | このプランではクーポンを作れない旨を伝える（買い切りプランなら作れる） |
