# 商品・プランの構造リファレンス

**いつ読むか**: 商品・プラン本体（作成・更新・表示順・公開・削除）の送信を組み立てる前、enum を日本語にして提示するとき、商品・プランの書き込みが拒否されたとき。

送信するリクエストの組み立て方と、返ってきたレスポンスの読み方。**商品・プラン本体の項目の範囲・組み合わせ・既定値・拒否メッセージと、enum の日本語変換表（全領域分）の正本はこのファイル。** プランの設定・複製・クーポンの項目と拒否メッセージは、それぞれ [membership-link.md](membership-link.md)（提供コンテンツ・ライセンス）/ [post-purchase-settings.md](post-purchase-settings.md)（サンクスページ・自動リダイレクト・感想レポート）/ [plan-duplicate.md](plan-duplicate.md)（複製）/ [coupons.md](coupons.md)（クーポン）が正本。SKILL.md・mcp-tools.md・best-practices.md は数値や表を再掲せず、これらを参照する。

## 旧サービス（isLegacyService: true）

**旧サービスのルールと案内文の正本はこの節。** SKILL.md・各領域ファイルはここを参照する。

商品の一覧・詳細の取得ツールは、`isLegacyService: true` を付けて旧サービスも返す。旧サービスは管理画面の旧サービスの編集画面で設定・販売するもので、このスキルが扱う商品とは別物。

- **判定**: 商品の一覧・詳細（`getCreatorProducts` / `getCreatorProduct`）の `isLegacyService` でだけできる（プランの取得には無い）。プランの設定・複製・クーポンの依頼でも、属する商品で確かめてから進める。`isMigratedFromLegacySite` は判定に使わない
- **意味**: `true` は「旧サービスのプランを 1 つでも含む」こと。旧サービスでないプランが混ざっていても、このスキルはその商品に丸ごと書き込まない
- **できること**: 読み取り（一覧・詳細・各設定の取得・既存クーポンの一覧と状態の確認）だけ
- **しないこと**: 書き込みは一切しない。API が拒否しない操作（提供コンテンツの紐付け・解除・ライセンス・自動リダイレクト・感想レポート・クーポンの発行・有効／無効・削除）も行わない。既存クーポンを案内するときもクーポン付き URL は作らない（旧サービスのページではクーポンが自動で入らない）
- **理由**: 旧サービスの編集画面では会員サイトを紐付けられないなど、API で書き込むと画面と食い違う状態を作るため。クーポンは旧サービスの画面・決済での扱いが確認できていない
- **一覧での示し方**: 商品の行に混ぜず、別枠で「旧サービス」として示す

**案内文**（変更の依頼には、書き込まずにこれだけを返す）

**旧サービスを「商品」と呼ばない（「旧サービスとして扱われている商品」も不可）。`isLegacyService` などの項目名や `true` などの値を文面に出さない。**

- **会員サイトの紐付け・ライセンス**: 「これは旧サービスです。旧サービスには会員サイトを紐付けられません。」（旧サービスの編集画面でも紐付けられないので、編集画面へは誘導しない）
- **それ以外の変更**: 「これは旧サービスなので、管理画面の旧サービスの編集画面で変更してください。」

API が拒否する書き込みは次のとおり（事実として記録。上のとおり試さない）。右列は実際に返る文言（原文のまま）。

| 操作 | 拒否されたときのメッセージ |
|---|---|
| 商品の更新（公開状態の切り替えを含む） | 旧サービスとして販売しているプランがある商品は、サービスの編集画面で編集してください |
| 商品の削除 | 旧サービスとして販売しているプランがある商品は削除できません |
| プランの追加 | 旧サービスとして販売しているプランがある商品には、プランを追加できません |
| プランの更新（公開状態の切り替えを含む） | 旧サービスとして販売しているプランは、サービスの編集画面で編集してください |
| プランの削除 | 旧サービスとして販売しているプランは削除できません |
| プランの複製 | 旧サービスとして販売しているプランは複製できません |
| サンクスページ／メールの更新 | 旧サービスとして販売しているプランのサンクス設定は、サービスの編集画面で編集してください |

## 文字数の 2 つの上限

`description` / `precautions` / `cancellationPolicy` には上限が 2 つある。混同しない。

- **表示テキスト 10,000 文字** … 実際にユーザーが読む文字数。超えると拒否される
- **送信ペイロード 100,000 文字** … リッチテキストの JSON はマークアップの分だけ長くなるため、その余裕を見た上限

プレーンテキストで送る場合、実質の上限は 10,000 文字と考えてよい。

## リッチテキストの扱い

`description` / `precautions` / `cancellationPolicy` は、管理画面のエディタで編集するとリッチテキストの内部形式（JSON 文字列）で保存される。

- **読むとき**: 取得した値が JSON 形式なら、本文テキストを取り出して提示する。内部形式のまま見せない
- **書くとき**: プレーンテキストで送ってよい。既存の内部形式を保つ必要があるときは、取得した値をそのまま送り返す
- **書き換えるとき**: 内部形式を手で編集しようとしない。全文をプレーンテキストで置き換えるか、ユーザーに管理画面での編集を案内する

## 置き換えになる項目

`imageIds` と `steps` は、送った配列がそのまま新しい内容になる。**差分ではない。**

```
既存:  imageIds = ["A", "B", "C"]
送信:  imageIds = ["D"]
結果:  imageIds = ["D"]     ← A・B・C は消える
```

1 枚追加したいなら `["A", "B", "C", "D"]` を送る。既存の値は `getCreatorProduct` で取得する。

`steps` も同じ。1 ステップだけ直す場合も、変えないステップを含めた全件を送る。

## 申し込み後の流れ（`steps`）

各ステップは `orderNum` / `title` / `description` / `imageId` の 4 項目すべてが必須。`imageId` は `null` を入れられるが、**項目ごと省略することはできない**。

`orderNum` は表示順序（0 以上の整数）。**同じ値を 2 つ以上入れると拒否される。**

## プランを作るときの既定値

作成では上表の「必須」がすべて要る。ユーザーが言及しなかった項目は次で埋め、**埋めた内容を保存前に提示する**。

| 項目 | 既定値 | 理由 |
|---|---|---|
| `publishingStatus` | `PRIVATE` | 内容を確認してもらってから公開する |
| `capacity` | `0` | 定員なし |
| `showRemaining` / `remainingThreshold` | `false` / `0` | 残席を出さない |
| `paymentMethods` | クレジットカードのみ有効 | 銀行振込は明示的な希望があるときだけ |
| `bankTransferDeadlineDays` | `null` | 標準の 15 日。銀行振込を有効にし、日数の指定があるときだけ入れる |
| `installmentType` / `installmentIterations` | `LUMP_SUM` / `[]` | 一括払い |
| `benefits` | `[]` | 特典なし |
| `discountPrice` | `null` | 割引表示なし |
| `applicationStartDateTime` / `applicationEndDateTime` / `applicationPeriods` | `null` | 受付期間の制限なし |
| `billingStartType` | `immediate` | 購入後すぐに初回課金 |
| `orderNum` | `0` | 自動採番されるので値に意味はない |

## 課金サイクルと受付期間の対応

受付期間の設定先は課金サイクルで分かれる。**混ぜると拒否される。**

| 課金サイクル | 受付期間の設定先 | 空にする項目 |
|---|---|---|
| `ONE_TIME`（買い切り） | `applicationStartDateTime` / `applicationEndDateTime` | `applicationPeriods` は空配列か `null`、`initialPrice` / `iterations` は `null`、`benefits` は `[]` |
| `MONTHLY` / `YEARLY`（サブスクリプション） | `applicationPeriods` | `applicationStartDateTime` / `applicationEndDateTime` / `discountPrice` は常に `null` |

買い切りに `initialPrice` / `iterations` / `applicationPeriods` を入れると拒否される。

買い切りの販売受付期間の組み合わせ:

| 開始 | 締切 | 結果 |
|---|---|---|
| `null` | `null` | 受付期間の制限なし |
| 日時 | `null` | 開始日時から受付 |
| `null` | 日時 | **拒否される**（締切だけを指定すると保存した瞬間から受付中になるため、開始も必須） |
| 日時 | 日時 | 開始が締切より前のときだけ通る。同じ日時・逆順は拒否される |

**締切を設定するときの開始日時はユーザーに聞く。** 「12月末まで受付」のように締切だけを頼まれたとき、作成日時・今日・過去日などを開始日時に勝手に入れて送らない。「今すぐ受付開始（今の日時）」「指定日から」を選択肢として示してよいが、選ぶのはユーザー。既存のプランで開始が未設定（制限なし）のまま締切を足す・変える依頼も同じ。

サブスクリプションの決済方法はクレジットカードのみ。`paymentMethods` の `BANK_TRANSFER` は `isEnabled: false`、`bankTransferDeadlineDays` は `null` にする。

## 初回価格（`initialPrice`）

初回価格はサブスクリプション × fincode のクリエイター限定。**Stripe のクリエイターが送ると拒否されずに無視され**（エラーにならない）、`null` で保存されて通常価格と同額で課金される。決済代行会社は事前に確かめられないので、初回価格を指定したら作成後に読み戻し、初回価格が `null` になっていないかを確かめる。`null` なら「この決済代行会社では初回価格を使えなかった（初回も通常価格で課金される）」と伝え、どうするかを相談する。

## 価格の範囲

`amount` は **0 円（無料）または 100 円以上**。上限と下限は課金サイクルと分割払いの設定、そしてクリエイターの決済代行会社で変わる。

- サブスクリプションは 1,000,000 円以下。買い切りは 2,700,000 円以下だが、決済代行会社によってはこれより低い
- 分割入金（`INSTALLMENT`）のプランは 4,000 円以上
- サブスクリプションは決済代行会社によって 0 円（無料）を許さない

`discountPrice` は**価格より大きい**必要がある（同額・それ以下は拒否される）。上限は価格の上限（決済代行会社・課金サイクルで決まる値）と同じ。

**決済代行会社を事前に確認する手段は無い。** 範囲を断定せず、拒否されたらメッセージの数値をそのまま伝える。

## 割引前の価格と価格の更新

プランの更新で `discountPrice` を省略するか、取得した現在値をそのまま送ると「変更なし」として扱われる。ただし保存済みの値によって結果が変わる。

| 保存済みの割引前の価格 | 結果 |
|---|---|
| サブスクリプションのプランに値が残っている | `null` に置き換わる（割引表示が消える） |
| 買い切りで、更新前の価格以下かつ更新後の価格以下（すでに打ち消し線の意味が無い古い値） | `null` に置き換わる |
| 買い切りで、更新前の価格より大きく、更新後の価格以下（価格を割引前の価格以上に上げた） | **拒否される**（「割引前の価格は価格より大きい金額で設定してください」） |
| 買い切りで、更新後の価格より大きい | そのまま残る |

- 価格を上げる依頼では、送る前に割引前の価格と比べる。新しい価格が割引前の価格以上になるなら、割引前の価格も上げるか、`null` にして割引表示をやめるかをユーザーに確かめる
- 価格を変えたあとの読み戻しでは、価格と一緒に割引前の価格（消えていないか・意図どおりか）も確かめて提示する

## 分割払い

`installmentType` は一括払い / 分割払いの選択肢を表す（下の変換表）。組み合わせのルールは次のとおり。

| `installmentType` | `installmentIterations` | 備考 |
|---|---|---|
| `LUMP_SUM`（一括払い） | **空配列**。値を入れると拒否される | — |
| `INSTALLMENT_LUMP_DEPOSIT`（一括入金） | 任意。**送っても保存されない**（分割回数はカード会社側で決まる）。取得では空配列で返るので、更新では `[]` を送ればよい | fincode のクリエイターのみ |
| `INSTALLMENT`（分割入金） | **1 件以上必須**。`count` は 2 以上、`price` は 1 円以上か `null`（`null` は個別金額を指定しない） | 1 回あたりの金額を決められるのはこのタイプだけ |

分割払い（`LUMP_SUM` 以外）では**クレジットカード決済を有効にする**（`paymentMethods` の `CARD` を `isEnabled: true`）。無効だと拒否される。

分割回数（`count`）と 1 回あたりの金額（`price`）が保存されるのは**分割入金だけ**。分割入金から一括入金（または一括払い）へ切り替えると、保存済みの回数と金額は消える。あとで分割入金に戻すなら回数を指定し直す。

支払い総額（`count` × `price`）は、プラン価格を下回れず、決済代行会社ごとの上限も超えられない。

**サブスクリプションでは一括払い（`LUMP_SUM`）にする。** 管理画面でもサブスクリプションはカード一括払いしか選べない。

## 課金開始日（サブスクリプションのみ）

`billingStartType` で初回課金のタイミングを決める。作成時に設定し、更新できるのは非公開かつ購読者ゼロの間だけ（`isBillingStartEditable`）。

| 値 | 意味 | 併せて送る項目 |
|---|---|---|
| `immediate` | 購入後すぐに初回課金 | `billingStartAbsoluteDate: null` / `billingStartRelativeOffsetDays: 0` |
| `absolute` | 日付を指定して課金開始 | `billingStartAbsoluteDate` に **今日以降・1 年以内**の日付 |
| `relative` | 購入から N 日後に課金開始 | `billingStartRelativeOffsetDays` に 1〜365 |

`absolute` なら `billingStartAbsoluteDate`、`relative` なら 1 以上の `billingStartRelativeOffsetDays` を必ず添える。値が無いと拒否される。

**Stripe のクリエイターの月額プランでは、課金回数と課金開始日（`immediate` 以外）を併用できない。** 年額プランなら併用できる。

これはプランの設定値で、ゲストごとに解決される実際の初回課金日ではない。

**更新での扱い**: 取得では `billingStartRelativeOffsetDays` が `relative` 以外のとき `null`（`billingStartAbsoluteDate` も `absolute` 以外は `null`）で返るが、更新では日数に `null` を送れず形式エラーになる。

- **課金開始日を変えないなら 3 項目とも省略する**（省略で現在値を維持する）。取得値をそのまま送り返さない
- 変えるときは上表の組み合わせで 3 項目をそろえて送る。`immediate` / `absolute` では日数を `0` にする
- `billingStartType` を送らずに日付・日数だけを送ると拒否される（「課金開始日を変更する場合は billingStartType を指定してください。」）

## 作成後に変更できない項目

| 項目 | 変えたいときの案内 |
|---|---|
| 課金サイクル（`billingCycle`） | 新しいプランを作る |
| 課金回数（`iterations`） | 同上 |
| 初回価格（`initialPrice`） | 同上 |

更新で現在値と違う値を送ると拒否される。**現在値をそのまま含めて送る。**

課金開始日（`billingStart*`）は非公開かつ購読者ゼロの間だけ変更できる（`isBillingStartEditable`）。公開中または購入者がいるプランで変えたいときは新しいプランを作る。

## プラン名・価格のロック

サブスクリプションプランは、**非公開かつ購読者（解約済みを含む）が 1 人もいない**ときだけプラン名と価格を変更できる。買い切りプランは常に変更できる。

取得したプランの `isNameEditable` / `isPriceEditable` が `false` なら、送る前に分かる。この場合は送り直さず、**新しいプランを作成して、このプランを非公開にする**流れを案内する。

## 申込期間（`applicationPeriods`）の組み立て

サブスクリプションの受付期間。1 要素が 1 つの受付時間帯を表し、繰り返しは `recurringFrequency` で指定する。

| `recurringFrequency` | 併せて必要な項目 |
|---|---|
| `NONE`（繰り返しなし） | なし。**繰り返し設定を送ると拒否される** |
| `DAILY`（日毎） | `recurringInterval`（1 以上） |
| `WEEKLY`（週ごと） | `recurringInterval` + `recurringDaysOfWeek`（1 つ以上） |
| `MONTHLY`（月ごと） | `recurringInterval` + `recurringWeekOfMonth`（1 つ以上） + `recurringDaysOfWeek`（1 つ以上） |

- `startDateTime` / `endDateTime` は 1 回分の受付時間帯。`endDateTime` は `startDateTime` より後
- `recurringDaysOfWeek` は 1=月曜 〜 7=日曜、`recurringWeekOfMonth` は 1〜5
- 繰り返しの終わりは `recurringEndDateTime`（`null` は無期限）

## 表示順の並び替え

`productPlanIds` に並べたい順でプラン ID を入れる。**非公開のプランも対象。**

```
既存の順:  A, B, C, D
送信:      C, A
結果:      C, A, B, D     ← 送らなかった B・D は既存の相対順のまま末尾へ
```

意図した順にするには、`getCreatorProductPlans` で取得した**全プラン**を並べて送る。

`productId` はここだけ**数値**で渡す。他のプラン操作では文字列。

## 公開の条件

`publishingStatus` を `PUBLIC` または `LIMITED` にするには、次の両方が必要。

1. **公開中のプランが 1 つ以上ある**。プランの公開状態は販売期間を反映した実効値で判定されるため、販売期間が終了したプランは公開中に数えられない
2. **事業者情報が登録済み**。これを事前に確認するツールは無い

非公開（`PRIVATE`）へ戻すときは、どちらの条件も問われない。

## 公開状態を変えたときのプランへの波及

| 変更 | 紐づくプランへの影響 |
|---|---|
| → `PRIVATE` | **すべて非公開になる**。ただし公開中の別商品も同じ旧サービスを参照しているプランは非公開にしない |
| → `PUBLIC` / `LIMITED` | プランの公開設定は変わらない（非公開のプランは非公開のまま） |

非公開にしてから公開に戻しても、プランの公開設定は自動では戻らない。ユーザーにこれを伝える。

商品が**限定公開**のときは、プランに `PUBLIC` を指定しても限定公開として扱われる。プラン側だけを公開にしても、商品が非公開ならゲストからは見えない。

## 拒否されたときのメッセージ

拒否理由は返ってきたメッセージにそのまま入っている。商品・プラン本体の主なものは次のとおり（「旧サービスとして販売している…」で始まるものは上の「旧サービス（isLegacyService: true）」。提供コンテンツ・ライセンス・購入後設定・複製・クーポンのものは各領域ファイルの「拒否されたときのメッセージ」）。**再試行せず**、内容を伝えて次の行動を案内する。

| メッセージ | 意味 | 案内すること |
|---|---|---|
| 公開されているプランがありません。プランを公開してから商品を公開してください。 | 公開中のプランが 0 件 | このスキルでプランを公開する（`patchCreatorProductPlan` の `publishingStatus`）か、新しく作成する |
| 事業者情報が登録されていないため商品を公開できません。事業者情報を登録してから公開してください。 | 事業者情報が未登録 | 管理画面で事業者情報を登録してもらう |
| 事業者情報を確認できませんでした。決済設定をご確認ください。 | 事業者情報の状態を判定できなかった | 管理画面の決済設定を確認してもらう |
| 指定された画像が見つかりません。 | 画像 ID（`imageIds` / `steps[].imageId`）が存在しないか、自分がアップロードした画像でない | アップロードした画像なら [media-upload.md](media-upload.md) の「失敗したとき」に従う。ユーザーから受け取った ID なら確認し直す |
| 申込後の流れの表示順が重複しています。 | `steps` の `orderNum` が重複 | 重複を解消して送り直す |
| 本文は10,000文字以内で入力してください。 | 表示テキストが上限超過 | 削る内容をユーザーと相談する |
| サブスク購読中またはサービス購入済のゲストがいるため削除できません。 | 商品の削除で、配下のプランに購入者がいる | 削除できない旨を伝え、非公開を代案に示す |

プラン特有のものは次のとおり。

| メッセージ | 意味 | 案内すること |
|---|---|---|
| 課金サイクル・課金回数・初回価格はプラン作成後に変更できません。変更する場合は新しいプランを作成してください。 | 変更できない項目に現在値と違う値を送った | 現在値のまま送り直すか、新しいプランを作る |
| 公開中または購入者がいるサブスクリプションプランはプラン名・価格を変更できません。価格を変える場合は新しいプランを作成し、このプランを非公開にしてください。 | プラン名・価格がロックされている | 新プラン作成 + 旧プラン非公開を案内する |

| productPlanIds に重複したIDは指定できません。 / 指定された productPlanIds に不正なIDが含まれています。 | 並び替えで同じプランを 2 回入れた、またはこの商品に無いプランを含めた | `getCreatorProductPlans` で取り直した全プランを 1 回ずつ並べて送り直す |
