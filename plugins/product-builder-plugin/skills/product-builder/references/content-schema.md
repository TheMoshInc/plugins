# 商品・プランの構造リファレンス

送信するリクエストの組み立て方と、返ってきたレスポンスの読み方。

## 商品の項目

| 項目 | 作成 | 更新 | 意味・扱い |
|---|---|---|---|
| `name` | 必須 | 任意 | 商品名（1〜100 文字）。提示の主キーにする |
| `description` | 必須 | 任意 | 商品説明。プレーンテキストでもリッチテキストの JSON 文字列でも送れる |
| `precautions` | 必須 | 任意 | サービスに関する注意事項。同上 |
| `cancellationPolicy` | 必須 | 任意 | キャンセルポリシー。同上 |
| `imageIds` | 任意 | 任意 | 商品画像の ID 一覧（最大 7 件）。**置き換え**。**提示しない** |
| `publishingStatus` | 指定不可 | 任意 | 公開ステータス（下の変換表）。作成時は常に非公開 |
| `steps` | 指定不可 | 任意 | 申し込み後の流れ。**置き換え** |
| `id` | — | — | 商品 ID。**提示しない** |
| `slug` | — | — | 公開 URL 用の識別子。**提示しない**（URL は `publicUrl` を使う） |
| `isDeletable` | — | — | 削除可能か。配下プランにサブスク購読中またはアクティブな購入者がいると `false` |
| `publicUrl` | — | — | ゲスト向け商品ページの URL。**非公開ではページが存在しないため `null`（正常）** |
| `planCount` | — | — | 紐づくプラン件数 |
| `createdAt` / `updatedAt` | — | — | 作成・更新日時 |

## 文字数の 2 つの上限

`description` / `precautions` / `cancellationPolicy` には上限が 2 つある。混同しない。

- **表示テキスト 10,000 文字** … 実際にユーザーが読む文字数。超えると拒否される
- **送信ペイロード 100,000 文字** … リッチテキストの JSON はマークアップの分だけ長くなるため、その余裕を見た上限

プレーンテキストで送る場合、実質の上限は 10,000 文字と考えてよい。

## リッチテキストの扱い

`description` / `precautions` / `cancellationPolicy` は、管理画面のエディタで編集するとリッチテキストの内部形式（JSON 文字列）で保存される。

- **読むとき**: 取得した値が JSON 形式なら、本文テキストを取り出して提示する。内部形式のまま見せない
- **書くとき**: プレーンテキストで送ってよい。既存の内部形式を保つ必要があるときは、取得した値をそのまま送り返す
- **書き換えるとき**: 内部形式を手で編集しようとしない。全文をプレーンテキストで置き換えるか、ユーザーに管理画面での編集を案内する

## 置き換えになる項目

`imageIds` と `steps` は、送った配列がそのまま新しい内容になる。**差分ではない。**

```
既存:  imageIds = ["A", "B", "C"]
送信:  imageIds = ["D"]
結果:  imageIds = ["D"]     ← A・B・C は消える
```

1 枚追加したいなら `["A", "B", "C", "D"]` を送る。既存の値は `getCreatorProduct` で取得する。

`steps` も同じ。1 ステップだけ直す場合も、変えないステップを含めた全件を送る。

## 申し込み後の流れ（`steps`）

各ステップは `orderNum` / `title` / `description` / `imageId` の 4 項目すべてが必須。`imageId` は `null` を入れられるが、**項目ごと省略することはできない**。

`orderNum` は表示順序（0 以上の整数）。**同じ値を 2 つ以上入れると拒否される。**

## プランの項目

| 項目 | 作成 | 更新 | 意味・扱い |
|---|---|---|---|
| `name` | 必須 | 必須 | プラン名（1〜50 文字）。提示の主キーにする |
| `description` | 必須 | 必須 | プラン説明（10,000 文字まで） |
| `orderNum` | 必須 | 必須 | 表示順序。**作成時は自動採番され、送った値は無視される** |
| `publishingStatus` | 必須 | 必須 | 公開設定（下の変換表） |
| `capacity` | 必須 | 必須 | 定員（0〜1,000,000）。**`0` は「定員なし（無制限）」で、「定員 0 人」ではない** |
| `showRemaining` | 必須 | 必須 | 公開ページに残席数を出すか |
| `remainingThreshold` | 必須 | 必須 | 残席がこの数以下になったら表示する。`showRemaining` が `true` なら 1 以上、かつ定員以下 |
| `price` | 必須 | 必須 | `{ amount, currency }`。`currency` は `JPY` |
| `discountPrice` | 必須 | 任意 | 割引前の価格（打ち消し線で表示される元値）。無いなら `null`。指定するなら 1 円以上、かつ**価格より大きい** |
| `paymentMethods` | 必須 | 必須 | `{ method, isEnabled }` の配列。買い切りでは 1 つ以上を有効にする |
| `billingCycle` | 必須 | 必須（変更不可） | 課金サイクル（下の変換表） |
| `benefits` | 必須 | 必須 | 特典内容。サブスクリプションで使い、買い切りでは `[]` を送る。**最大 10 件・各 50 文字** |
| `installmentType` | 必須 | 必須 | 分割払いタイプ（下の変換表） |
| `installmentIterations` | 必須 | 必須 | 分割回数と 1 回あたりの金額。`installmentType` との組み合わせは下の「分割払い」 |
| `applicationStartDateTime` / `applicationEndDateTime` | 必須 | 必須 | 販売受付の開始・終了日時。`null` は制限なし。**サブスクリプションでは常に `null`** |
| `initialPrice` | 任意 | 任意（変更不可） | 初回価格（1 円以上）。**fincode のクリエイターのサブスクリプションでのみ使う**。`null` で通常価格と同額 |
| `iterations` | 任意 | 任意（変更不可） | 課金回数（初回を含む合計、1〜12）。サブスクリプションかつ **Stripe のクリエイターのみ**。`null` で無制限 |
| `applicationPeriods` | 任意 | 任意 | 申込期間。**サブスクリプションのみ**。`null` または空配列は制限なし |
| `billingStartType` / `billingStartAbsoluteDate` / `billingStartRelativeOffsetDays` | 任意 | **項目が無い** | 課金開始日の指定。作成時のみ設定でき、後から変えられない |
| `isSuspended` | — | 必須 | 販売受付停止フラグ。`true` は公開のまま受付だけ止める |
| `id` / `productId` / `moshServiceId` | — | — | 内部 ID。**提示しない** |
| `remainingCapacity` | — | — | 残り枠。定員なしのときは `null` |
| `isDeletable` | — | — | 削除できるか。購読中・購入済みのゲストがいると `false` |
| `isNameEditable` / `isPriceEditable` | — | — | プラン名 / 価格を変更できるか（下の「プラン名・価格のロック」） |
| `salesStatus` | — | — | 販売状態（下の変換表） |
| `membershipSites` | — | — | 紐づく会員サイト。`name` で提示し `id` は出さない |

## プランを作るときの既定値

作成では上表の「必須」がすべて要る。ユーザーが言及しなかった項目は次で埋め、**埋めた内容を保存前に提示する**。

| 項目 | 既定値 | 理由 |
|---|---|---|
| `publishingStatus` | `PRIVATE` | 内容を確認してもらってから公開する |
| `capacity` | `0` | 定員なし |
| `showRemaining` / `remainingThreshold` | `false` / `0` | 残席を出さない |
| `paymentMethods` | クレジットカードのみ有効 | 銀行振込は明示的な希望があるときだけ |
| `installmentType` / `installmentIterations` | `LUMP_SUM` / `[]` | 一括払い |
| `benefits` | `[]` | 特典なし |
| `discountPrice` | `null` | 割引表示なし |
| `applicationStartDateTime` / `applicationEndDateTime` / `applicationPeriods` | `null` | 受付期間の制限なし |
| `billingStartType` | `immediate` | 購入後すぐに初回課金 |
| `orderNum` | `0` | 自動採番されるので値に意味はない |

## 課金サイクルと受付期間の対応

受付期間の設定先は課金サイクルで分かれる。**混ぜると拒否される。**

| 課金サイクル | 受付期間の設定先 | 空にする項目 |
|---|---|---|
| `ONE_TIME`（買い切り） | `applicationStartDateTime` / `applicationEndDateTime` | `applicationPeriods` は空配列か `null`、`initialPrice` / `iterations` は `null`、`benefits` は `[]` |
| `MONTHLY` / `YEARLY`（サブスクリプション） | `applicationPeriods` | `applicationStartDateTime` / `applicationEndDateTime` は常に `null` |

買い切りに `initialPrice` / `iterations` / `applicationPeriods` を入れると拒否される。

## 価格の範囲

`amount` は **0 円（無料）または 100 円以上**。上限と下限は課金サイクルと分割払いの設定、そしてクリエイターの決済代行会社で変わる。

- サブスクリプションは 1,000,000 円以下。買い切りは 2,700,000 円以下だが、決済代行会社によってはこれより低い
- 分割入金（`INSTALLMENT`）のプランは 4,000 円以上
- サブスクリプションは決済代行会社によって 0 円（無料）を許さない

`discountPrice` は**価格より大きい**必要がある（同額・それ以下は拒否される）。上限は価格と同じ。

**決済代行会社を事前に確認する手段は無い。** 範囲を断定せず、拒否されたらメッセージの数値をそのまま伝える。

## 分割払い

`installmentType` は一括払い / 分割払いの選択肢を表す（下の変換表）。組み合わせのルールは次のとおり。

| `installmentType` | `installmentIterations` | 備考 |
|---|---|---|
| `LUMP_SUM`（一括払い） | **空配列**。値を入れると拒否される | — |
| `INSTALLMENT_LUMP_DEPOSIT`（一括入金） | 必須ではないが**入れれば使われる**。カード会社が提示する分割回数になる。`price` は無視される | fincode のクリエイターのみ |
| `INSTALLMENT`（分割入金） | **1 件以上必須**。`count` は 2 以上、`price` は 1 円以上か `null`（`null` は個別金額を指定しない） | 1 回あたりの金額を決められるのはこのタイプだけ |

分割払い（`LUMP_SUM` 以外）では**クレジットカード決済を有効にする**（`paymentMethods` の `CARD` を `isEnabled: true`）。無効だと拒否される。

分割回数（`count`）は一括入金・分割入金の**どちらでも使われる**。1 回あたりの金額（`price`）だけが分割入金専用で、一括入金では無視される。一括入金へ切り替えるときも回数を空にしない。

支払い総額（`count` × `price`）は、プラン価格を下回れず、決済代行会社ごとの上限も超えられない。

**サブスクリプションでは一括払い（`LUMP_SUM`）にする。** 管理画面でもサブスクリプションはカード一括払いしか選べない。

## 課金開始日（サブスクリプションのみ）

`billingStartType` で初回課金のタイミングを決める。**作成時にしか設定できない。**

| 値 | 意味 | 併せて送る項目 |
|---|---|---|
| `immediate` | 購入後すぐに初回課金 | `billingStartAbsoluteDate: null` / `billingStartRelativeOffsetDays: 0` |
| `absolute` | 日付を指定して課金開始 | `billingStartAbsoluteDate` に **今日以降・1 年以内**の日付 |
| `relative` | 購入から N 日後に課金開始 | `billingStartRelativeOffsetDays` に 1〜365 |

`absolute` なら `billingStartAbsoluteDate`、`relative` なら 1 以上の `billingStartRelativeOffsetDays` を必ず添える。値が無いと拒否される。

**Stripe のクリエイターの月額プランでは、課金回数と課金開始日を併用できない。** 年額プランなら併用できる。

これはプランの設定値で、ゲストごとに解決される実際の初回課金日ではない。

## 作成後に変更できない項目

| 項目 | 変えたいときの案内 |
|---|---|
| 課金サイクル（`billingCycle`） | 新しいプランを作る |
| 課金回数（`iterations`） | 同上 |
| 初回価格（`initialPrice`） | 同上 |
| 課金開始日（`billingStart*`） | 同上。更新リクエストには項目自体が無い |

更新で現在値と違う値を送ると拒否される。**現在値をそのまま含めて送る。**

## プラン名・価格のロック

サブスクリプションプランは、**非公開かつ購読者（解約済みを含む）が 1 人もいない**ときだけプラン名と価格を変更できる。買い切りプランは常に変更できる。

取得したプランの `isNameEditable` / `isPriceEditable` が `false` なら、送る前に分かる。この場合は送り直さず、**新しいプランを作成して、このプランを非公開にする**流れを案内する。

## 申込期間（`applicationPeriods`）の組み立て

サブスクリプションの受付期間。1 要素が 1 つの受付時間帯を表し、繰り返しは `recurringFrequency` で指定する。

| `recurringFrequency` | 併せて必要な項目 |
|---|---|
| `NONE`（繰り返しなし） | なし。**繰り返し設定を送ると拒否される** |
| `DAILY`（日毎） | `recurringInterval`（1 以上） |
| `WEEKLY`（週ごと） | `recurringInterval` + `recurringDaysOfWeek` |
| `MONTHLY`（月ごと） | `recurringInterval` + `recurringWeekOfMonth` + `recurringDaysOfWeek` |

- `startDateTime` / `endDateTime` は 1 回分の受付時間帯。`endDateTime` は `startDateTime` より後
- `recurringDaysOfWeek` は 1=月曜 〜 7=日曜、`recurringWeekOfMonth` は 1〜5
- 繰り返しの終わりは `recurringEndDateTime`（`null` は無期限）

## 表示順の並び替え

`productPlanIds` に並べたい順でプラン ID を入れる。**非公開のプランも対象。**

```
既存の順:  A, B, C, D
送信:      C, A
結果:      C, A, B, D     ← 送らなかった B・D は既存の相対順のまま末尾へ
```

意図した順にするには、`getCreatorProductPlans` で取得した**全プラン**を並べて送る。

`productId` はここだけ**数値**で渡す。他のプラン操作では文字列。

## enum の日本語変換表

| 項目 | 値 → 表示 |
|---|---|
| `publishingStatus` | `PUBLIC`=公開 / `LIMITED`=限定公開 / `PRIVATE`=非公開 |
| `billingCycle` | `ONE_TIME`=買い切り / `MONTHLY`=月額 / `YEARLY`=年額 |
| `paymentMethods[].method` | `CARD`=クレジットカード / `BANK_TRANSFER`=銀行振込 |
| `installmentType` | `LUMP_SUM`=一括払い / `INSTALLMENT_LUMP_DEPOSIT`=一括払い または 分割払い（一括入金） / `INSTALLMENT`=一括払い または 分割払い（分割入金） |
| `salesStatus` | `forSale`=受付中 / `notForSale`=受付停止中 / `soldOut`=満員 / `beforeApplicationPeriod`=受付開始前 / `afterApplicationPeriod`=受付終了 / `outOfApplicationPeriod`=受付期間外 |
| `recurringFrequency` | `NONE`=繰り返しなし / `DAILY`=日毎 / `WEEKLY`=週ごと / `MONTHLY`=月ごと |
| `billingStartType` | `immediate`=購入後すぐ / `absolute`=指定日から / `relative`=購入から N 日後 |

## 公開の条件

`publishingStatus` を `PUBLIC` または `LIMITED` にするには、次の両方が必要。

1. **公開中のプランが 1 つ以上ある**。プランの公開状態は販売期間を反映した実効値で判定されるため、販売期間が終了したプランは公開中に数えられない
2. **事業者情報が登録済み**。これを事前に確認するツールは無い

非公開（`PRIVATE`）へ戻すときは、どちらの条件も問われない。

## 公開状態を変えたときのプランへの波及

| 変更 | 紐づくプランへの影響 |
|---|---|
| → `PRIVATE` | **すべて非公開になる**。ただし公開中の別商品も同じ内容を参照しているプランは非公開にしない |
| → `PUBLIC` / `LIMITED` | プランの公開設定は変わらない（非公開のプランは非公開のまま） |

非公開にしてから公開に戻しても、プランの公開設定は自動では戻らない。ユーザーにこれを伝える。

商品が**限定公開**のときは、プランに `PUBLIC` を指定しても限定公開として扱われる。プラン側だけを公開にしても、商品が非公開ならゲストからは見えない。

## 拒否されたときのメッセージ

拒否理由は返ってきたメッセージにそのまま入っている。主なものは次のとおり。**再試行せず**、内容を伝えて次の行動を案内する。

| メッセージ | 意味 | 案内すること |
|---|---|---|
| 公開されているプランがありません。プランを公開してから商品を公開してください。 | 公開中のプランが 0 件 | 管理画面でプランを公開してもらう |
| 事業者情報が登録されていないため商品を公開できません。事業者情報を登録してから公開してください。 | 事業者情報が未登録 | 管理画面で事業者情報を登録してもらう |
| 事業者情報を確認できませんでした。決済設定をご確認ください。 | 事業者情報の状態を判定できなかった | 管理画面の決済設定を確認してもらう |
| 指定された画像が見つかりません。 | 画像 ID が存在しないか、自分の画像でない | 画像 ID をユーザーに確認し直す |
| 申込後の流れの表示順が重複しています。 | `steps` の `orderNum` が重複 | 重複を解消して送り直す |
| 本文は10,000文字以内で入力してください。 | 表示テキストが上限超過 | 削る内容をユーザーと相談する |
| サブスク購読中またはサービス購入済のゲストがいるため削除できません。 | 購入者がいるため削除不可 | 削除できない旨を伝える |

プラン特有のものは次のとおり。

| メッセージ | 意味 | 案内すること |
|---|---|---|
| 課金サイクル・課金回数・初回価格はプラン作成後に変更できません。変更する場合は新しいプランを作成してください。 | 変更できない項目に現在値と違う値を送った | 現在値のまま送り直すか、新しいプランを作る |
| 公開中または購入者がいるサブスクリプションプランはプラン名・価格を変更できません。価格を変える場合は新しいプランを作成し、このプランを非公開にしてください。 | プラン名・価格がロックされている | 新プラン作成 + 旧プラン非公開を案内する |
| 定員は現在の購読者数以上に設定してください。 | 定員を購読者数より小さくした | 現在の購読者数を確認してもらう |
| 課金回数は1〜12回で設定してください。 | `iterations` が範囲外 | 1〜12 で設定し直す |
| 課金回数はサブスクリプションプランのみ設定できます。 / 初回価格はサブスクリプションプランのみ設定できます。 | 買い切りプランに指定した | 買い切りでは送らない（`null`） |
| 課金回数設定は Stripe のクリエイターのみ利用可能です。 | 決済代行会社が対応していない | 課金回数なし（`null`）で作り直すか、無制限で運用してもらう |
| 課金開始日設定はサブスクリプションプランのみ利用可能です。 | 買い切りに課金開始日を指定した | 買い切りでは `immediate` にする |
| Stripeの月額プランでは課金回数設定と課金開始日設定を併用できません。 | 併用できない組み合わせ | どちらかを諦めるか、年額プランにするかを相談する |
| 日付を指定して課金開始する場合は課金開始日を指定してください。 / 申し込みからの日数で課金開始する場合は日数を指定してください。 | 課金開始日の値が欠けている | 日付または日数（1 以上）を聞いて添える |
| 初回価格は0円以下に設定できません。1円以上を指定してください。 | 初回価格が 0 以下 | 1 円以上にする（無料にしたいなら初回価格を使わない） |
| 分割プランの支払い総額が◯◯円を上回っています。1回あたりの金額を引き下げてください。 | 分割の総額が決済代行会社の上限超過 | メッセージの数値をそのまま伝える |
| サブスクリプションプランでは販売受付期間を設定できません。申込期間で設定してください。 | サブスクに `applicationStartDateTime` 等を指定した | 申込期間に置き換える |
| 都度払いのプランでは申込期間を設定できません。販売受付期間で設定してください。 | 買い切りに `applicationPeriods` を指定した | 販売受付期間に置き換える |
| 都度払いのプランでは決済方法を1つ以上有効にしてください。 | すべての決済方法が無効 | 有効にする決済方法を確認する |
| 分割払いを設定する場合はクレジットカード決済を有効にしてください。 | 分割払いなのにカードが無効 | カード決済を有効にする |

| 支払い総額がプラン価格を下回っています。1回あたりの金額を引き上げてください。 | 分割の総額不足 | 1 回あたりの金額を上げてもらう |
| 残り人数を表示する場合は定員を1人以上に設定してください。 / 残席の表示条件は定員以下に設定してください。 | 残席表示と定員が矛盾 | 定員か表示条件を直す |

## 絶対に避けること

書き込みを伴うため、取り返しのつかない事故につながる項目をここに集約する。

- **`imageIds` / `steps` を部分的に送らない。** 送らなかった要素は消える。必ず全件送る
- **プランの更新で一部の項目だけ送らない。** 部分更新に対応していない。`getCreatorProductPlan` で現在値を読んでから全項目を送る
- **一括入金へ切り替えるときに分割回数を空にしない。** 回数は一括入金でも使われる。空で保存すると保存済みの回数が消える
- **並び替えでプランを一部だけ送らない。** 含めなかったプランは末尾に回る
- **プランの作成をやみくもに再試行しない。** 同じ内容でも別のプランが増える。先に一覧で重複を確認する
- **画像 ID を捏造しない。** ユーザーから示された ID か、`getCreatorProduct` で取得した既存の値だけを使う
- **必須項目を仮の文言で埋めない。** 決まっていなければユーザーに聞く
- **承認なしで公開状態を変えない・削除しない。** どちらもユーザーの事業に直接影響する
- **削除を「試して」確かめない。** `isDeletable: false` なら実行せずに伝える。削除は取り消せない
- **リッチテキストの内部形式を手で編集しない。** 全文置き換えか、管理画面での編集を案内する
- 生の内部 ID（`id` / `productId` / `productPlanId` / `moshServiceId` / `slug` / `imageIds` の値）を提示しない
- enum の英字値（`PUBLIC` / `MONTHLY` / `forSale` 等）をそのまま表示しない
- `publicUrl: null` を「エラー」「取得失敗」と説明しない（非公開商品の正常な値）
- `capacity: 0` を「定員 0 人」と説明しない（定員なし）
