# 商品の構造リファレンス

送信するリクエストの組み立て方と、返ってきたレスポンスの読み方。

## 商品の項目

| 項目 | 作成 | 更新 | 意味・扱い |
|---|---|---|---|
| `name` | 必須 | 任意 | 商品名（1〜100 文字）。提示の主キーにする |
| `description` | 必須 | 任意 | 商品説明。プレーンテキストでもリッチテキストの JSON 文字列でも送れる |
| `precautions` | 必須 | 任意 | サービスに関する注意事項。同上 |
| `cancellationPolicy` | 必須 | 任意 | キャンセルポリシー。同上 |
| `imageIds` | 任意 | 任意 | 商品画像の ID 一覧（最大 7 件）。**置き換え**。**提示しない** |
| `publishingStatus` | 指定不可 | 任意 | 公開ステータス（下の変換表）。作成時は常に非公開 |
| `steps` | 指定不可 | 任意 | 申し込み後の流れ。**置き換え** |
| `id` | — | — | 商品 ID。**提示しない** |
| `slug` | — | — | 公開 URL 用の識別子。**提示しない**（URL は `publicUrl` を使う） |
| `isDeletable` | — | — | 削除可能か。配下プランにサブスク購読中またはアクティブな購入者がいると `false` |
| `publicUrl` | — | — | ゲスト向け商品ページの URL。**非公開ではページが存在しないため `null`（正常）** |
| `planCount` | — | — | 紐づくプラン件数 |
| `createdAt` / `updatedAt` | — | — | 作成・更新日時 |

## 文字数の 2 つの上限

`description` / `precautions` / `cancellationPolicy` には上限が 2 つある。混同しない。

- **表示テキスト 10,000 文字** … 実際にユーザーが読む文字数。超えると拒否される
- **送信ペイロード 100,000 文字** … リッチテキストの JSON はマークアップの分だけ長くなるため、その余裕を見た上限

プレーンテキストで送る場合、実質の上限は 10,000 文字と考えてよい。

## リッチテキストの扱い

`description` / `precautions` / `cancellationPolicy` は、管理画面のエディタで編集するとリッチテキストの内部形式（JSON 文字列）で保存される。

- **読むとき**: 取得した値が JSON 形式なら、本文テキストを取り出して提示する。内部形式のまま見せない
- **書くとき**: プレーンテキストで送ってよい。既存の内部形式を保つ必要があるときは、取得した値をそのまま送り返す
- **書き換えるとき**: 内部形式を手で編集しようとしない。全文をプレーンテキストで置き換えるか、ユーザーに管理画面での編集を案内する

## 置き換えになる項目

`imageIds` と `steps` は、送った配列がそのまま新しい内容になる。**差分ではない。**

```
既存:  imageIds = ["A", "B", "C"]
送信:  imageIds = ["D"]
結果:  imageIds = ["D"]     ← A・B・C は消える
```

1 枚追加したいなら `["A", "B", "C", "D"]` を送る。既存の値は `getCreatorProduct` で取得する。

`steps` も同じ。1 ステップだけ直す場合も、変えないステップを含めた全件を送る。

## 申し込み後の流れ（`steps`）

各ステップは `orderNum` / `title` / `description` / `imageId` の 4 項目すべてが必須。`imageId` は `null` を入れられるが、**項目ごと省略することはできない**。

`orderNum` は表示順序（0 以上の整数）。**同じ値を 2 つ以上入れると拒否される。**

## enum の日本語変換表

| 項目 | 値 → 表示 |
|---|---|
| `publishingStatus` | `PUBLIC`=公開 / `LIMITED`=限定公開 / `PRIVATE`=非公開 |

## 公開の条件

`publishingStatus` を `PUBLIC` または `LIMITED` にするには、次の両方が必要。

1. **公開中のプランが 1 つ以上ある**。プランの公開状態は販売期間を反映した実効値で判定されるため、販売期間が終了したプランは公開中に数えられない
2. **事業者情報が登録済み**。これを事前に確認するツールは無い

非公開（`PRIVATE`）へ戻すときは、どちらの条件も問われない。

## 公開状態を変えたときのプランへの波及

| 変更 | 紐づくプランへの影響 |
|---|---|
| → `PRIVATE` | **すべて非公開になる**。ただし公開中の別商品も同じ内容を参照しているプランは非公開にしない |
| → `PUBLIC` / `LIMITED` | プランの公開設定は変わらない（非公開のプランは非公開のまま） |

非公開にしてから公開に戻しても、プランの公開設定は自動では戻らない。ユーザーにこれを伝える。

## 拒否されたときのメッセージ

拒否理由は返ってきたメッセージにそのまま入っている。主なものは次のとおり。**再試行せず**、内容を伝えて次の行動を案内する。

| メッセージ | 意味 | 案内すること |
|---|---|---|
| 公開されているプランがありません。プランを公開してから商品を公開してください。 | 公開中のプランが 0 件 | 管理画面でプランを公開してもらう |
| 事業者情報が登録されていないため商品を公開できません。事業者情報を登録してから公開してください。 | 事業者情報が未登録 | 管理画面で事業者情報を登録してもらう |
| 事業者情報を確認できませんでした。決済設定をご確認ください。 | 事業者情報の状態を判定できなかった | 管理画面の決済設定を確認してもらう |
| 指定された画像が見つかりません。 | 画像 ID が存在しないか、自分の画像でない | 画像 ID をユーザーに確認し直す |
| 申込後の流れの表示順が重複しています。 | `steps` の `orderNum` が重複 | 重複を解消して送り直す |
| 本文は10,000文字以内で入力してください。 | 表示テキストが上限超過 | 削る内容をユーザーと相談する |
| サブスク購読中またはサービス購入済のゲストがいるため削除できません。 | 購入者がいるため削除不可 | 削除できない旨を伝える |

## 絶対に避けること

書き込みを伴うため、取り返しのつかない事故につながる項目をここに集約する。

- **`imageIds` / `steps` を部分的に送らない。** 送らなかった要素は消える。必ず全件送る
- **画像 ID を捏造しない。** ユーザーから示された ID か、`getCreatorProduct` で取得した既存の値だけを使う
- **必須項目を仮の文言で埋めない。** 決まっていなければユーザーに聞く
- **承認なしで公開状態を変えない・削除しない。** どちらもユーザーの事業に直接影響する
- **削除を「試して」確かめない。** `isDeletable: false` なら実行せずに伝える。削除は取り消せない
- **リッチテキストの内部形式を手で編集しない。** 全文置き換えか、管理画面での編集を案内する
- 生の内部 ID（`id` / `productId` / `slug` / `imageIds` の値）を提示しない
- enum の英字値（`PUBLIC` 等）をそのまま表示しない
- `publicUrl: null` を「エラー」「取得失敗」と説明しない（非公開商品の正常な値）
