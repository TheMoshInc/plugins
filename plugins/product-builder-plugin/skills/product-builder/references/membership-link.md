# 提供コンテンツ（会員サイトの紐付け）とライセンス設定

**いつ読むか**: プランに会員サイトを紐付ける・変える・外す、予約メニューの紐付けを外す、購入したゲストが閲覧できるフォルダや閲覧期限（ライセンス）を変えるとき。SKILL.md 手順 7・8 の本体と、項目・拒否メッセージの正本。

## 手順 7. 提供コンテンツ（会員サイト）の紐付け（ユーザー承認が必須）

対象が旧サービス（商品一覧・詳細で `isLegacyService: true`）なら書き込まず、[content-schema.md](content-schema.md) の「旧サービス（isLegacyService: true）」の案内文で返す。

プランで提供する会員サイトを紐付ける・変える・外す。予約メニューは**解除だけ**できる（紐付けは管理画面を案内する）。リクエストの形は [../examples/link-membership-site.json](../examples/link-membership-site.json) を参照する。例の `membershipSiteId` はダミー値なので、取得した値に置き換えてから送る。

1. `getCreatorProductPlanOfferedContents` で現状を読む。会員サイトと予約メニューが同じ一覧に並ぶ。`isUsingLegacySite` が `true` なら、いま申込者向けサイト（旧会員サイト）を使っている。`false` のプランでは申込者向けサイトは新しく使えない（会員サイトを紐付けるか、使わないかの 2 択）
2. **すでに何か紐付いているプラン**を変える・外すなら、`getCreatorProductPlan` の `isDeletable` を見る。**申込者向けサイトを使っているプラン（`isUsingLegacySite: true`。会員サイトが紐付いていなくても）から会員サイトへ変える・「会員サイトを使わない」にする場合もこれに当たる**ので、手順 3 の承認より先に見る。`false` なら購入者がいる可能性があり、紐付けの変更・解除は拒否されうるため、このスキルでは変えない。**ツールを呼ばずに**その旨を伝える（`isDeletable` の項目名や値は書かず「購入者がいるため変更できない」とだけ言う）。`true` でも解約済みの購入者がいると拒否されることがあるので、拒否されたら理由をそのまま伝える。何も紐付いていないプランへの初回の紐付けは、購入者がいてもできる
3. **`isUsingLegacySite` が `true` なら、紐付け（または「会員サイトを使わない」）の前に「申込者向けサイトは非公開になり、元に戻せない」と伝えて承認を取る**（伝える文言と条件の正本は下の「会員サイトの紐付けリクエスト」）。`false` のプランでは申込者向けサイトの話はしない（使っていないプランで話すと、関係のない心配をさせる）
4. 紐付ける会員サイトは `getCreatorMembershipSites` の一覧から**名前で**特定する。`membershipSiteId` は**数値**。完全一致しなければ候補を提示して選んでもらう
5. 何が起きるかを伝えて承認を取る（3. の申込者向けサイトの承認は、この承認とまとめて取ってよい）。次の該当するものを必ず言葉にする
   - 別の会員サイトへ変えると、いままでの会員サイトの紐付けは外れる
   - 会員サイトを使わない設定にすると、ゲストはこのプランから会員サイトを閲覧できなくなる
6. 承認後に `postCreatorProductPlanOfferedContent` を呼ぶ。3 通りの使い分けと起きることは下の「会員サイトの紐付けリクエスト」が正本
   - **同じ会員サイトを再指定すると「変更がないためスキップしました」で成功する。** 失敗ではないので、そのまま「すでに紐付いています」と伝える
   - 会員サイトを新しく紐付けると、そのプランのライセンスが既定値（全フォルダ閲覧可・今後追加分も含む・無期限）で自動作成される。変えたいときは手順 8 へ進む
7. 会員サイトや予約メニューの紐付けを 1 件だけ外すときは `deleteCreatorProductPlanOfferedContent` を使う。対象を**タイトルで**提示し、「その提供コンテンツがゲストから見えなくなる」ことを伝えて承認を取ってから呼ぶ。申込者向けサイトの紐付けはこの方法では外せない（`postCreatorProductPlanOfferedContent` で「会員サイトを使わない」を選ぶ）
8. `getCreatorProductPlanOfferedContents` で読み戻し、紐付いている会員サイト名・予約メニュー名を提示する

## 手順 8. ライセンス設定（閲覧できるフォルダ・閲覧期限）（フォルダを外すときはユーザー承認が必須）

会員サイトが紐付いたプランで、購入したゲストが閲覧できるフォルダと期間を決める。`membershipSiteId` は手順 7 の一覧で得た**数値**を使う。リクエストの形は [../examples/update-license-setting.json](../examples/update-license-setting.json) を参照する（`viewableFolderIds` はダミー値。取得した `folders` の ID に置き換える）。

1. `getCreatorMembershipSiteProductPlanLicenseSetting` で現在値を読む。`folders` に会員サイトの全フォルダが**フォルダ名と閲覧可否付き**で返るので、フォルダはこの名前で提示する
2. 変更内容を組み立てる。`putCreatorMembershipSiteProductPlanLicenseSetting` は `viewableFolderIds` / `isNewFoldersIncluded` / `accessDurationDays` / `accessStartsAt` / `accessEndsAt` の**5 項目すべてが必須で、送った内容に置き換わる**。1 つのフォルダを足すときも、閲覧可能にするフォルダの ID を全件送る。期間を変えないときも、読んだ期間の 3 項目をそのまま送る
3. 会員サイトで**閲覧順の固定**（`getCreatorMembershipSite` の `isFixedViewingOrder`）が有効なら、全フォルダを閲覧可能にし `isNewFoldersIncluded: true` にしないと拒否される。フォルダを分けたい依頼なら、先に閲覧順の固定を外す必要があることを伝える（サイト設定の変更は `membership-site-builder` スキル）。閲覧順の固定を外すとゲストの閲覧完了状態が消えて元に戻せないことも併せて伝える
4. いま閲覧可能なフォルダを外すとき、手順 1 で読んだ `hasLicensedGuests` が `true` なら、**そのフォルダを購入済みのゲストも見られなくなる**ことを外すフォルダ名とともに伝えて承認を取る。`false` でも公開中・限定公開のプランなら確認を取る（条件の正本は下の「ライセンス設定の項目」）。伝えるときは項目名を出さず「このプランで閲覧中のゲストがいます」と言う。購入者の有無を `isDeletable` で推し量らない
5. 閲覧できる期間は「無期限」「購入から N 日間」「指定日（開始日時〜終了日時）」の 3 通りから 1 つ選ぶ。`accessDurationDays` と日時（`accessStartsAt` / `accessEndsAt`）は同時に指定できず、拒否される（組み合わせは下の「ライセンス設定の項目」）。使わない側は `null` を送る（省略はできない）
   - 購入から N 日間: `accessDurationDays` に日数（範囲は下の「ライセンス設定の項目」）、日時は 2 つとも `null`
   - 指定日: `accessDurationDays` を `null` にし、`accessStartsAt` / `accessEndsAt` を `2026-10-01T10:00:00+09:00` のようにタイムゾーンオフセット付きで送る。片方だけでもよい。両方入れるなら終了を開始より後にする
   - サブスクリプションのプランで終了日時を入れると、課金が続いていても終了日時以降は閲覧できなくなる。送る前にそれを伝えて承認を取る
6. 送信後に同じ取得ツールで読み戻し、閲覧できるフォルダ名・今後追加分の扱い・閲覧期限を提示する

ライセンス設定で「見つからない」旨のエラーが返ったら、会員サイトが紐付いていないプランを指定していないか、先に提供コンテンツの一覧で紐付きを確かめる。

## 使用するツール

パスの `productId` / `productPlanId` / `offeredContentId` はいずれも**数値文字列**。ライセンス設定のパスは `membershipSiteId`（**数値**。提供コンテンツ一覧の値）/ `productId` / `planId` の 3 つで、**プラン ID のパラメータ名だけ `planId`**。送る項目の必須・制約は下の各節が正本。

| ツール | 用途 | 注意 |
|---|---|---|
| `getCreatorProductPlanOfferedContents` | 提供コンテンツの一覧 | 応答は `{ offeredContents, totalCount, isUsingLegacySite }`。会員サイトと予約メニューが**同じ配列**に並ぶ。ページングされない。紐付けが無ければ空配列 |
| `postCreatorProductPlanOfferedContent` | 会員サイトの紐付け・変更・「使わない」 | body は下の「会員サイトの紐付けリクエスト」。自分の会員サイトでない `membershipSiteId` は「見つからない」旨のエラー |
| `deleteCreatorProductPlanOfferedContent` | 提供コンテンツを 1 件外す | `offeredContentId` は一覧の `id`。会員サイトも予約メニューも同じツールで外す。例外として、**削除済み（アーカイブ済み）の予約メニュー**の紐付けは、予約の有無・購入者の有無にかかわらず外せる |
| `getCreatorMembershipSites` | 会員サイト名から `membershipSiteId` を特定 | `id` / `name` / `isPublished` が返る。`limit`（既定 20）/ `offset` でページングされ、`totalCount` が取得済み件数より多ければ続きを取得する |
| `getCreatorMembershipSite` | 閲覧順の固定（`isFixedViewingOrder`）の確認 | — |
| `getCreatorMembershipSiteProductPlanLicenseSetting` | ライセンスの現在値 | 応答は `{ folders: [{ id, name, isViewable }], isNewFoldersIncluded, accessDurationDays, accessStartsAt, accessEndsAt, hasLicensedGuests }`。会員サイトが紐付いていないプラン・自分の会員サイトでない `membershipSiteId` は「見つからない」旨のエラー |
| `putCreatorMembershipSiteProductPlanLicenseSetting` | ライセンスの更新（全置換） | 項目は下の「ライセンス設定の項目」。日時にタイムゾーンオフセットが無いと形式エラーで拒否される |

## 提供コンテンツの項目

`getCreatorProductPlanOfferedContents` が返す `offeredContents[]` の 1 件。会員サイトと予約メニューが同じ形で並び、**`calendarBookingItem` が `null` なら会員サイト、入っていれば予約メニュー**。

| 項目 | 意味・扱い |
|---|---|
| `id` | 提供コンテンツ ID。解除（`deleteCreatorProductPlanOfferedContent`）で使う。**提示しない** |
| `title` | 会員サイト名または予約メニュー名。提示の主キーにする。名前が空のときは `(未設定)` |
| `description` | 説明。会員サイト・予約メニューでは空文字が返る。申込者向けサイト（旧会員サイト）では文章が入っていることがある |
| `iconImageUrl` | アイキャッチ画像の URL。無ければ空文字 |
| `membershipSiteId` | 紐付いている会員サイトの ID（数値）。**ライセンス設定のパスに使う**。申込者向けサイト（旧会員サイト）と予約メニューでは `null`。**提示しない** |
| `isPublished` | 会員サイトの公開状態。申込者向けサイトと予約メニューでは常に `false` なので、「非公開」と説明しない |
| `calendarBookingItem` | 予約メニュー固有の項目（下表）。会員サイトでは `null` |
| `createdAt` / `updatedAt` | 作成・更新日時 |

`calendarBookingItem` の中身:

| 項目 | 意味・扱い |
|---|---|
| `calendarBookingItemId` | 予約メニュー ID。**提示しない** |
| `slotType` | 枠種別（[content-schema.md](content-schema.md) の「enum の日本語変換表」） |
| `publishStatus` | 予約メニューの公開状態（同上） |
| `acceptStartAt` / `acceptEndAt` | 予約の受付開始・終了日時。`null` は常時受付 |

一覧と一緒に返る `isUsingLegacySite` が `true` なら、申込者向けサイト（旧会員サイト）を使っている。

## 会員サイトの紐付けリクエスト

`postCreatorProductPlanOfferedContent` は `useLegacyMembershipSite` と `membershipSiteId` の**両方が必須**で、組み合わせで操作が決まる。`membershipSiteId` は省略できず、使わないときは `null` を送る。

| 操作 | `useLegacyMembershipSite` | `membershipSiteId` | 起きること |
|---|---|---|---|
| 会員サイトを紐付ける（変更も同じ） | `false` | 会員サイト ID（数値） | いままでの会員サイト・申込者向けサイトの紐付けは外れ、指定した会員サイトに置き換わる。ライセンスが自動作成される（下表） |
| 申込者向けサイト（旧会員サイト）を使い続ける | `true` | `null` | **いま申込者向けサイトが紐付いているプラン（`isUsingLegacySite: true`）でだけ受け付ける。** 紐付いていないプランでは拒否される（申込者向けサイトの新規利用は停止している）。会員サイトが紐付いていれば、その紐付けは外れずに残る |
| 会員サイトを使わない | `false` | `null` | 申込者向けサイトを含む会員サイトの紐付けをすべて外す |

**申込者向けサイトを使っているプラン（`isUsingLegacySite: true`）への影響**: 会員サイトを紐付ける・「会員サイトを使わない」にすると、申込者向けサイトは**非公開になり、このプランの紐付けも外れる**。外れたあとは `true` を送っても拒否されるため、**このプランで申込者向けサイトに戻すことは二度とできない**。承認を取るときに「申込者向けサイトは非公開になり、今後このプランでは使えなくなります（元に戻せません）」と伝える。**戻せないのは申込者向けサイトだけ**で、そのあと別の会員サイトへ変える・「会員サイトを使わない」にすることは購入者がいなければできる。「他の紐付け方法に変更できなくなる」のように、会員サイトの変更まで不可とは言わない。`isUsingLegacySite: false` のプランでは申込者向けサイトへの影響は無いので、この説明は要らない（初回の紐付けで「申込者向けサイトが非公開になる」とは言わない）。

- `true` と会員サイト ID を同時に送ると拒否される
- **同じ会員サイトを再指定すると「変更がないためスキップしました。」で成功する**（失敗ではない）
- 購入者がいるプランでは、紐付いている会員サイトの変更・申込者向けサイトから会員サイトへの変更・「使わない」への切り替えが拒否される。`getCreatorProductPlan` の `isDeletable: false` なら拒否されうるため、このスキルでは変えない（呼ばずに伝える）。何も紐付いていないプランへの初回の紐付けは、購入者がいてもできる
- 予約メニューの紐付けは、このリクエストでは変わらない
- 1 件だけ外す `deleteCreatorProductPlanOfferedContent` は申込者向けサイトの紐付けを外せず、申込者向けサイトの公開状態も変えない

会員サイトを新しく紐付けたとき（別の会員サイトへ変えたときも）、そのプランのライセンスは次の既定値で自動作成される。変えたければ `putCreatorMembershipSiteProductPlanLicenseSetting` で更新する。

| 項目 | 自動作成時の値 |
|---|---|
| 閲覧できるフォルダ | 紐付けた時点の全フォルダ |
| `isNewFoldersIncluded` | `true`（今後追加されるフォルダも閲覧可） |
| `accessDurationDays` | `null`（無期限） |
| `accessStartsAt` / `accessEndsAt` | `null`（日時の制限なし） |

## ライセンス設定の項目

`getCreatorMembershipSiteProductPlanLicenseSetting` / `putCreatorMembershipSiteProductPlanLicenseSetting`。パスは `membershipSiteId`（**数値**。提供コンテンツ一覧の値）/ `productId` / `planId`。

| 項目 | 取得 | 更新 | 意味・扱い |
|---|---|---|---|
| `folders[]` | ○ | — | 会員サイトの全フォルダ。`id`（**提示しない**）/ `name`（提示に使う）/ `isViewable`（このプランで閲覧できるか） |
| `viewableFolderIds` | — | 必須 | 閲覧可能にするフォルダの ID（数値）の配列。**送った内容に置き換わる**。重複不可。会員サイトに無い ID は拒否 |
| `isNewFoldersIncluded` | ○ | 必須 | 今後追加されるフォルダも自動で閲覧可能にするか |
| `accessDurationDays` | ○ | 必須 | 閲覧期限（購入からの日数）。**1〜1100**。使わないときは `null`。**省略不可** |
| `accessStartsAt` | ○ | 必須 | 閲覧開始日時。この日時ちょうどから閲覧できる。`null` は開始の制限なし。タイムゾーンオフセット付き。**省略不可** |
| `accessEndsAt` | ○ | 必須 | 閲覧終了日時。この日時ちょうどで閲覧できなくなる。`null` は終了の制限なし。タイムゾーンオフセット付き。**省略不可** |
| `hasLicensedGuests` | ○ | — | このライセンスで閲覧できるゲストがいるか。`true` なら、閲覧可能なフォルダを外すと購入済みのゲストもそのフォルダを見られなくなる。BAN されたライセンス・期限切れのライセンスは数えず、決済失敗で一時停止中のライセンスは数える。**提示しない**（「閲覧中のゲストがいる」と言い換える） |

閲覧できる期間は管理画面の 3 択（無期限 / 期間指定 / 指定日）と同じく、次のどれか 1 つにする。

| 管理画面の選択肢 | `accessDurationDays` | `accessStartsAt` | `accessEndsAt` |
|---|---|---|---|
| 無期限 | `null` | `null` | `null` |
| 期間指定（プラン購入から N 日間） | 日数（範囲は上表） | `null` | `null` |
| 指定日 | `null` | 日時 または `null` | 日時 または `null`（両方入れるなら開始より後） |

- 日数と日時は同時に指定できない（拒否される）
- 過去の日時も受け付ける。開始日時より前にゲストが開くと「まだ閲覧開始前です」と表示される
- 日時の片方だけも指定できる（開始だけなら「◯◯ から」、終了だけなら「◯◯ まで」）
- サブスクリプションのプランに終了日時を入れると、課金が続いていても終了日時以降は閲覧できなくなる

更新の組み立ては、取得した `folders` のうち `isViewable: true` の `id` を土台にして、足す・外すを反映する。

```
取得:  folders = [A(可), B(可), C(不可)]
希望:  C も見せたい
送信:  viewableFolderIds = [A, B, C]     ← [C] だけ送ると A・B が見られなくなる
```

**閲覧順の固定が有効な会員サイト**（`getCreatorMembershipSite` の `isFixedViewingOrder: true`）では、全フォルダを閲覧可能にし `isNewFoldersIncluded: true` にした設定しか保存できない。フォルダを分ける依頼には、先に閲覧順の固定を外す必要があることを伝える。閲覧順の固定を外すとゲストの閲覧完了状態が消えて元に戻せないことも併せて伝える。

**フォルダを外すときの承認**: いま閲覧可能なフォルダを外すとき、取得した `hasLicensedGuests` が `true` なら、そのフォルダを購入済みのゲストも見られなくなる。外すフォルダを名前で示し、影響を伝えて承認を取ってから送る。`false` でも公開中・限定公開のプラン（`publishingStatus: PUBLIC` / `LIMITED`）なら、これから購入するゲストに効くので、外すフォルダを名前で示して確認を取る。非公開かつ `false` なら確認は変更内容の提示だけでよい。

## 拒否されたときのメッセージ（提供コンテンツ・ライセンス）

**再試行せず**、内容を伝えて次の行動を案内する。

| メッセージ | 意味 | 案内すること |
