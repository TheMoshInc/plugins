# MOSH コンタクト名簿（LINE友だち / メール購読者）

## Overview

MCP ツールで、MOSH クリエイターの**コンタクトそのもの**と**コンタクトタグ**を扱う。できるのは「探す・数える・1件を詳しく見る・削除する・タグを作る/名前を変える/付ける/外す・メールアドレスをCSVで取り込み始める」。コンタクトを1件ずつ新規作成すること、タグ自体を削除することはできない。

**このドメインの書き込みには取り消せない副作用がある。** 削除は復元できない（ツール名は `patch...` だが実質は削除。LINE は表示名とプロフィール画像そのものが消える）。タグの新規付与は、タグ付与をトリガーにしたワークフローを起動し、配信まで進むと取り消せない。**どの操作で人の承認を取るかは「承認の判定表」だけで決める。**

> **ツール名表記について**: 本スキル内では MCP ツールを OpenAPI の `operationId`（例: `postCreatorContactsLineSearch`）で参照する。MCP クライアントが実際に提示するツール名にはサーバー識別子のプレフィックスが付くが、その形はユーザー環境により異なるため、本スキルでは付けない。

## When to use

- コンタクトを探したい・条件に合う人が何人いるか数えたいとき（「タグAの友だち何人？」「配信対象は何件？」）
- 1件のコンタクトの登録日・受け取った特典・タグ・流入経路・表示中リッチメニューを確認したいとき
- コンタクトを削除したいとき（LINE友だち / メール購読者）
- コンタクトに今すぐ手動でタグを付けたい・外したいとき（名指しでも、「タグAの人全員」のような条件でも）。タグの作成・名前変更も含む
- メールアドレスの一覧を CSV で一括登録したいとき

## When NOT to use

- メルマガ・LINE一斉配信を作る／予約する／履歴を見る → `contact-broadcast` スキル。本スキルは配信そのものには踏み込まない（配信対象が何人いるかを**数えるだけ**なら本スキル）
- 「申し込んだら自動でタグを付ける」「タグAが付いたら3日後にタグBを付ける」など、**条件を満たしたときに自動で**タグを付け外しする仕組み、ステップ配信、流入経路の作成 → `workflow-builder` スキル（ワークフローの `ADD_CONTACT_TAG` / `REMOVE_CONTACT_TAG` ステージ）。今いる人への手動・一括の付け外しは本スキル
- サービスを購入した「顧客（ゲスト）」の検索・詳細・申込履歴、**顧客タグ**の作成・付け外し → `customer-manager` スキル（`*Customer*` 系ツール）。顧客タグはコンタクトタグとは別物で、id も混用できない。コンタクト（LINE友だち・メール購読者というマーケティングリスト）とは別概念なので、どちらの話か曖昧なときは実行前にユーザーに確認する
- リッチメニューの内容編集・デフォルト設定 → `line-rich-menu` スキル（本スキルはリッチメニューを**検索条件と表示項目として読むだけ**）
- LP の作成・編集 → `lp-builder` スキル

## ツールの選び方

コンタクト本体:

| やりたいこと | メール | LINE |
|---|---|---|
| 探す・数える（一覧） | `postCreatorContactsEmailSearch` | `postCreatorContactsLineSearch` |
| 1件を詳しく見る（特典を全件） | `getCreatorContactEmail` | `getCreatorContactLine` |
| 削除する | `patchCreatorContactsEmail` | `patchCreatorContactsLine` |
| CSV で一括登録を開始する | `postCreatorContactsEmailCsvImportJobs` | 提供なし（下の「MCP からはできないこと」） |

コンタクトタグ（タグはメール・LINE 共通。1人のコンタクトに付くと両方の一覧・配信条件に反映される）:

| やりたいこと | ツール |
|---|---|
| タグを作る（同名があれば既存の id が返る） | `postCreatorContactTags` |
| タグの名前を変える | `patchCreatorContactTag` |
| 名指しした人に付ける／外す | `postCreatorContactTagContacts` / `deleteCreatorContactTagContacts` |
| 検索条件に合う全員に付ける／外す | メール: `postCreatorContactTagContactsEmailByCondition` / `deleteCreatorContactTagContactsEmailByCondition`、LINE: `postCreatorContactTagContactsLineByCondition` / `deleteCreatorContactTagContactsLineByCondition` |

条件に使う ID は必ず次のツールで解決する（推測・創作は禁止）: タグ `getCreatorContactTags` / 流入経路 `getCreatorScenariosInflowActions` / リッチメニュー `getCreatorLineRichMenus` / LINE公式アカウント `getCreatorLineChannels`。

ルーティング上の注意（パラメータ・エラーの詳細は [references/mcp-tools.md](references/mcp-tools.md) が正本）:

- **ID は検索でしか手に入らない。** 詳細取得・削除・名指しのタグ付け外しは ID 指定のみ。名前やメールアドレスしか分かっていないときは、必ず先に検索する
- **メール・LINE・`contactId` は3つとも独立した ID 体系で、同じ数値が別の相手を指しうる。取り違えても 404 になるとは限らず、別人に当たる（無言の失敗）。**
  - 詳細取得・削除に渡すのは検索結果の **`id`**（同じ系統の検索から取ったものだけ）
  - 名指しのタグ付け外しに渡すのは検索結果の **`contactId`**（`id` ではない）。**詳細取得・削除と逆になる**ので、渡す直前に毎回確かめる
- **タグ ID はコンタクトタグ（`getCreatorContactTags`）の id だけを使う。** 顧客タグ（`getCreatorCustomerTags`）の id を渡しても 404 になるとは限らず、同じ数値の別のコンタクトタグが書き換わる
- **名指しか条件か**: 数人を名指しされたら ID 指定、「タグAの人全員」「ブロックしていない人全員」のように条件で表せる大人数なら検索条件一括（ByCondition）を使う
- **一覧と詳細の違いは特典だけ。** 一覧は最初に取得した特典1件、詳細は取得済みの特典すべてを返す。特典の全件が要らなければ詳細取得は呼ばない
- **メール検索は氏名で引けない。** `postCreatorContactsEmailSearch` に「名前」を絞り込む項目はそもそも無く、`keyword` もメールアドレスにしか当たらない。名前しか分かっていない依頼は、メールアドレスの提供を求めるか、LINE側の話でないか確認する。存在しない「名前」条件をでっち上げて検索したことにしない
- **「〜じゃない人」「〜が付いていない人」は `ne` で1回の検索で表現できる。全体件数から引き算しない。** `inflowAction`（流入経路） / `richMenu` は `{ id: { value: <id>, operator: "eq" | "ne" } }`、`tag` は同じ形の条件を `id` 配列に並べる形で、`ne` は「別の値を持つ人」ではなく**その条件の記録・設定が一切無い人も含む**（例: `richMenu` の `ne` はリッチメニューが何も紐付いていない人も含む）。**`inflowAction` と `richMenu` は `filters` 直下の独立したキー**（`line` オブジェクトの中には無い）。構造の正本は [references/search-schema.md](references/search-schema.md)

## Workflow

基本フロー: 対象・条件の確認 → 検索 → 結果の提示 → **（書き込み操作なら）ユーザーの承認** → 実行 → 結果の報告。読み取りだけなら承認は不要。

### 承認の判定表（唯一の分岐条件）

**この表だけが「実行前に止まるか」を決める。** 他の節でこの条件を再定義しない。

| 操作 | 判定 | 根拠 |
|---|---|---|
| 削除（`patchCreatorContactsEmail` / `patchCreatorContactsLine`、`active: false`） | **必ず停止し、対象を提示して承認を得る** | 復元できない（API では解除不可・管理画面にも導線なし）。ツール定義も「対象を提示し、同意を得てから実行」を要求している |
| 非表示の解除（`active: true`） | **実行しない** | MCP の認証（APIトークン）では拒否され、管理画面にも復元の導線が無い |
| タグの付与（名指し・条件一括とも） | **必ず停止し、タグ名・対象件数・ワークフローが起動しうることを提示して承認を得る** | 新規付与でタグ付与トリガーのワークフローが起動し、配信まで進むと取り消せない。ツール定義も合意を要求している |
| タグの解除（名指し・条件一括とも） | **必ず停止し、タグ名・対象件数を提示して承認を得る** | ツール定義が合意を要求。解除を取り消す（再付与する）と新規付与扱いになりワークフローが起動する |
| タグの名前変更（`patchCreatorContactTag`） | **必ず停止し、変更前後の名前を提示して承認を得る** | タグを参照しているワークフロー・配信条件すべてに新しい名前が反映される。ツール定義も合意を要求している |
| タグの作成（`postCreatorContactTags`） | 停止しない | 同名があれば既存の id を返すだけの冪等操作で、作るだけではコンタクトに影響しない（作った後の付与は上の「付与」行に従う） |
| CSV インポート（`postCreatorContactsEmailCsvImportJobs` 以降の一連） | **ジョブを作る前に1回停止し、ファイルと取り込み内容を提示して承認を得る。承認後はジョブ作成 → アップロードを止めずに通す** | 取り込みは自動で始まり、取り消す手段が MCP にない。一方でアップロード先URLは15分で失効するため途中で止められない |
| 検索・詳細取得・タグ一覧（`post...Search` / `getCreatorContact*` / `getCreatorContactTags`） | 停止しない | 読み取り |

**依頼文がどれだけ具体的でも（「◯◯さんを今すぐ削除して」「全員にタグ付けといて」等）、上表で「承認」となっている操作は承認なしに実行しない。**

### 1. 依頼内容の確認

次を把握する。曖昧なまま検索・書き込みに進まない。

- **メールか LINE か**（「コンタクト」「友だち」「リスト」はどちらにも取れる）。判断できない依頼では両方を検索して件数を並べて示すのは可。ただし**書き込みは対象を確定してからでないと実行しない**
- **顧客（購入者）の話ではないか**（「お客さん一覧」「購入者を探して」「顧客タグ」は別ドメイン。When NOT to use 参照）
- 削除・タグの付け外しなら、**対象が ID または検索条件で特定できるか**。「もう使ってない人を消して」のような依頼は対象を確定するまで進まない
- タグ操作なら、**どのタグか・付けるか外すか・名指しか条件か**
- LINE で複数の LINE公式アカウントを運用している場合、どのアカウントの話か（未指定なら全アカウント横断で検索される）

### 2. 検索して対象を特定する

[references/search-schema.md](references/search-schema.md) を読み、リクエストを組み立てる（`filters` は使わないキーも含めて**全キー必須**で、未使用は `null`。この構造を毎回そこで確認する）。

- 件数だけ知りたいときは `limit: 1` で呼び、`filteredCount` を読む（全件を取得しない）
- 「配信対象は何人か」を数えるときは、メールなら `subscribed: true`、LINE なら `blocked: false` を条件に入れる。入れないと届かない相手を含んだ数になる
- 既定では削除済み（非表示）は結果に含まれない
- 100件を超える対象は `offset` を進めて取得する。ページングを省いて「全部で N 件」と言わない
- **タグの付け外しの対象を特定するときは、[references/mcp-tools.md](references/mcp-tools.md) の「コンタクトタグ操作」を必ず読む**（タグ名の解決、名指しで集める `contactId`、条件一括の前に同じ条件で数える手順と件数の読み方がそこにある）。条件一括で対象が0件なら「該当なし」と伝えて実行しない

### 3. 結果をユーザーに提示する

「ユーザーへの提示規約」に従って、件数と代表例を自然文・表で示す。書き込みの依頼では、**その操作の対象そのもの**（何件・誰か・何が起きるか）を提示する。

### 4. 承認を取る（書き込み操作のみ）

判定表で「承認」となる操作は、ここで必ず止まる。

- **削除**: 何件・誰か（LINE は表示名、メールはメールアドレス）／**復元できないこと**（LINE は表示名とプロフィール画像が消える）／削除後は検索結果に出ず配信も届かなくなること（メールアドレス自体は保持される）
- **タグの付与**: タグ名／新しく付く人数（数え方は mcp-tools.md）／**そのタグをきっかけに動くワークフローがあれば対象者に配信が始まり、送られた分は取り消せないこと**／LINE とメールの両方を持つ人は両方の一覧に反映されること
- **タグの解除**: タグ名／外れる人数／コンタクト自体は消えず、他のタグも残ること
- **タグの名前変更**: 変更前と変更後の名前／そのタグを使っているワークフローや配信の条件にも新しい名前で反映されること
- **CSV インポート**: [references/csv-import.md](references/csv-import.md) の「承認時に伝えること」に従う

### 5. 実行して結果を報告する

- 削除は ID の明示指定のみ・1回あたり最大100件。101件以上は分割して実行し、**分割の各回に対する承認は Step 4 の1回にまとめてよい**（対象一式を提示済みのため）
- 削除・タグの付け外しは成功しても「何件変わったか」は返らない。件数を API の返り値から作らない（下表）
- 承認後に対象・タグ・条件が変わったら、承認を取り直す

### 6. 完了を断定してよい操作／してはいけない操作

| 操作 | 報告の仕方 |
|---|---|
| 削除 | 断定してよい（成功応答＝反映済み）。件数は**こちらが渡した ID の件数** |
| タグの付け外し・名前変更 | 断定してよい（成功応答＝反映済み）。ただし付け外しの件数は「事前に数えた対象 N 件」として伝え、「N 人に新しく付けました」とは言わない（既に付いていた人・付いていなかった人はそのまま）。正確な件数が要るなら、実行後にそのタグで再検索した `filteredCount` を根拠にする |
| CSV インポート | **断定しない。** 「取り込みを開始しました。取り込み結果（件数・エラー行）は MOSH に登録されているメールアドレス宛の通知でご確認ください」と伝える。MCP には進捗・結果を確認するツールが無い |

## MCP からはできないこと

依頼を受けたら、できない旨と代替手段を伝える。**できるふりをして別のツールで代用しない。**

| 依頼 | 実際 | 案内 |
|---|---|---|
| 削除の取り消し・復元 | API 権限上できず、管理画面にも復元の導線がない | 削除前に必ず伝える（Step 4）。削除後の依頼には復元不可であることを伝える |
| 「ブロックした人を全部削除」など条件での一括削除 | 条件指定の一括削除ツールは MCP に公開されていない | 検索 → ID を提示 → 承認 → ID 指定で分割実行（Step 5） |
| タグ自体の削除 | MCP に公開されていない | MOSH 管理画面のタグ管理で削除するよう案内する。全員から外す・名前を変えるで「削除したこと」にしない |
| タグを使っているワークフロー・配信の確認 | MCP に公開されていない | 管理画面のタグ管理で確認するよう案内する |
| LINE友だちの一括取り込み・LINE公式アカウントとの友だち同期 | MCP に公開されていない（CSV 取り込みはメールのみ） | MOSH 管理画面での操作を案内 |
| CSV インポートの進捗・結果・取り込み件数の確認 | MCP に公開されていない | クリエイター宛の通知メールで確認するよう案内 |
| コンタクトを1件ずつ手で追加 | 作成ツールが無い | メールは CSV インポート、LINE は友だち追加・管理画面 |
| 購読解除された人を配信対象に戻す | CSV で再インポートしても購読解除は維持される | 本人による再購読が必要であることを伝える |

## ユーザーへの提示規約

- **個人情報を目的外に出さない。** メールアドレス・LINE表示名・プロフィール画像URLは、依頼された用途に必要な範囲だけ提示する。件数を聞かれただけなら件数を答え、一覧を貼らない。依頼と無関係なファイルへの転記・保存はしない
- **内部表現を見せない。** JSON、`filters` のキー名、HTTPステータスコード、`operationId` をそのまま出さない。エラーは状況を平易な言葉で伝える（例外: タグの名前変更が拒否されたときは、ツール定義の指示どおり応答の案内文をそのまま伝えてよい）。ID は削除対象の確認など、ユーザーが指し示す必要があるときだけ「コンタクトID: 123」の形で添える
- **ID を創作しない・使い回さない。** コンタクトID・タグID・流入経路ID・リッチメニューID・LINE公式アカウントIDは、必ず対応する取得ツールの返り値から取る。ユーザーや会話の前半で出てきた ID を書き込みに使う前には、**同じ系統の検索・詳細取得で、その ID が誰を指すかを確認する**
- **数を推測しない。** 件数は `filteredCount` を根拠に答え、取得できていない範囲を「たぶん◯件」と補わない。条件に合う人が0件のときはエラーではなく「該当なし」として伝える
- **どの条件で数えたかを添える。** 「配信対象（購読中）で 120名」のように、絞り込み条件を1行で明示する（同じ「友だち数」でもブロック済みを含むかで数が変わるため）

上のセクションでカバー済みの事項は再掲しない。ここは他セクション・references でカバーされない落とし穴のみ（追記前に既存セクションでカバーできないか確認し、できるならそちらを強化する）。

| NG | OK |
|---|---|
| `patch...`（`patchCreatorContactsEmail` / `Line`）を「更新」と解釈し、名前やタグの変更に使おうとする | このツールで変えられるのは表示状態だけで、実質は削除。タグはタグ用のツールで付け外しする |
| 検索結果の `totalCount` を「条件に合う件数」として報告する | 条件に合うのは `filteredCount`。`totalCount` は絞り込み前の有効件数（[references/search-schema.md](references/search-schema.md)） |
| タグを2つ指定して「どちらかを持つ人」を数える | タグ条件の複数指定は AND（すべて満たす人）。OR が必要なら1タグずつ数える |
| LINE の「友だち数」を、ブロック済みを含めたまま報告する | ブロック状態は結果に含まれる。配信文脈なら `blocked: false` で絞ってから数える |
| メールコンタクト一覧の `name` を本人が入力した氏名として扱う | `name` は同一コンタクトの LINE プロフィール名で、無ければ空文字。氏名として断定しない |
| 「タグAとタグBをまとめて」を、Aの名前をBに変えて実現しようとする | 同名への変更は拒否される。Aが付いている人にBを付与し（承認が要る）、Aは管理画面で削除してもらう |

## エラーが返ったとき

コード別の意味は [references/mcp-tools.md](references/mcp-tools.md) が正本。ここでは状況別の対処だけを示す。

| 状況 | 対処 |
|---|---|
| 詳細取得・削除で「見つからない」 | ID の取り違え（メール↔LINE、`id` と `contactId`）か、既に削除済み。検索で対象を引き直してから再実行する。ユーザーには「該当のコンタクトが見つかりませんでした」と伝える |
| 詳細取得の結果が、ユーザーの言う相手と一致しない | ID 体系の取り違えで別人を引いている可能性が高い（エラーにならない）。**書き込みには進まず**、名前・メールアドレス・登録日で検索し直して対象を確定する |
| 削除で「すでに非表示」と返る | 対象は既に削除済み。再実行せず、その旨を伝える |
| 削除が権限エラーで拒否される | `active: true`（解除）を渡していないか確認する。解除は MCP からはできない |
| タグの付け外しで「見つからない」 | タグ ID が顧客タグ・存在しない、または `contactIds` に1件でも不正な値（`id` を渡した等）がある。**全件が反映されていない**（部分反映なし）。タグを引き直し、検索で `contactId` を集め直してから再実行する（承認済みの対象と同じなら承認は取り直さなくてよい） |
| タグの名前変更が「同じ名前のタグがある」で拒否される | 返ってきた案内文をそのまま伝え（提示規約の例外）、別の名前にするか確認する（よくあるミスの「まとめて」も参照） |
| 検索・条件一括がリクエスト不正で返る | `filters` のキー欠落（全キー必須）、`limit` が範囲外、タグ条件の同じ id の重複（`eq` と `ne` の同時指定を含む）・6件以上の可能性が高い。[references/search-schema.md](references/search-schema.md) と mcp-tools.md で構造を確認して組み直す |
| CSV アップロードが失効した | アップロード先URLの有効期限は15分。ジョブ作成からやり直す（[references/csv-import.md](references/csv-import.md)） |
