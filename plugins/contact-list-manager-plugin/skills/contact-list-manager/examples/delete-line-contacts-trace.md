# 削除依頼の完全トレース（LINEコンタクト）

発話 → 検索 → 提示 → 承認 → 実行 → 報告。削除フローの言い回しと停止位置の見本。ID・件数は架空。

---

**ユーザー**: テスト用に追加した「テスト太郎」と「テスト花子」のLINE友だち、消しといて。

**アシスタント（内部）**: 削除は承認が要る操作。まず対象を検索して確定する。

`postCreatorContactsLineSearch`:

```json
{
  "keyword": "テスト",
  "limit": 20,
  "offset": 0,
  "sort": "createdAtDesc",
  "filters": {
    "contact": { "active": { "value": true, "operator": "eq" }, "blocked": null },
    "line": { "createdAt": null, "name": null },
    "tag": null,
    "inflowAction": null,
    "richMenu": null
  }
}
```

→ `filteredCount: 3`。「テスト太郎」（id 811）「テスト花子」（id 812）「テストキッチン中村」（id 655）。

**アシスタント（ユーザーへ）**:

> 「テスト」で3件見つかりました。ご依頼の2件はこちらです。
>
> | 名前 | 登録日 | コンタクトID |
> |---|---|---|
> | テスト太郎 | 2026-09-01 | 811 |
> | テスト花子 | 2026-09-01 | 812 |
>
> ほかに「テストキッチン中村」さん（2026-03-12 登録）もヒットしましたが、実在のお客様に見えるため対象から外しています。
>
> この2件を削除してよろしいですか？ 削除すると**元に戻せません**。LINE の表示名とプロフィール画像は消え、あとから復元できません。検索結果にも出なくなり、配信も届かなくなります。

**ユーザー**: OK、その2件でお願い。

**アシスタント（内部）**: `patchCreatorContactsLine`:

```json
{ "ids": [811, 812], "active": false }
```

→ 成功。返り値に件数は含まれないため、報告件数は渡した ID の数（2件）を使う。

**アシスタント（ユーザーへ）**:

> 2件（テスト太郎さん・テスト花子さん）を削除しました。今後は検索結果と配信対象に含まれません。

---

## この例で守っていること

- 依頼が具体的でも、検索で対象を確定してから提示・承認を挟んでいる
- ヒットした中の**判断が割れる1件**を勝手に削除せず、除外した理由を明示している
- 復元不可・LINE の表示名/画像が消えることを、承認をもらう前に伝えている
- 内部表現（JSON・`filters`・ツール名）をユーザーに見せず、ID は指し示すために必要な列としてだけ出している
- 報告件数を API の返り値から作らず、渡した ID の件数にしている

## メールコンタクトの場合の違い

- 検索の `keyword` は**メールアドレスにしか当たらない**（氏名では引けない）ので、名前で指定されたら別の手がかり（登録日・タグ・特典）を聞く
- 承認時の説明は「表示名と画像が消える」ではなく「メールアドレスは残るが、検索結果と配信対象から外れる」に置き換える
