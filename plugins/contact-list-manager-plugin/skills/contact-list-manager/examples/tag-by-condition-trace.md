# 検索条件で一括タグ付与の完全トレース（LINEコンタクト）

発話 → タグ解決 → 件数確認（全体・新規） → 承認 → 一括付与 → 報告。条件一括の数え方と停止位置の見本。ID・件数は架空。

---

**ユーザー**: 「体験申込」タグが付いてるLINE友だち全員に、「フォロー対象」タグも付けておいて。

**アシスタント（内部）**: タグ付与は承認が要る操作。まずタグ名を id に解決する（顧客タグではなくコンタクトタグ）。

`getCreatorContactTags`（`keyword: "体験申込"`）→「体験申込」id 21 と「体験申込（旧）」id 9 が返る。名前が完全に一致する id 21 を使う。`getCreatorContactTags`（`keyword: "フォロー対象"`）→ id 34。

元の条件で件数を数える。`postCreatorContactsLineSearch`（全アカウント横断なので `lineChannelId` は省略）:

```json
{
  "keyword": "",
  "limit": 1,
  "offset": 0,
  "sort": "createdAtDesc",
  "filters": {
    "contact": null,
    "line": null,
    "tag": { "id": [ { "value": 21, "operator": "eq" } ] },
    "inflowAction": null,
    "richMenu": null
  }
}
```

→ `filteredCount: 148`（条件に合う件数。「フォロー対象」が既に付いている人も含む）。

新しく付く件数を数えるため、付与するタグ id 34 を `ne` で加えて検索:

```json
"tag": { "id": [ { "value": 21, "operator": "eq" }, { "value": 34, "operator": "ne" } ] }
```

→ `filteredCount: 120`。

**アシスタント（ユーザーへ）**:

> 「体験申込」タグが付いているLINE友だちは148名で、そのうち「フォロー対象」がまだ付いていないのは120名です。
>
> この120名に「フォロー対象」タグを付けてよろしいですか？
>
> - 「フォロー対象」が付いたことをきっかけに動くワークフローがあれば、この120名に配信が始まります。送られたメッセージは取り消せません
> - メールアドレスも登録されている人は、メールのコンタクト一覧でもこのタグが付いた状態になります
> - 既に付いている28名はそのままです

**ユーザー**: 大丈夫、付けて。

**アシスタント（内部）**: 実行は**元の条件**で行う（`ne` を加えた条件ではない）。`postCreatorContactTagContactsLineByCondition`（パス `id: 34`）:

```json
{
  "keyword": "",
  "lineChannelId": null,
  "filters": {
    "contact": null,
    "line": null,
    "tag": { "id": [ { "value": 21, "operator": "eq" } ] },
    "inflowAction": null,
    "richMenu": null
  }
}
```

→ 成功（返り値に件数は無い）。

**アシスタント（ユーザーへ）**:

> 「体験申込」タグの付いたLINE友だち（事前確認で148名、うち新規120名）に「フォロー対象」タグを付けました。

---

## この例で守っていること

- タグ名は2つとも `getCreatorContactTags` で解決し、部分一致の候補から完全一致を選んでいる（id を推測していない）
- 実行前に同じ条件で数え、さらに `ne` を加えて「新しく付く人数（ワークフローの起動対象）」を出している
- ワークフローが起動しうること・取り消せないことを、承認をもらう前に伝えている
- 検索では `lineChannelId` を省略し、一括付与では `null` を明示している（全アカウント横断）
- `filters` を `null` にしていない（`null` にすると全コンタクトが対象になる）
- 報告件数を API の返り値から作らず、事前に数えた件数として伝えている
- 内部表現（JSON・`filters`・ツール名・タグID）をユーザーに見せていない

## 解除の場合の違い

- 件数確認の検索と解除ツールの**両方**で、外すタグを `eq` で `filters.tag.id` に含める（例: 「体験申込」全員から「フォロー対象」を外すなら `[{21, eq}, {34, eq}]`）。その `filteredCount` が外れる件数
- 承認時はワークフローの話ではなく「コンタクト自体と他のタグは残る」ことを伝える（解除ではワークフローは起動しない）
