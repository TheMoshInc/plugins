# メールアドレスのCSVインポート（正本）

`postCreatorContactsEmailCsvImportJobs` を起点とする一括登録の手順・CSV形式・取り込み挙動の正本。ツールの入出力そのものは [mcp-tools.md](mcp-tools.md)。

> 本ファイルの手順・CSV形式・挙動は、MOSH の API スキーマ定義で確認したもの（2026-09 時点）。
> 値を書き換えるときは、記憶や推測ではなく MOSH の API スキーマ定義で裏取りする。

**LINE友だちには CSV インポートが無い**（同期ジョブは MCP 非公開）。LINE の一括取り込みを頼まれたら管理画面を案内する。

## 実行できるかを先に判定する

手順2でCSVファイルの実体を HTTP PUT する必要がある。**PUT できる手段（Bash の curl 等）を持たないクライアントでは、この一連を完了できない。**

| 状況 | 対応 |
|---|---|
| ファイルの実体を PUT できない | ジョブを作らない（作ると使われないジョブが残る）。MOSH 管理画面からの CSV アップロードを案内する |
| CSVファイルが手元に無い（内容だけ口頭で渡された） | まず CSV を作ってよいかを確認し、下記の形式で作成してからユーザーに内容を確認してもらう |
| PUT できる | 下の手順に進む |

## 手順（順序の入れ替え不可）

1. `postCreatorContactsEmailCsvImportJobs` に `{ "name": "<ファイル名>" }` を渡し、`id` と `uploadUrl` を受け取る
2. `uploadUrl` に CSV ファイルの実体を `Content-Type: text/csv` で **HTTP PUT** する（API は代行しない）

アップロードが完了すると、取り込みは自動的に開始される（別途の実行指示は不要）。`uploadUrl` の有効期限は **発行から15分**。失効したら手順1からやり直す。

**承認は手順1の前に1回だけ取る**（判定表は SKILL.md）。承認後は手順1→2を止めずに通す。

## CSVの形式

- 1行目に**ヘッダー行が必須**。`email` 列を含めること（列名の大文字小文字は問わない）
- 2行目以降にメールアドレスを1行1件
- `email` 以外の列は無視される（名前・タグ等を入れても取り込まれない）

```csv
email
tanaka@example.com
sato@example.com
```

## 取り込み時の挙動

| ケース | 結果 |
|---|---|
| 前後に空白がある / 大文字が混ざる | 空白除去・小文字化して正規化したうえで判定・登録される |
| 同じアドレスが複数行にある | 後の行が優先され、1件として取り込まれる |
| 既に登録済みのアドレス | 重複登録されない |
| 削除済み（非表示）のコンタクト | **再度有効化される** |
| 購読解除されたコンタクト | **購読解除のまま維持され、配信対象には戻らない** |
| 形式が不正な行 | 取り込まれず、エラーとして集計される |

## 結果は MCP から確認できない

取り込みの成否と結果（取り込み件数・エラー行の明細）は**クリエイター宛のメールでのみ通知**され、MCP からは取得できない（進捗確認ツールは非公開）。

そのため、報告は完了を断定しない。例:

> CSVの取り込みを開始しました。取り込み結果（件数・エラー行）は、MOSH に登録されているメールアドレス宛の通知でご確認ください。

「◯件を登録しました」「インポートが完了しました」とは書かない。ファイルの行数からの推計を「取り込み件数」として提示しない。

## 承認時に伝えること

- どのファイルを、何行（ヘッダーを除く件数）取り込むか
- 削除済みのコンタクトが含まれていれば**再度有効になる**こと
- 購読解除した人は配信対象に戻らないこと
- 取り込みが始まると MCP からは取り消せず、結果は通知メールでの確認になること
