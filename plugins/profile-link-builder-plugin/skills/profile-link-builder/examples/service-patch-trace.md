# トレース例: 「サービスカードを大サイズにして」

取得ツールがある環境と、取得ツールがカタログに無い環境（保険の手順）の両方を示す。

## ユーザー発話

> プロフィールリンクの「ビジネス英語コーチング」のカード、大サイズにして。

## A. 現在値を取得できる環境（`getCreatorProfileLinkServices` がある）

### 1. 取得

```
getCreatorProfileLinkServices(queryParams: {})
→ services: [ { service: { id: "42", ...「ビジネス英語コーチング」... },
                profileLinkSettings: { isVisible: true, displayOrder: 1, cardSize: "MEDIUM" } }, ... ]
```

名前が1件だけに一致 → ID は `42`。同名が複数ならユーザーに選んでもらう。

### 2. 提示 → 承認

> 以下の内容で更新します。
>
> - 対象: 「ビジネス英語コーチング」
> - カードサイズ: 中 → **大**
> - 表示/非表示: 表示のまま　／　表示順: 2番目のまま
>
> この内容で進めてよいですか？

### 3. 実行

`displayOrder` は0始まりの絶対値。取得した `1`（= 2番目）をそのまま渡す。

```
patchCreatorProfileLinkService(
  pathParams: { id: "42" },
  bodyParams: { isVisible: true, displayOrder: 1, cardSize: "LARGE" }
)
```

### 4. 報告

> 「ビジネス英語コーチング」のカードサイズを大サイズに変更しました。プロフィールページには通常すぐ反映されます。

## B. 取得ツールがカタログに無い環境

`getCreatorProfileLinkServices` がカタログに無い。ID も現在値も読めない。ID は管理画面に表示されないことがあり、クリエイターが答えられないことも多いので、**まず分かるかを聞く**。

> 「ビジネス英語コーチング」のカードサイズをここから変えるには、このサービスの ID と、今の表示/非表示・表示順が必要です。分かりますか？

- 分かる → 「今の状態を確認する手段が無いため、教えていただいた内容をそのまま使います」と添えて提示 → 承認 → 実行（A の 2 以降と同じ）
- 分からない → **実行せず**、「ここからは変更できないので、管理画面で操作してください」と案内して終える（画面のどこで ID を確認できるかは案内しない。確認できていないため）

## NG（やってはいけない）

- 取得せずに `displayOrder: 0` / `cardSize: "MEDIUM"` などを推測で埋めて「非表示だけ」送る → 表示順やサイズが意図せず書き換わる
- ユーザーへの文面に `patchCreatorProfileLinkService` / `cardSize` / `LARGE` などの内部名を出す
