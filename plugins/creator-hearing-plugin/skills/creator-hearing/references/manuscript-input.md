# 原稿が渡された場合（セールスレター・既存ページの文面・メモ）

ユーザーが原稿を持っているとき、改めて聞かれるのは手間でしかない。**原稿を読み取ってシートを埋め、確認だけにする**。

1. 原稿から共通3ブロックと、呼び出し元シートの項目を抽出して埋める。商品・価格・特典・保証・締切・実績・声・講師・行動先は原文の記載をそのまま転記し、出典として「原稿◯段落目」を添える
2. 顧客像は原稿の「こんな方へ」「あなたは〜ではありませんか」等の呼びかけから1人分に要約し、`確認` 扱いで提示する。要約が合格基準の3点（状況・困りごと・代替手段が具体名詞）に届かなければ、`要記入` にして候補を 2〜3 人分出す。目的ごとに決める項目（例: 目的の種別）は、呼び出し元のシートの推奨ルールで推奨を選び、推奨に印を付けた選択式で出す（ユーザーが肯定して `確定`）
3. シートは**要記入だけを先頭に**まとめ、埋まった項目は「原稿から転記しました。違う所だけ直してください」と1行でくくる（全行を読ませない）
4. 原稿に無いもの（多くは行動先の実URL/ID・画像URL・使用許諾。目的ごとの項目は呼び出し元のシートの規則）だけを `要記入` として尋ねる。原稿に無い実績・声・保証を補わない
5. 原稿は書き換えない（`SKILL.md` 必須ルール D）。後続の構成案・構築では原文を優先して配置し、改善提案（抽象表現・具体化等）は「未確認・仮定」の欄に提案として書く

## 外部の既存ページ（実URL）が渡された場合

調査結果を、シートの仮埋め材料にする。商品・顧客像・行動先は原文から埋め、埋まらなければ `要記入`。外部ページの調査手順そのものは、呼び出し元のスキル（例: LP を作るスキルの外部ページ再現の手順）が持つ。
