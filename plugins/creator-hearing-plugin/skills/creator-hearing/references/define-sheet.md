# 呼び出し元のスキルが、追加項目のシートを持つ・渡すとき

`creator-hearing` は共通3ブロックを持つ。目的ごとに必要な追加項目（例: LP のゴール種別・画像、ファネルの目標数値、ワークフローの配信目的）は、**呼び出し元のスキルが自分のシートとして持つ**。このファイルはその書き方と、呼び出し側の義務。

## シートの書き方

呼び出し元の `references/hearing-sheet.md`（または同等のファイル）に、次を書く。

| 書くこと | 内容 |
|---|---|
| 追加ブロックの項目表 | 列は `# / ブロック / 項目 / 区分 / 仮埋めの主な材料` の5つ（共通シートと同じ）。番号は共通の #1〜#3 に続けて #4 から振る（番号は目的ごとに独立で、結果ファイルでは目的ごとの節に分かれる） |
| 必須と任意の区分 | **必須は、埋まらないと後続が成り立たない項目だけ**にする（ゲートで止まるため）。迷ったら任意にして `仮定` を置く |
| 仮埋めの材料 | その項目を、どのツール・資料から埋めるか（スナップショットのどの節か、どの MCP か） |
| 目的固有の禁止 | 目的に固有の「やってはいけない」だけ書く。共通の禁止（1問ずつ聞く、捏造、幅広く 等）は再掲しない |
| 提示フォーマットの例 | 追加ブロックの行の例（共通3ブロックの例は `common-sheet.md` にある） |

共通3ブロックは**書き直さない**。共通の項目に目的ごとの補足があるときだけ、「#N: 〜（目的ごとの補足）」と1行で足す。

## 呼び出し側の義務

実行時の義務（目的とシートのパスを渡す、`確定`・`確認` を聞き直さない、`仮定` を引き継ぐ、結果ファイルを書き換えない）は `SKILL.md`「呼び出し元のスキルが守ること」が正。ここには再掲しない。

## 例

LP 用のシートの例は、#4 ゴール、#5 証拠、#6 流入と端末、#7 トーン・素材、#8 見せ場の材料。ほかの目的のシートも、それぞれのスキルが同じ形で足す。
