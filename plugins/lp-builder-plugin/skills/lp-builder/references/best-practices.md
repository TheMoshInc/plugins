# LP設計ベストプラクティス

構造ルール（必須フィールド・許可プロパティ・クラッシュ防止）は `content-schema.md` が正。本書は「売れる・読みやすい LP」にするための設計指針と、送信前のセルフレビュー観点をまとめる。

## 構成計画（構築を始める前に必ず）

プラン・サービスの情報を分析し、LP 全体の構成を先に計画してから content を組み立てる:

- ターゲット顧客が「このサービスを今すぐ購入すべき理由」を納得するストーリーを組み立てる
- 各セクションで伝えるメッセージを、見出しだけでなく本文テキストの内容まで具体的に決める
- **フル構築（構成をお任せされた新規 LP）ではセクション数最低10個**を基準にする（LP は縦に長く読ませる媒体。3〜4セクションでは訴求が薄く安っぽく見える）。**ユーザーがセクション構成や規模を明示的に指定した場合はその指定を優先し、勝手に増やさない**

### 推奨セクション構成

「役割」は設計上の呼び名で、実際に `attributes.sectionType` に入れる値は「`sectionType`」列の値を使う（`"hero"` や `"cta"` は無効値。許容値の一覧は `content-schema.md` の「`sectionType` の許容値」を参照）。

| 順 | 役割 | 内容 | `sectionType` |
|---|---|---|---|
| 1 | ヒーロー | キャッチコピーとメインビジュアル、CTA | `main` |
| 2 | 悩み共感 | ターゲットの課題・悩みへの共感 | `description` |
| 3 | 解決策 | 提供する解決策の提示 | `description` |
| 4 | 特徴・メリット | プラン・サービスの特徴・受講後の変化 | `merit` |
| 5 | 実績・数字 | 実績を大きな数字で見せる（下記「数字・実績バー」） | `merit` または `description` |
| 6 | 受講の流れ | 申込みから受講までのステップ | `description` |
| 7 | お客様の声 | 受講者の声（カード形式） | `description` |
| 8 | 講師紹介 | 講師・運営者のプロフィール | `profile` |
| 9 | 料金・CTA | 価格表示 + 説明 + 大きな CTA ボタン | `description` または `main` |
| 10 | FAQ | よくある質問（見出し + テキストの繰り返し） | `faq` |
| 11 | フッターCTA | 最終 CTA + 注意事項 | `description`（特商法表記等は `footer`） |

プラン・サービスの内容に応じて追加・変更してよいが、削って10未満にしない。

### 禁止パターン（セクションの中身）

- `heading` だけのセクション（必ず説明テキストを添える）
- `text` だけのセクション（見出しか画像を添える）
- セクション内に要素が1つだけ（最低2つ以上の要素を配置）
- 子要素ゼロの空セクション

## テキストの具体性原則

- テキストは具体的に書く: 「充実のサポート」ではなく「24時間以内に返信するチャットサポート」
- 「充実した」「丁寧な」「安心の」など、具体性のない抽象表現は使わない。何がどう充実しているのかを数字・固有名詞・手段で書く
- 見出しはベネフィット（受講後にどうなるか）を語り、本文がその根拠を語る構成にする

### 日本語テキストの規律

- テキストは全て正確な日本語で書く。文字化けは絶対 NG
- **簡体字は禁止**（例: 「踏袭」「业务」「电话」は不可 → 「踏襲」「業務」「電話」）。繁体字の伝統字形（「國」「體」「學」等）も禁止。現代日本語の標準字体（新字体）とひらがな・カタカナのみを使う
- 少しでも自信がない漢字はひらがなにする
- 「✓」「✔」等の記号・チェックマークは使わない（環境により文字化けする）

## 余白の原則

余白ゼロは絶対 NG。詰まって見える LP は安っぽくなる。

- セクション間: `padding` 上下 **80px 以上**（モバイルは 48px 以上）
- カード内部: `padding` **32px 以上**
- 見出しと本文の間: **16〜24px**（`text` / `heading` の `padding` で確保する。`margin` は使わない）
- ボタンの上下: **24px 以上**の余白
- テキストの左右: 端に張り付かないよう左右 `padding` を入れる（デスクトップ 48〜60px、モバイル 16〜20px）

高さの演出は `height` ではなくセクションの `padding` 上下値で行う（`height` 指定は編集画面が崩れるため禁止 — `content-schema.md` 参照）。ヒーローで迫力を出したい場合は `padding: "120px 24px"` のように上下を大きく取る。

## 表現テクニック

いずれも `content-schema.md` の許可スタイルプロパティの範囲内で実現する。

### ゼブラ背景（交互背景色）

隣り合うセクションで背景色を交互に変える（例: 白 → ベージュ → 白 → ダーク）。セクション間の視覚的な区切りが明確になり、長い LP でも読みやすい。**全セクションが同じ背景色（またはデフォルト白の放置）にならないこと**。背景色は `attributes.background: { "type": "color", "color": "#..." }` で設定する。

### カード表現

外枠 `section` の `children` に内枠 `section` を置き、内枠に薄い背景色 + `borderRadius`（8〜16px）+ `padding` 32px 以上を設定してカードに見せる。特徴カードやお客様の声で使う。

枠線を付ける場合は**辺別 border プロパティ**（`borderTopStyle` / `borderTopWidth` / `borderTopColor` を四辺ぶん。詳細は `content-schema.md` の許可プロパティの項）で薄い線（例: `rgba(0,0,0,0.08)` の 1px）を指定する。`border` ショートハンドは編集画面のパネルに反映されないため使わない。影（`boxShadow`）は引き続き禁止 — 強調は枠線と背景色のコントラストで表現する。

### 3層見出しパターン

セクション導入を「小さいラベル → 大きい見出し → 説明文」の3層で組むと視覚的な階層が明確になる:

1. `text`（`fontSize: "12px"`〜`"14px"`、アクセント色、英語ラベル等）
2. `heading`（`fontSize: "30px"`〜`"36px"`）
3. `text`（本文サイズ、グレー系）

### 数字・実績バー

ダーク背景のセクションに、大きな数字（`fontSize: "48px"`）+ 小さいラベルのペアを `display: "flex"` で横並びに配置する。「10年以上の実績 / 500名以上の受講生 / 満足度98%」のような信頼性の訴求に効果的。

### グラデーション背景

セクションの背景は単色・画像のほか、構造化形のグラデーション（`attributes.background` の `type: "gradationColor"`）を設定できる。フラットな単色よりモダンで洗練された印象になり、ヒーローや CTA セクションで効果的。指定方法と値の制約（`angle`・`colorStops`・hsl 形式）は `content-schema.md` の「背景グラデーション」を参照。`styles.background` に `linear-gradient(...)` 文字列を書く方法は禁止（描画はされるがユーザーが後から編集できなくなる）。

### 横並びレイアウト（最大3列）

親 `section` に `styles: { "display": "flex", "gap": "16px" }`、子 `section` に `width`（例 `"31%"`）を指定して横並びにする。**横並びは最大3列まで**。4列以上はテキストが狭くなり読めなくなる（6項目なら 3列×2段か縦積みにする）。モバイルでは必ず `mobileStyles: { "display": "block" }` で縦積みに切り替える（詳細は `content-schema.md` の「PC/SPでレイアウト方向を変える方法」）。

### フォントの使い分け

見出しと本文でフォントを変えるとメリハリが出る（例: 見出し `'Noto Serif JP'` × 本文 `'Noto Sans JP'`）。使えるのは `content-schema.md` 記載の4種のみ。LP 内での組み合わせは1パターンに統一する。

### テキスト色と背景色のコントラスト

ダーク背景セクションには白系テキスト（`#ffffff` / `#cccccc`）、ライト背景にはダーク系テキスト（`#1a1a2e` / `#212529` / `#666666`）を使う。テキスト色と背景色が同系・近似になっていないか必ず確認する。

## モバイルファースト（必須）

MOSH のユーザーの多くはスマートフォンからアクセスする。全セクションでモバイル対応を必ず行う。

- **全セクションに `mobileStyles` を必ず指定する**（省略禁止。省略すると PC 用の大きな余白・横並びがそのまま SP に出る）
- padding: デスクトップ `"80px 60px"` → モバイル `"48px 20px"` 程度
- 見出し: デスクトップ 30〜48px → モバイル 20〜30px（固定スケール内で選ぶ）
- 本文: デスクトップ 16〜18px → モバイル 14〜16px。**12px 未満は禁止**（10px は注釈など補助テキストに限る）
- ボタン: モバイルでは `mobileStyles: { "width": "100%" }` で全幅にし、`padding` を十分に確保してタップ領域を44px以上にする（ボタンの `fontSize` は UI 固定の 14px のまま — `content-schema.md` 参照）
- 横並び（`display: "flex"`）は `mobileStyles: { "display": "block" }` で縦積みに
- 画像はモバイルで幅 100% 基本。固定幅の要素がモバイル画面幅（375px）を超えないこと（横スクロールの発生は禁止）

## CTA の設計

- CTA ボタンは LP 内に**最低3箇所**配置する: ヒーロー直後・中盤・最終セクション
- MOSH のプラン・サービスへ誘導する場合、`href` は `https://mosh.jp/services/{id}?openExternalBrowser=1` の形式にする。**末尾の `?openExternalBrowser=1` は必須**（LINE 等のアプリ内ブラウザでの決済不安定を回避するため）。`{id}` はユーザーから確認した実在のプラン・サービス ID のみ使う
- `href` が確定しないボタンにダミー URL（`#` や `https://example.com/...`）を捏造しない（`content-schema.md` の既存ルールどおり。ユーザーに確認するか、その旨を伝えて保留する）

## 画像の運用

- **`image` 要素は、実在する画像 URL をユーザーから提供された場合のみ作成する**。URL が未提供の段階で `src: ""` のプレースホルダーを配置しない（編集画面の画像配置も画像を選択してから行うフローであり、src 空の image 要素は画面上で空枠・壊れ画像表示になるだけで居場所の確保として機能しない）
- ダミー URL（`https://example.com/...` や `#` 等）の捏造も引き続き禁止
- 画像が未提供のときは、テキスト・見出し・背景色・ボタンでセクションを組み、画像は「編集画面の『パーツの追加 > 画像』からアップロードして追加してください」と案内する。ユーザーが画像を用意でき次第、URL をもらって `image` 要素を追加してもよい
- 実 URL を配置する場合のサイズ目安: アイコンは `width` 60〜100px、装飾画像は 150〜300px、写真・メイン画像は幅 100%（モバイル）

## セルフレビューチェックリスト

`patchCreatorLandingPageDraft` で content を送る**前**に一度、保存後に `getCreatorLandingPage` で読み戻した content に対してもう一度、以下を確認する。問題があれば修正して再保存する。

| # | チェック | NG の例 |
|---|---|---|
| 1 | セクション数が計画どおりか（フル構築なら10以上。ユーザー指定構成なら指定どおり） | お任せ構築で4セクションのまま完成扱い |
| 2 | 見出しだけ・テキスト1つだけ・空のセクションがないか | `heading` 1つのセクション |
| 3 | テキスト色と背景色が近すぎないか | ダーク背景に `#333` のテキスト |
| 4 | 背景色未設定（デフォルト白）の放置がないか | 全セクション白 |
| 5 | CTA ボタンが3箇所以上あり、href が正しいか | CTA 1箇所のみ / href 空のまま放置 |
| 6 | 抽象的な文言が残っていないか | 「充実のサポート」 |
| 7 | 文字化け・簡体字・不自然な漢字がないか | 「业务」「✓」 |
| 8 | 全セクションに `mobileStyles` があるか | PC 用 padding のまま |
| 9 | 横並びセクションに `mobileStyles.display: "block"` があるか | SP で3列が潰れる |
| 10 | src が空・ダミー URL の image 要素が無いか | `src: ""` や `https://example.com/...` の画像 |

10項目すべてを下書き保存の前に満たす。公開時はチェックリスト全体を再確認してから `PUBLISHED` にする。
