# ヒアリングシート（1往復方式）

新規 LP の要件は、質問を順に投げて答えさせるのではなく、**LLM が先に調べて仮埋めしたシートを1画面で提示し、ユーザーには空欄と誤りだけ直してもらう**。一流のウェブディレクターが「事前調査で埋めたヒアリングシートを渡し、面談では確認と訂正だけを行う」のと同じ立ち回り。

## 手順

1. **事前調査（ユーザーに聞く前に必ず）**
   - `getCreatorProducts` → 売り物の候補。該当しそうな商品は `getCreatorProduct` / `getCreatorProductPlans` で価格・期間・説明文まで取る
   - `getCreatorLandingPages` → 既存 LP のトーン・実績表現・使っている画像の有無
   - ユーザーから渡された原稿・参考 URL・画像 URL があればそれを主材料にする（外部 URL は本文の商品・顧客像・CV先だけを材料にし、画像は流用しない）
   - 商品が MOSH 未登録で原稿も無い場合は仮埋め率が落ちる。その旨を明記し、必須欄だけは記入を依頼する
2. **シートを仮埋めして1画面で提示する**。各行に `確認`（調査で埋まった。誤りがあれば直してほしい）/ `要記入`（材料が無い）/ `仮定`（任意欄で材料が無いため LLM が仮置きした）のどれかを付ける
3. 冒頭に一言添える: 「良い LP にするため、下の表の『要記入』と、違っている『確認』だけ直してください。それ以外は仮定のまま進めて、構成案で確認します」
4. **必須欄（1〜4。#4 は種別の選択のみ）が埋まるまで構成案には進まない**。任意欄は空でも `仮定` を明記して進む。ゴール種別は LLM の推奨に印を付けた4択で示し、選ばせる（書かせない）
5. 回答を受けてシートを確定し、`section-plan.md` の構成案へ

## 原稿が渡された場合（セールスレター・既存LPの文面・メモ）

ユーザーが原稿を持っているとき、改めて聞かれるのは手間でしかない。**原稿を読み取ってシートを埋め、確認だけにする**。

1. 原稿から7ブロックを抽出して埋める。商品・価格・特典・保証・締切・実績・声・講師・CTA先は原文の記載をそのまま転記（出典として「原稿◯段落目」を添える）
2. 顧客像は原稿の「こんな方へ」「あなたは〜ではありませんか」等の呼びかけから1人分に要約し、ゴール種別は**売り物の価格**（LINE/無料DLのみ→A、日程→B、〜数万円→C、数万円超→D。CVが無料相談でも D）から推奨を選ぶ。どちらも `確認` 扱いで提示
3. シートは**要記入だけを先頭に**まとめ、埋まった項目は「原稿から転記しました。違う所だけ直してください」と1行で括る（全行を読ませない）
4. 原稿に無いもの（多くは CV先の実URL/ID・事業者名・画像URL・使用許諾）だけを `要記入` として尋ねる。原稿に無い実績・声・保証を補わない
5. 原稿の文章は**ユーザーの資産**として扱う。構成案・JSON では原文を優先して配置し、勝手に要約・書き換え・トーン変更をしない。改善提案（抽象表現・具体化等）は構成案の「未確認・仮定」列に提案として書き、承認を得てから反映する

## シートの項目

| # | ブロック | 項目 | 区分 | 仮埋めの主な材料 |
|---|---|---|---|---|
| 1 | 商品・オファー | 商品名 / 価格 / 提供形式・期間 / 特典・保証・締切 / 選ばれる理由（競合・代替手段との差） | **必須** | 原稿があれば原稿 → getCreatorProduct(s) / ProductPlans で突合 |
| 2 | 顧客像 | 1人分の「状況・いま困っていること・いま使っている代替手段」（下記の合格基準） | **必須** | 商品説明・原稿から逆算 |
| 3 | CV 先 | LP の唯一の CV（申込 / 購入 / LINE登録 / 資料DL）と遷移先（MOSH サービス・プラン ID、または外部 URL） | **必須** | Products / Plans の ID。無ければ要記入 |
| 4 | ゴール | LP の種別を **4択で選ばせる**: (A) リード獲得（LINE登録・無料DL。無料相談は含めない）/ (B) 告知・イベント / (C) 即決販売（数万円まで）/ (D) 高額・講座販売（検討型）。セクション数と**唯一の行動（CTA の文言・遷移先）**を決める。目標数値・判断期限は任意 | **必須**（種別のみ） | **売り物の価格で決める**: LINE登録・無料DLのみ→A、日程が主役→B、〜数万円→C、数万円超→D（CV が無料相談でも D。無料相談は A の判定材料にしない）。推奨を先に選んでおき、違えば選び直してもらう |
| 5 | 証拠 | 実績数字 / 受講者の声 / メディア・資格。使用許諾済みか | 任意 | 既存 LP・原稿。無ければ「実績セクションは立てない」と仮定 |
| 6 | 流入と端末 | 主な流入元（広告 / SNS / LINE / メルマガ / 検索）と流入前に見せているもの。スマホ比率 | 任意 | 仮定: SNS・LINE 起点、スマホ主体 |
| 7 | トーン・素材 | **プリセット**（`presets.md` の5つから、ゴール・業種で推論したおすすめに印を付けて4〜5択で提示） / 参考 LP 1本 or 避けたい雰囲気（渡されたら印象語のまま扱わず `best-practices.md`「参考LP・雰囲気を意匠に変換する（6軸観察）」で色・書体・余白・写真・UI・言語表現に分解する） / ブランド色の指定 / **画像**: 下記「画像の収穫と依頼」のスロット表で聞く（MOSH 内の候補を先に埋め、空いたスロットだけ依頼） / フッター表記（事業者名・屋号、特商法・プライバシーポリシーの URL） | 任意（事業者名だけは構成案までに確定） | `getCreatorProducts` の画像・`getCreatorLandingPages` の画像・`getCreatorMaterials` の画像素材。特商法等の URL は実在するものだけ |

## 画像（#7）の収穫と依頼

画像はデザイン品質の最大レバー（テンプレ・配色より効く）。シートの #7 では、**ゴール別に必要な画像スロットを表で示し、MOSH 内で見つかった候補を先に埋めてから、空いたスロットだけを依頼する**。「画像ありますか？」と漠然と聞かない。

| スロット | 役割 | 使う場所 | ゴール別の要否 | 収穫元（先に埋める） | 無いときの依頼文 |
|---|---|---|---|---|---|
| プロフィール／講師の顔写真 | Trust | ヒーロー横 or 講師紹介 | A・D は必須、B は登壇者分、C は任意 | 既存 LP の画像（`getCreatorLandingPages`）・素材ライブラリ（`getCreatorMaterials`） | 「ご本人の顔写真を1枚（明るい場所・正面〜斜め、縦横どちらでも）」 |
| 商品・サービスの写真 | Solution | ヒーロー・画像＋テキスト | C・D は必須、A は特典の見た目があれば | 商品画像（`getCreatorProducts` の画像）・既存 LP | 「商品（教材・会場・成果物）が分かる写真を1〜2枚」 |
| 活動・受講の風景 | Solution | 画像＋テキスト・声の横 | A・B で効く、D は任意 | 既存 LP・素材ライブラリ | 「セッション中や受講中の写真を1枚（顔出し不可なら後ろ姿・手元でも可）」 |
| 悩み・課題が伝わる写真（任意） | Problem | 悩み共感セクション（無ければヒーロー直後） | あれば効果的、C・D で特に効く | 既存 LP・素材ライブラリ（実写が無ければ無理に用意しない。イラストの捏造は不可） | 「顧客が困っている場面が伝わる写真があれば1枚（無理に用意しなくてOKです）」 |
| ロゴ・屋号 | — | ヒーロー上部・フッター | 任意（あれば全ゴール） | 既存 LP・MOSH の表示アイコン | 「ロゴがあれば PNG で」 |
| 実績・メディア | Trust | 数字バー下・信頼章 | あれば（捏造禁止） | 既存 LP | 「掲載メディアのロゴ・資格証など、使用許諾があるもの」 |
| 背景・雰囲気素材（任意） | Hero | ヒーロー背景 or CTA帯背景（`best-practices.md`「背景画像で装飾密度を作る」） | あれば効果的、無くても単色背景で組む | 既存 LP・素材ライブラリ | 「雰囲気に合う写真（活動風景・商品・空間など）が1枚あれば背景に使えます。無ければ単色背景で組みます」 |

- 表は**そのゴールで要否が「必須」「効く」のスロットだけ**出す（D なら顔・商品の2〜3行）。**依頼する枚数**は1スロット1枚で足りる（多く求めない）。ただし収穫できた画像は複数セクションに使い回してよく、LP 全体で使う画像の総枚数・役割はゴール別の目安（`best-practices.md`「画像点数の目安」＝Hero/Problem/Solution/Trustの4役割）を満たすようにする
- 埋まらないスロットは、①依頼（URL か編集画面からのアップロード）②見送り（テキスト・背景色で組む。品質が落ちる旨を一言）③下書きはプレースホルダで進め公開前に差し替え、の3択をユーザーに選ばせる。黙って格下げしない
- 収穫した画像は用途（ヒーロー用など）と一緒に列挙し、「この写真をヒーローに使ってよいですか」と使用可否を確認する（他人が写る写真・メディアロゴは使用許諾も）
- 形式は JPEG / PNG / WebP。SVG は不可。手元ファイルは編集画面の「パーツの追加 > 画像」からアップロードしてもらい、URL を受け取る

## 顧客像（#2）の合格基準

- **1人分**で、次の3点が**具体名詞**で書けていること: (a) 状況（職業・立場・ライフステージ）(b) いま困っていること (c) いま使っている代替手段（他サービス・独学・放置 等）
- 「30〜50代女性、幅広く」「起業したい人全般」は不合格。埋まっているが使えない
- 不合格・空欄のときは**書かせず、選ばせる**: 商品の価格・期間・約束（説明文）から逆算して顧客像候補を 2〜3 人分こしらえ、「どれが一番近いですか」と選択させる。選ばれたものを確定値にし、微調整だけ受ける

## 禁止

- 項目を1問ずつ順番に質問する（「急に20問」体験になる）
- 必須欄が空のまま構成案・JSON 構築へ進む（ゴール種別を仮定のまま進めない。セクション数がぶれる）
- 1つの LP に2種類の行動（例: 無料相談と高額申込）を混在させる。高額商品は相談への申込に一本化し、料金は見せるだけにする
- 「幅広く」を顧客像として受け入れる（ヒーローのコピーが総花的になり、薄い LP の直接原因になる）
- 材料が無い項目を「確認」扱いで捏造する（無いものは `要記入` か `仮定`）
