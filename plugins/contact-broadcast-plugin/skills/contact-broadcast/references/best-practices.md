# 配信文面のベストプラクティス

**文面をこちらで組む余地があるときに読む。** 項目の上限・形式・パラメータ仕様は
[mcp-tools.md](mcp-tools.md) が正。承認フロー・完了形の書き方・**依頼に無い事実を補わない規約**は
SKILL.md が正。本書はそれらの上で「読まれ、通報されず、1つの行動につながる文面」にするための
**形式の基準**とセルフレビュー観点をまとめる。

## この基準の使い方（先に読む）

本書は**形式（長さ・構造・表現の規律）の基準**であり、**書く材料（事実）を増やす根拠にはならない。**
SKILL.md の「配信本文は与えられた情報の言い換え・整形に留める」が常に優先する。

- 材料が足りず目安の文字数に届かないときは、**文面を膨らませず短いまま出す。** 厚くしたいなら
  Step 3 で材料をユーザーに尋ねる。
- 直すべきなのは次の4種だけ（**根拠が違うので混ぜない**）:
  1. **上限超過**（読まれない長さ・多すぎる吹き出し）
  2. **A の表現の混入**（収益の断定・誇大表現。**LINE のガイドライン/規約に根拠あり = BANリスク**）
  3. **依頼文に無い事実の追加**（実績・社会的証明・希少性・効果・対象者。**BANとは無関係で、
     依頼内容への忠実性の問題**）
  4. **目的と誘導先の散乱**（1配信に複数の目的・複数のURL）
- 「短い」「情報が少ない」ことは、依頼文の材料の範囲で書けている限り**欠点として扱わない。**
  逆に、材料に無い数字・実績を足して厚くするのは 3 に当たり、短いことより重い問題。
- **依頼文が本文・件名を逐語で指定している場合は、絵文字の追加・改行の挿入も含めて手を加えない。**
  本書の基準は文面をこちらで組む場合にだけ適用する。

## 1メッセージ = 1目的

- 1通の目的は1つ。読ませる（教育・お知らせ）と申し込ませる（販売）を同じ吹き出しに混ぜない。
- **誘導先は1つに絞る。** 2つ以上並べるとどちらも押されない。
- 別々の告知が2件あるなら配信を2本に分ける（同じ本文に詰め込まない）。

## 文字数の目安（全角換算）

**上限は守る。目安の下限は「材料がある場合の目標」で、下限未達それ自体は問題ではない。**

| 用途 | 目安 | 上限 | 補足 |
|---|---|---|---|
| 告知・案内（LINE の `text` / メール本文の主文） | 150〜250字 | 500字 | 長いと離脱する。API 上限（`text` は 4000字。mcp-tools.md）とは別の実務基準 |
| リマインド（日時・リンクだけ） | 80〜120字 | 200字 | 教育・訴求を混ぜない |
| ひとこと（お礼・短い連絡） | 50〜100字 | 200字 | 説明が要るなら別配信に分ける |
| メール件名 | 15〜25字 | — | スマホで切れない長さ。要点を【】で囲むと目に入る |
| `altText`（カルーセル・リッチメッセージの通知文） | 20〜40字 | 50字（mcp-tools.md） | 通知に出る文。何の配信か分かる形にする |
| カルーセルのカード | `title` 15字以内 / `text` 40〜60字 | — | カード幅で折り返すので短く。カードごとに内容を変える |
| ボタン文言（`buttonText` / CTA） | 8〜15字 | — | 動詞で終わる（「詳細を見る」「申し込む」） |

メール本文をこちらで組む場合の全体量は 500〜1,200字（スクロール3回以内）が目安。ただし依頼文の
材料で足りる分だけ書く。

### 吹き出し数（LINE の `contents` の要素数）

- 1配信あたり **2〜3個**。上限 **5個**。
- **吹き出し数 = LINE公式アカウントの課金通数。** 細かく割るとそのぶん配信コストが増える。
- 1つで足りる内容を分割しない。逆に、目的の違う内容を1つの吹き出しに詰め込まない。

## CTA（次にとってほしい行動）

- **1配信1CTA。** 文言は8〜15字で動詞で終わる（「詳細を見る」「日程を確認する」「申し込む」）。
- 「こちら」「以下をご覧ください」のように行動が分からない文言にしない。
- カルーセルで複数カードを出す場合は「カードごとに誘導先1つ」を守る。
- URL を渡さず「プロフィールのリンクから」と間接誘導するのは、URL を直接指定できない場合だけにする。
- 本文に URL を入れてクリック計測をしたい場合は、先に [tracking-consent.md](tracking-consent.md) の
  同意手順を通す（本書ではなくそちらが正）。

## 使ってはいけない表現

**出典の違う2種類が混ざりやすいので分けて扱う。** A は**アカウント停止（BAN）のリスク**、
B は**依頼への忠実性**の問題で、根拠も対処も別物。B を「BAN対策」として説明してはいけない。

### A. BANリスクのある表現（LINE の一次情報に根拠あり）

出典: [LINE公式アカウントガイドライン](https://terms2.line.me/official_account_guideline_jp) の
「禁止されるコンテンツ表現」「禁止業種・業態」、および LINE公式アカウント利用規約 第18条（禁止行為）。

| 使わない表現 | 直し方 | 根拠 |
|---|---|---|
| 稼げる / 稼ぐ / 儲かる / 儲ける / 月収○万円 / 不労所得 / 副業で○万円 | 収益・収入に言及しない（金額の話を本文から外す） | ガイドライン「『◯◯するだけ』等の簡単に稼げるような表現」／「儲かる・儲ける」を謳う情報商材は**禁止業態**／「稼げる」「儲かる」はアルゴリズム自動検知の禁止ワード例としても挙がる |
| ○○するだけ / たったこれだけ / 楽して | 手軽さを売りにしない。何をするのかだけ書く | 同上（「簡単に稼げるような表現」） |
| 誰でもできる / 誰でも成功できる / 確実に / 絶対に / 必ず / 100%成功 / 失敗しない | 成果・再現性の断定を**別の言い方に置き換えず削る** | ガイドライン「『誰でも成功できる』等の誇大広告・虚偽表現」／規約18条「虚偽情報の流布」 |
| 他社・他者を名指しした批判 | 自分の提供内容だけを書く | 規約18条「名誉権・プライバシー権の侵害」 |

**閾値は公開されていない。** 一次調査も「具体的にどの程度の表現・頻度でBANされるかの明確な閾値は
公開されていない」と明記している。**この表は「これだけ避ければ安全」という十分条件ではない**ので、
迷う表現は避ける側に寄せる。

**直し方の原則: 断定を別の断定に置き換えない。** 「絶対に成果が出ます」→「高確率で成果が出ます」は
主張を弱めただけで裏が取れていない点は変わらず、B の問題に横滑りするだけ。**主張そのものを削る**のが
正しい直し方（削って文が薄くなるのは正常。下の「材料が無いときの正解の形」を参照）。

### B. 出典が確認できていない表現（BANの根拠としては主張しない）

以下は LINE マーケティングの実務記事で「避けるべき」とされることが多いが、**LINE の一次情報
（ガイドライン・規約）に該当記述を確認できていない。** BANリスクとして説明してはいけない。
避ける理由があるとすれば次のとおり:

| 表現 | 避ける本当の理由 |
|---|---|
| 今すぐやらないと損 / ラストチャンス / 二度とない / 残席わずか / 今回限り | 期限・希少性は**事実**。依頼文に期限や残席の材料が無いのに書けば「依頼文に無い事実の追加」（→ 下の「文面を『お任せ』されたとき」）に当たる |
| 実際と違う「限定○名」 | 事実に反する記載。規約18条「虚偽情報の流布」に触れうる |
| 本文への金額の直書き | BANの根拠は未確認。金額は変わりやすく配信後に直せないため、申込ページ側に置くほうが安全という運用上の理由 |

- グレー: 「無料」は単体なら問題ない。「今すぐ」「限定」と重ねると煽りに見えやすいので1つの吹き出しに
  重ねない。

### ユーザーがその表現を自分で指定してきたとき

**A・B いずれも、ユーザーが本文を逐語で指定した場合は書き換えずにそのまま扱い**、Step 3 で
リスク（A は根拠つきで、B は「LINE の一次情報では未確認だが」と添えて）と言い換え案を1行示して
判断してもらう（本文の勝手な改変は SKILL.md の規約違反）。**逐語指定ではなく「強めに書いて」と
方針だけ言われた場合は、A の表現を使わずに組む**（この場合は改変にならない）。このとき
**削った分を実績や対象者の話で埋めない**（B の問題になる。次節を参照）。

## 具体性は「材料の範囲で」出す

- 「充実の」「安心の」「丁寧な」など中身のない形容は使わない。**代わりに、材料にある数字・
  固有名詞・日時・手段を使う**（「充実のサポート」→「9月5日20時から60分のオンライン説明会」）。
- 材料に無い数字・実績・所要時間・対象者を**創作して具体化しない。** 捏造の禁止が具体性より優先する。
- 材料が抽象語しか無いなら、抽象語を足すのではなく**その一文を削る。**

### 文面を「お任せ」されたとき

「本文はお任せ」「説明文とボタン文言はお任せ」と言われても、**書ける材料が増えたわけではない。**
委任されたのは表現の選択であって、事実の創作ではない。**カルーセルのカード本文だけの話ではなく、
LINE のテキスト1通・メール本文・件名・`altText` を含む、こちらで組む文面すべてに適用する。**

書いてよいのは**与えられた情報（講座名・サービス名・日時・URL・既存の配信内容）を自然な日本語に
言い換えた範囲**まで。

#### 判定のしかた（例の暗記ではなくこの1問で決める）

> **その一文が本当かどうかを、依頼文（と既存の配信内容）だけで判定できるか。**
> 判定できない＝クリエイターに確認しないと真偽が分からないなら、**書かない。**

「言いすぎかどうか」ではなく「**裏が取れているかどうか**」で判断する。やわらかい言い方にしても、
裏が取れていない事実は書けない（「絶対に成果が出ます」を「成果が期待できます」に直しても、
成果の根拠が無いなら書けないのは同じ）。

| | 例 |
|---|---|
| 書いてよい（名称・日時・URL の言い換え） | 「骨盤調整」→「骨盤まわりを整えるクラスです。」／「瞑想入門」→「瞑想のはじめ方を学ぶクラスです。」／「秋の新講座」→「秋の新しい講座のご案内です。」 |
| **書いてはいけない（実績・社会的証明）** | 「**ご好評いただいています**」「**人気の講座です**」「**おかげさまで**」「**リピーターの方も多い**」「**〜という声をいただいています**」「満席になりました」「たくさんの方にご参加いただきました」 |
| **書いてはいけない（開催実績・回数・希少性）** | 「**今回初めて開催する講座です**」「毎年恒例の」「久しぶりの開催」「**今回限り**」「残席わずか」「定員間近」 |
| 書いてはいけない（効果の断定） | 「姿勢や巡りをサポートします」「体幹バランスが整います」「成果が期待できます」 |
| 書いてはいけない（対象者の限定） | 「姿勢の悩みがある方におすすめです」「運動不足の方向けです」「初めての方でも取り組みやすい内容です」 |
| 書いてはいけない（検証できる具体値） | 「所要60分」「定員12名」「満足度98%」「これまで500名が受講」 |

**この節の根拠は BAN 対策ではない。** 上の A（LINE のガイドライン・規約に根拠がある表現）とは別で、
理由は**依頼内容への忠実性** ── 裏が取れていない事実を、クリエイターの名前で実顧客に送らないため。
実績・社会的証明・開催回数・希少性を LINE の一次情報に基づく「BANリスク」として説明してはいけない
（一次調査に該当記述はない）。

実績・社会的証明系は**特に混入しやすい**（訴求を強めたい依頼で、A の表現を避けた代わりに
「好評」「人気」で埋めてしまう）。**A の表現を削る場面でも、削った分を実績・対象者の話で埋めない。**
削って薄くなった文はそのままでよい。

#### 材料が無いときの正解の形

**物足りなく感じても足さない。** 告知は「何が・いつから・どこで詳細が見られるか」だけで成立する。

```
秋の新しい講座のご案内です。

詳細はプロフィールのリンクからご確認ください。
```

厚くしたいなら Step 3 で材料（実績・対象者・所要時間など）をユーザーに尋ねる。委任された場面で
最短の言い換えに留めるのは手抜きではなく、**事実を保証できない文を実顧客に送らないための正しい判断**。
`examples/line-carousel-three-cards.json` のカード本文もこの範囲の見本になっている。

## 読みやすさ（スマホ前提）

- 1行 **20〜25字**で改行する。PC 幅で書かない。
- 3〜4行ごとに空行を入れる。1段落を長くしない。
- **数字は半角**（「3日間限定」「9月5日20時」）。
- **絵文字は1メッセージ2〜3個まで。** 見出しの位置に使い、装飾として散らさない。
- 罫線・■◆の多用はしない。「✓」など環境依存の記号は使わない。
- 冒頭1〜2行で「誰に向けた何の連絡か」が分かるようにする（LINE は通知プレビューでここだけ読まれる）。
- `{{line_name}}` を文頭に置くと、表示名が空のコンタクトでは「さん、こんにちは」と見える
  （SKILL.md の「埋め込み変数」参照）。空でも成立する形にする。

## 本スキルの対象外（参考値）

以下は一斉配信ではないため**本スキルでは作れない**（ステップ配信・自動応答は `workflow-builder`
スキル、挨拶メッセージ・キーワード自動返信は管理画面の担当）。依頼が来たらそちらへ案内する。
数値は同系統の目安として参考にとどめる。

| 種別 | 目安 | 上限 |
|---|---|---|
| ステップ配信（1吹き出し） | 150〜250字 | 500字 |
| 挨拶メッセージ | 200〜300字 | 500字 |
| キーワード自動返信 | 50〜100字 | 200字 |

## セルフレビューチェックリスト

書き込み（`post` / `patch`）の**前**、Step 3 で内容を提示するときに確認する。

| # | チェック | NG の例 |
|---|---|---|
| 1 | 1配信の目的が1つか（読ませると申し込ませるを混ぜていない） | 講座紹介と別サービスの告知が同じ本文にある |
| 2 | 誘導先の URL が1つに絞れているか | 本文に3本のリンク |
| 3 | CTA 文言が8〜15字で、動詞で終わっているか | 「こちら」「以下をご覧ください」 |
| 4 | 上限文字数を超えていないか（告知500字 / リマインド200字 / `altText` 50字） | 告知の本文が1,200字 |
| 5 | 吹き出しが2〜3個（上限5個）に収まっているか | テキストを7個に細切れ（課金7通） |
| 6 | A（BANリスク）の表現が入っていないか＝収益の断定・誇大表現 | 「誰でも確実に稼げます」「たったこれだけで成功」 |
| 7 | 中身のない形容だけの文が残っていないか | 「充実の内容でお届けします」 |
| 8 | 依頼文に無い事実を書いていないか。**各文が依頼文だけで真偽を判定できるか**を1文ずつ確認する（実績・社会的証明・開催回数・希少性・効果・対象者・所要時間・人数・価格） | 材料なしで「ご好評いただいています」「今回初めて開催します」「満足度98%」 |
| 9 | スマホで読めるか（1行20〜25字・空行・半角数字・絵文字2〜3個まで） | 改行なしで30行のベタ書き |
| 10 | 逐語指定された本文・件名に手を加えていないか | 指定文に絵文字と改行を勝手に足した |

**材料が薄くて物足りなく感じても、文面を膨らませて埋めない。** Step 3 で材料を尋ねるか、短いまま
提示する（短いこと自体は不合格ではない）。
