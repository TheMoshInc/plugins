# リッチメニュー MCP ツールのパラメータ・副作用・エラー

呼び出す直前に、該当する操作の節だけを読む。**ツールの選び分けと承認の要否は SKILL.md が正本、リッチメニュー1件の中身（レイアウト・エリア・上限値）は [menu-schema.md](menu-schema.md) が正本**（本ファイルでは再定義しない）。ここは各ツールの引数・返り値・可否条件・副作用と、**エラーの読み方（正本）**を扱う。

## MCP に無いもの（先に確認する）

| やりたいこと | MCP | 代わりにどうするか |
|---|---|---|
| リッチメニューの**新規作成** | **無い**（作成用のエンドポイントは MCP に公開されていない） | MOSH 管理画面で作成してもらい、作成後の仕上げを MCP で行う |
| 特定のコンタクトへの**個別付与・解除** | **無い** | ワークフローの「個別リッチメニューの付与」アクション（`workflow-builder` スキル） |
| どのワークフローが参照しているかの**調査** | **無い** | 調べられないことを伝え、管理画面での確認を依頼する（SKILL.md §C） |
| 背景画像の**アップロード** | 本スキルの担当外 | `file-share` スキル（[image-preparation.md](image-preparation.md)） |
| **別の LINE公式アカウントへの移動** | **無い**（`creatorLineChannelId` は更新不可） | 移動先アカウントで管理画面から作り直す |

## 一覧（`getCreatorLineRichMenus`）

- 引数: `queryParams.creatorLineChannelId`（任意）。省略すると**そのクリエイターの全アカウント分が返る**
- **ページネーション・並び替え・検索の指定はできない。全件返る**（並びは最終更新日時の降順で固定）
- 返る項目: ID / 名前 / 所属アカウントID / 背景画像の識別子 / **デフォルト設定中か** / **個別リンク中のコンタクト数** / 最終更新日時
- **返らない項目: レイアウト・エリア・メニューバー文言**。中身が必要なら詳細取得を呼ぶ
- **個別リンク中のコンタクト数は、ブロック中・削除済みのコンタクトを除いた数**。デフォルト表示で見えている友だちは含まれない（この数が 0 でも「誰にも見えていない」ことにはならない）

## 詳細取得（`getCreatorLineRichMenu`）

- 引数: `pathParams.id`（リッチメニューID）
- **更新はここから始める**（SKILL.md §A）。返る項目が更新 body の6項目をすべて含む
- 追加で返る項目: 所属アカウントID / デフォルト設定中か / 作成・更新日時
- 他のクリエイターのIDを渡すと「見つからない」になる（存在しないIDと区別できない）

## 更新（`patchCreatorLineRichMenu`）

- 引数: `pathParams.id` と `bodyParams`（**6項目すべて必須**。項目仕様は [menu-schema.md](menu-schema.md)）
- 返るのは成功メッセージのみ。**更新後の内容は返らない**ので、確認が必要なら詳細取得を呼び直す

### 副作用（把握しておく）

**LINE には「リッチメニューの更新」API が無いため、MOSH は毎回 LINE 上に新しいリッチメニューを作り直して古いものを消す。** その結果:

- **公開中のメニューは即座に差し替わる**（下書き状態は存在しない）
- **デフォルト設定中なら、新しいメニューへ自動で付け替えられる**。デフォルト設定はやり直さなくてよい
- **個別リンク中のコンタクトも、新しいメニューへ自動で付け替えられる**（500件ずつ処理）。人数が多いほど時間がかかる
- **途中で失敗すると、MOSH のデータも LINE 側の設定も元に戻そうとする**（付け替え済みの分も戻す）。ただしこの復旧処理自体はベストエフォートで、**復旧に失敗してもエラーとしては返らずログに残るだけ**。したがって「失敗したから元のままのはず」と決めつけず、**失敗を報告する前に `getCreatorLineRichMenu` で現在の内容を確認する**

### 拒否される条件

| 条件 | 返るもの |
|---|---|
| レイアウトとエリア件数が不一致 | 「レイアウトとエリアの数が一致しません。」 |
| LINE公式アカウントが未連携（連携解除済み） | 「LINE公式アカウントが連携されていません。」 |
| 背景画像の識別子が存在しない / まだ準備できていない | 「背景画像の取得に失敗しました。」 |
| 必須項目の欠落・文字数超過・件数超過・URL形式不正 | 入力エラー |
| LINE 側が受け付けない（画像の解像度不一致など） | 「LINEへのリッチメニュー操作に失敗しました。」（**原因を特定できない汎用メッセージ**） |

**最後の行が最も厄介**。MOSH は背景画像の解像度・ファイルサイズを検証せず LINE へ素通しするため、解像度の取り違えはこの汎用メッセージとしてしか現れない。更新前に [image-preparation.md](image-preparation.md) で解像度を確かめておく。

## デフォルト設定（`postCreatorDefaultLineRichMenu`）

- 引数: `bodyParams.lineRichMenuId`
- **「新規作成」ではない。** 既存のメニューを、そのメニューが属する LINE公式アカウントの初期表示に指定するだけ
- **既に別のメニューがデフォルトなら、確認なしで置き換える**（アカウントごとに1つだけ）。実行前に一覧で現在のデフォルトを調べ、名前を挙げて承認を取る（SKILL.md の承認の判定表）
- 対象アカウントは対象メニューの所属アカウントで決まる。アカウントを指定する引数は無い

## デフォルト解除（`deleteCreatorDefaultLineRichMenu`）

- 引数: `bodyParams.lineRichMenuId`（解除したいメニューのID。アカウントIDではない）
- **対象がデフォルトでない場合は何もせず成功を返す**（silent no-op）。「解除しました」と報告すると事実と食い違うので、**実行前に一覧でデフォルト設定中かを確認する**
- 解除するとそのアカウントにデフォルトが無くなり、個別リンクを持たない友だちにはメニューが表示されなくなる

## 削除（`deleteCreatorLineRichMenu`）

- 引数: `pathParams.id`
- **物理削除。復元できない**
- 自動で解除されるもの: デフォルト設定 / 個別コンタクトへのリンク
- **解除されないもの: ワークフローの「個別リッチメニューの付与」アクションに設定されたID**（参照が残り続ける。SKILL.md §C）

**LINE 側の削除に失敗したときの挙動は一様ではない。**

| LINE 側の状況 | 結果 |
|---|---|
| 既に LINE 上に無い（404）/ 操作権限が無い（403）/ アカウントが連携解除済み | LINE 側の掃除を諦めて **MOSH 側の削除は完了する** |
| それ以外の LINE エラー（一時障害など） | **削除そのものが失敗し、メニューは残る**（「LINEへのリッチメニュー操作に失敗しました。」） |

したがって**エラーが返ったときに「削除しました」と報告してはならない。** 削除できたかを確かめるには `getCreatorLineRichMenus` を呼び直す。

## エラーの読み方（正本）

MCP のツール結果には HTTP ステータスコードが含まれず、メッセージだけが返る。

| 返ってくる内容 | 原因 | 対処 |
|---|---|---|
| 見つからない | 存在しないID / 他のクリエイターのID | `getCreatorLineRichMenus` でIDを確認し直す |
| レイアウトとエリアの数が一致しません | `layout` と `areas` の件数が不一致 | [menu-schema.md](menu-schema.md) の対応表で件数を合わせる |
| LINE公式アカウントが連携されていません | 対象メニューの LINE公式アカウントが連携解除済み | MCP では直せない。管理画面での再連携を案内する |
| 背景画像の取得に失敗しました | 画像の識別子が誤っている / アップロード直後で準備が終わっていない | [image-preparation.md](image-preparation.md) の手順で識別子を取り直す |
| LINEへのリッチメニュー操作に失敗しました | LINE 側が受け付けなかった（**更新なら画像の解像度・ファイルサイズ・形式の不一致が最有力**、削除なら LINE の一時障害）／LINE の一時障害 | 更新ならまず解像度・容量・形式を確認する（[image-preparation.md](image-preparation.md)）。削除ならメニューが残っている可能性がある（上の「削除」節） |
| 入力エラー（必須項目・文字数・件数） | body の組み立て漏れ | 詳細取得の値を載せ直す（SKILL.md §A）。文字数は [menu-schema.md](menu-schema.md) の数え方 |

**再試行の可否と、エラー後に状態を確認してから報告することの徹底は SKILL.md「エラーが返ったとき」が正本。**

## 補足: これらの挙動の根拠

MCP に公開されているツールの範囲、一覧・更新・デフォルト設定・削除それぞれの副作用、エラーメッセージの意味は、動作確認済みの記述であり推測ではない。ただし仕様は変わりうる。実際のツール結果が本ファイルの記載と食い違う場合は、実際の挙動を優先する。
