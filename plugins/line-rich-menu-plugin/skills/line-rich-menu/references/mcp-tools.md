# リッチメニュー MCP ツールのパラメータ・副作用・エラー

呼び出す直前に、該当する操作の節だけを読む。**ツールの選び分けと承認の要否は SKILL.md が正本、リッチメニュー1件の中身（レイアウト・エリア・アクション・上限値）は [menu-schema.md](menu-schema.md) が正本**（本ファイルでは再定義しない）。ここは各ツールの引数・返り値・可否条件・副作用と、**エラーの読み方（正本）**を扱う。


## MCP に無いもの（先に確認する）

| やりたいこと | 代わりにどうするか |
|---|---|
| 特定のコンタクトへの**個別付与・解除** | ワークフローの「個別リッチメニューの付与」アクション（`workflow-builder` スキル） |
| どのワークフローが参照しているかの**調査** | 調べられないことを伝え、管理画面での確認を依頼する（SKILL.md §C）。他のメニューの切り替え先になっているかは、同じアカウントのメニューを詳細取得すれば調べられる |
| **別の LINE公式アカウントへの移動** | 更新では移せない。移動先アカウントで同じ内容を**作成**し直す（作成の承認が要る）。元のメニューを消すかは別途確認 |
| Webhook 設定の**確認** | 確認できない。[menu-schema.md](menu-schema.md) の手順をユーザーに案内する |
| 背景画像の**リサイズ** | MCP に無い。手元で加工する（[image-preparation.md](image-preparation.md)） |

## 一覧（`getCreatorLineRichMenus`）

- 引数: `queryParams.creatorLineChannelId`（任意）。省略すると全アカウント分
- **ページネーション・並び替え・検索の指定は無い。全件返る**（最終更新日時の降順で固定）
- 返る項目: ID / 名前 / 所属アカウントID / 背景画像の識別子 / **デフォルト設定中か** / **個別リンク中のコンタクト数** / 最終更新日時
- **返らない項目: レイアウト・エリア・メニューバー文言・タブの切り替え先**。中身が必要なら詳細取得
- **個別リンク数はブロック中・削除済みのコンタクトを除いた数**。デフォルト表示で見えている友だちは含まない（0 でも「誰にも見えていない」ことにはならない）。ワークフローでの付与に加え、**タブ等の切り替えで移った友だちも含む**

## 詳細取得（`getCreatorLineRichMenu`）

- 引数: `pathParams.id`
- **更新はここから始める**（SKILL.md §A）。更新 body の6項目をすべて含む（`areas` の各 `action` は3キーそろって返る）
- 追加で返る項目: 所属アカウントID / デフォルト設定中か / 作成・更新日時
- 他のクリエイターのIDは「見つからない」になる（存在しないIDと区別できない）

## 作成（`postCreatorLineRichMenu`）

- 引数: `bodyParams`（**7項目すべて必須**。項目仕様は [menu-schema.md](menu-schema.md)）
- 返るのは新しいメニューの `id` のみ
- **作っただけでは誰にも表示されない。** 表示されるのは、デフォルト設定（このスキル）・ワークフローでの個別付与（`workflow-builder`）・他のメニューからの切り替え先指定のいずれかをしたとき
- 処理順: アカウント確認 → エリア数確認 → タグ・切り替え先の確認 → 切り替え先の別名作成（無害・失敗しても残る） → 背景画像の取得 → LINE への登録と画像設定 → MOSH に保存。**背景画像の取得までに拒否された場合、メニューは作られない**（別名だけ残ることがある）
- **途中で失敗した場合は、LINE に登録した分と MOSH の行を消して元に戻そうとする**が、この後始末はベストエフォートで、失敗してもログに残るだけ。**エラー後は一覧を取り直して、作りかけのメニューが残っていないか確認する**
- 同じ内容で2回呼ぶと**2つ作られる**（重複チェックは無い）。エラー後に再送する前にも一覧で確認する

## 更新（`patchCreatorLineRichMenu`）

- 引数: `pathParams.id` と `bodyParams`（**6項目すべて必須**）
- 返るのは成功メッセージのみ。**更新後の内容は返らない**

### 副作用（把握しておく）

**LINE には「リッチメニューの更新」API が無いため、MOSH は毎回 LINE 上に新しいリッチメニューを作り直して古いものを消す。** その結果:

- **公開中のメニューは即座に差し替わる**（下書き状態は無い）
- **デフォルト設定中なら新しいメニューへ自動で付け替え**られる。やり直し不要
- **個別リンク中のコンタクトも自動で付け替え**られる（500件ずつ）。人数が多いほど時間がかかる
- **他のメニューのタブ等からの切り替え先になっていても、切り替えは引き続き効く**（MOSH が LINE 側の別名を新しいメニューへ付け替える）
- **途中で失敗すると、MOSH のデータ・デフォルト・個別リンク・別名を元に戻そうとする。** ただしこの復旧はベストエフォートで、**復旧に失敗してもエラーとしては返らずログに残るだけ**。「失敗したから元のままのはず」と決めつけず、**失敗を報告する前に詳細取得で現在の内容を確認する**
- 古い LINE 側メニューの削除に失敗しても更新は成功扱い（ユーザー影響なし）

## デフォルト設定（`postCreatorDefaultLineRichMenu`）

- 引数: `bodyParams.lineRichMenuId`
- **「新規作成」ではない。** 既存メニューを、そのメニューが属する LINE公式アカウントの初期表示に指定するだけ
- **既に別のメニューがデフォルトなら確認なしで置き換える**（アカウントごとに1つ）。実行前に一覧で現在のデフォルトを調べ、名前を挙げて承認を取る
- 対象アカウントはメニューの所属アカウントで決まる。LINE公式アカウントが連携解除済みなら「LINE公式アカウントが連携されていません。」
- 失敗時は LINE 側のデフォルトを直前のものへ戻そうとする（ベストエフォート）

## デフォルト解除（`deleteCreatorDefaultLineRichMenu`）

- 引数: `bodyParams.lineRichMenuId`（解除したいメニューのID。アカウントIDではない）
- **対象がデフォルトでない場合は何もせず成功を返す**（silent no-op）。**実行前に一覧でデフォルト設定中かを確認する**
- 解除するとそのアカウントにデフォルトが無くなり、個別リンクの無い友だちにはメニューが表示されなくなる

## 削除（`deleteCreatorLineRichMenu`）

- 引数: `pathParams.id`
- **物理削除。復元できない**
- 自動で解除されるもの: デフォルト設定 / 個別コンタクトへのリンク / このメニューの切り替え用の別名
- **解除されないもの**: ①ワークフローの「個別リッチメニューの付与」アクションに設定されたID ②**他のメニューの `richMenuSwitch` に設定されたこのメニューのID**（そのボタン・タブは押しても切り替わらなくなり、そのメニューを次に更新するときは切り替え先を直さないと拒否される。SKILL.md §C）

**LINE 側の削除に失敗したときの挙動は一様ではない。**

| LINE 側の状況 | 結果 |
|---|---|
| 既に LINE 上に無い（404）/ 操作権限が無い（403）/ アカウントが連携解除済み | LINE 側の掃除を諦めて **MOSH 側の削除は完了する** |
| それ以外の LINE エラー（一時障害など） | **削除そのものが失敗し、メニューは残る** |

**エラーが返ったときに「削除しました」と報告してはならない。** 一覧を呼び直して確かめる。

## 背景画像のアップロード枠（`postCreatorMaterialImageUpload`）

- 引数: `bodyParams.fileName`（拡張子つき）/ `mimeType`（`image/jpeg` / `image/png` / `image/webp`）/ `fileSizeBytes`（実測値）
- 返り値: `moshMediaId`（これを `backgroundMoshImageId` に使う）と `uploadUrl`（有効期限15分。本体はこちらから PUT する）
- **ここでの検証は形式と 100MB 上限だけ。** リッチメニュー用の条件（[image-preparation.md](image-preparation.md)）は検証されないので、`image/webp` や 1MB 超でも枠は発行される。条件は手元で満たしてから使う
- 手順の全体は [image-preparation.md](image-preparation.md)

## エラーの読み方（正本）

MCP のツール結果には HTTP ステータスコードが含まれず、メッセージだけが返る。

| 返ってくる内容 | 原因 | 対処 | 何か変わったか |
|---|---|---|---|
| 見つからない | 存在しないID / 他のクリエイターのID | 一覧でIDを確認し直す | 変わらない |
| レイアウトとエリアの数が一致しません | `layout` と `areas` の件数が不一致（タブありはタブ2件を含む） | [menu-schema.md](menu-schema.md) の表で件数を合わせる | 変わらない |
| 指定したLINE公式アカウントが見つかりません（作成） | アカウントIDが誤り、または連携解除済み | `getCreatorLineChannels` で連携中のアカウントを確認する | 変わらない |
| LINE公式アカウントが連携されていません（更新・デフォルト設定） | 所属アカウントが連携解除済み | MCP では直せない。管理画面での再連携を案内する | 変わらない |
| 指定されたタグが見つかりません | `contactTagId` に自分のタグでないIDがある | `getCreatorContactTags` で実在するIDに直す | 変わらない |
| 切り替え先のリッチメニューが見つかりません | `richMenuSwitch` のIDが存在しない・**削除済み** | 一覧で実在するIDに直すか `null` にする（詳細取得の値をそのまま載せ直すと、削除済みの切り替え先がここで引っかかる） | 変わらない |
| 切り替え先のリッチメニューを指定できません | 切り替え先が別の LINE公式アカウントのメニュー | 同じアカウントのメニューに直す | 変わらない |
| 背景画像の取得に失敗しました | 画像の識別子が誤っている / **アップロード直後で準備が終わっていない** | 識別子を確かめる。アップロード直後なら SKILL.md「エラーが返ったとき」の例外に従う | 変わらない（作成では切り替え用の別名だけ先に作られることがあるが無害） |
| LINEへのリッチメニュー操作に失敗しました | LINE 側が受け付けなかった（**作成・更新なら画像の解像度・容量・形式の不一致が最有力**だが、LINE 連携情報の失効など LINE 側の 4xx はすべて同じ文言になる。画像を確かめても分からなければ連携状態の確認を案内する。削除・デフォルト操作なら LINE の一時障害等） | 作成・更新はまず画像を確認する（[image-preparation.md](image-preparation.md)）。削除ならメニューが残っている可能性がある | **確定できない**。作成は一覧、更新は詳細取得、削除は一覧で確かめる |
| 内部エラー（理由の書かれていないエラー） | LINE 側の 5xx 等 | 時間を置くかをユーザーに確認する | **確定できない**。上と同じく状態を確かめる |
| 入力エラー（必須項目・文字数・件数・URL形式・余分なキー） | body の組み立て漏れ | 詳細取得の値を載せ直す（SKILL.md §A）。文字数は [menu-schema.md](menu-schema.md) の数え方 | 変わらない |

**再試行の可否と、エラー後に状態を確認してから報告することの徹底は SKILL.md「エラーが返ったとき」が正本。**
