# リッチメニューの構造（正本）

更新（`patchCreatorLineRichMenu`）の body を組み立てる前に読む。**ツールの選び分け・承認の要否・削除の影響は SKILL.md が正本**（本ファイルでは再定義しない）。ここはリッチメニュー1件の中身（レイアウト・エリア・アクション・上限値）を扱う。

> 本ファイルの数値・enum・挙動は動作確認済みの記述であり推測ではない。ただし仕様は変わりうるため、実際のツール結果が本ファイルの記載と食い違う場合は実際の挙動を優先する。

## 更新 body の6項目

| 項目 | 型 | 制約 | 備考 |
|---|---|---|---|
| `name` | string | 1〜300文字 | 管理用の名前。LINE 側にも同名で登録される |
| `layout` | enum | 下表の6値 | サイズ系統とエリア数を同時に決める |
| `backgroundMoshImageId` | string | 1文字以上 | 背景画像の識別子。[image-preparation.md](image-preparation.md) |
| `areas` | array | 1〜6件。**layout と件数一致が必須** | 配列の**順序**が位置に対応する |
| `chatBarText` | string | 1〜14文字 | トーク画面下部のメニューバー文言 |
| `chatBarOpenByDefault` | boolean | — | true でトーク画面を開いたときメニューを開いた状態にする |

**6項目すべてが必須**（部分更新は不可）。`creatorLineChannelId` は body に存在せず更新できない。

### 文字数の数え方（`name` / `chatBarText`）

上限は **JavaScript の文字列長（UTF-16 コードユニット数）** で判定される。したがって:

- ひらがな・漢字・全角記号は 1 文字
- 絵文字の多く（😀 など基本多言語面の外にあるもの）は **2 文字**として数えられる。「👍メニュー」は 7 ではなく 8 と数えられる
- 異体字セレクタや肌色修飾子つきの絵文字はさらに増える

**「14文字以内だから大丈夫」と目視で判断しない。** 絵文字を含む文言を入れるときは、コードユニット数で数えて 14 以下であることを確認する。超過すると更新は 400 で拒否される（loud fail）。

**検証手順（暗算で数えない）**: 候補文言を1文字ずつ書き出し、絵文字・サロゲートペア文字（Unicode コードポイントが U+10000 以上のもの）は `2`、それ以外は `1` として1文字ずつ加算する。目視の「だいたい14文字」は誤りやすい（実例: 「👍タップしてメニューを開く」を目視で13文字と数えたケースが実際にあったが、正しくは 👍=2 + タップしてメニューを開く(12文字×1) = **14**。超過はしていないが余裕ゼロで、1文字でも増やせば見逃す)。

- 合計がちょうど14、または13〜14に近い場合は、絵文字を減らすか文言を短くして余裕を持たせるようユーザーに提案する
- 迷ったら実際にコードで確認してよい（Bash が使える場合: `node -e 'console.log([...候補文言に置き換え].length)'` は Unicode 文字数であり **UTF-16 コードユニット数とは異なる**ため使わない。正しくは `node -e "console.log(\"文言\".length)"` のように JS 文字列リテラルの `.length` を使うこと）

## レイアウトの6値

| `layout` | サイズ系統 | エリア数 | ラベル | 必要な背景画像 |
|---|---|---|---|---|
| `SIX_SPLIT` | 大 | 6 | A〜F | 1200×810 px |
| `TOP_ONE_BOTTOM_THREE` | 大 | 4 | A〜D | 1200×810 px |
| `LEFT_RIGHT_SPLIT` | 大 | 2 | A, B | 1200×810 px |
| `ONE_BLOCK` | 大 | 1 | A | 1200×810 px |
| `THREE_SPLIT` | 小 | 3 | A〜C | 1200×405 px |
| `ONE_BLOCK_SMALL` | 小 | 1 | A | 1200×405 px |

**layout とエリア件数が一致しないと、更新は 400「レイアウトとエリアの数が一致しません。」で拒否される**（loud fail）。レイアウトを変えるときは必ず `areas` の件数も合わせる。

**サイズ系統（大/小）を答えるときは必ずこの表を参照する。記憶や分割数の印象で判定しない。** 特に `LEFT_RIGHT_SPLIT`（2分割）は分割数が少なく見た目の印象から「小」と誤認しやすいが、実際は**大サイズ（1200×810px）**。逆に `THREE_SPLIT`（3分割）は分割数が多くても**小サイズ（1200×405px）**。分割数とサイズ系統は連動しない。

## エリアの位置（配列の順序が位置）

各エリアは**配列のインデックス**で画面上の座標に割り当てられる。`label` はユーザー向けの表示用で、位置の決定には**使われない**。

したがって `areas` を並べ替えると、ラベルと実際の位置がズレたまま保存される（この silent fail の扱いは SKILL.md §B）。**ラベルは常に `A` から順に、下表の位置順に並べる。**

座標（px。左上原点）:

| `layout` | index 0 (A) | index 1 (B) | index 2 (C) | index 3 (D) | index 4 (E) | index 5 (F) |
|---|---|---|---|---|---|---|
| `SIX_SPLIT` | 左上 (0,0,400×405) | 中上 (400,0) | 右上 (800,0) | 左下 (0,405) | 中下 (400,405) | 右下 (800,405) |
| `TOP_ONE_BOTTOM_THREE` | 上全幅 (0,0,1200×405) | 左下 (0,405,400×405) | 中下 (400,405) | 右下 (800,405) | — | — |
| `LEFT_RIGHT_SPLIT` | 左 (0,0,600×810) | 右 (600,0,600×810) | — | — | — | — |
| `ONE_BLOCK` | 全面 (0,0,1200×810) | — | — | — | — | — |
| `THREE_SPLIT` | 左 (0,0,400×405) | 中 (400,0) | 右 (800,0) | — | — | — |
| `ONE_BLOCK_SMALL` | 全面 (0,0,1200×405) | — | — | — | — | — |

**背景画像のデザインとこの区切りが一致しているかは、誰も検証しない。** 解像度が合っていても、画像内のボタンの境界がこの座標とズレていれば、押した見た目と違う動作をするメニューがそのまま公開される（silent fail）。画像を差し替えるときは、レイアウトの区切りと画像の意匠が合っているかをユーザーに確認する。

## エリアのアクション（`action`）

```json
{ "label": "A", "action": { "url": null, "postbackActions": null } }
```

`url` と `postbackActions` は**両方のキーが常に必須**。使わない側に `null` を入れる（キーごと省くと 400）。

| `url` | `postbackActions` | 実際の動作 |
|---|---|---|
| 設定あり | `null` | タップで URL を開く |
| `null` | 設定あり | タップでアクション（メッセージ送信 / タグ付与 / タグ削除）を実行する |
| 設定あり | 設定あり | **URL を開き、あわせてアクションも実行される**（MOSH の中継ページを経由して遷移する）。**アクションの失敗は遷移を止めない**ため、「ページは開いたがタグが付かない」という部分的な失敗が起こりうる |
| `null` | `null` | **何も起きない。エラーにもならない**（silent fail）。この組み合わせを作らない |

### `url`

- 1000文字以内で、**URL として妥当な形式**であること（形式が不正だと 400）
- ユーザーが「〇〇のページに飛ばして」と言っただけで URL が分からないときは**推測して組み立てない**。ユーザーに確認する

### `postbackActions`

配列で **1〜3件**（`null` にするなら配列ごと `null`。空配列 `[]` は 400）。要素は次の3種のいずれか。

**メッセージを送る**

```json
{
  "postbackActionType": "sendMessage",
  "messages": [{ "messageType": "text", "message": "お問い合わせありがとうございます！" }]
}
```

- `messages` は **1件のみ**（2件以上は 400）。`messageType` は `text` のみ
- `message` は 1〜5000文字
- 本文中の URL は配信時に短縮URLへ置換される（トラッキング）

**タグを付ける / 外す**

```json
{ "postbackActionType": "addContactTag", "contactTagId": 123 }
{ "postbackActionType": "removeContactTag", "contactTagId": 123 }
```

- **`contactTagId` は保存時に実在確認されない**。誤ったIDを入れても保存時にはエラーにならず、友だちがタップした時点まで問題が表面化しない。事前確認の手順は SKILL.md §D

## 補足: これらの値・挙動の根拠

更新 body の必須項目・文字数上限・件数上限、layout とエリア数・座標の対応、`label` が位置決定に使われないこと、`url`/`postbackActions` の優先順位と組み合わせごとの挙動、`contactTagId` が保存時に実在確認されないことは、動作確認済みの記述であり推測ではない。ただし仕様は変わりうるため、実際のツール結果が本ファイルの記載と食い違う場合は実際の挙動を優先する。
