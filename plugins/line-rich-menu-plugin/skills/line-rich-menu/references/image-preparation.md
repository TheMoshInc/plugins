# 背景画像の準備

新しく作るとき、背景画像を差し替えるとき、レイアウトを変えて画像の描き直しが要るときに読む。**レイアウトごとに必要な解像度・タブの帯の位置・描き直しが要る変更は [menu-schema.md](menu-schema.md) が正本**（本ファイルでは再定義しない）。ここは「その画像をどう用意し、識別子をどう得るか」を扱う。


## 大前提: リッチメニュー側は画像の中身を検証しない

| どこで | 何を検証するか |
|---|---|
| 管理画面（ブラウザ） | 形式 JPEG/PNG・1MB 以下・px 完全一致（MCP では通らない） |
| アップロード枠の発行（`postCreatorMaterialImageUpload`） | 形式 JPEG/PNG/**WebP**・**100MB** 以下だけ |
| リッチメニューの作成・更新 | **画像を取得できるかだけ。** 解像度・容量・形式は見ずに LINE へ転送する |

したがって:

- 条件違反は、LINE に拒否されるとしても「LINEへのリッチメニュー操作に失敗しました。」という**原因の分からないエラー**としてしか返らない
- 拒否されなければ**そのまま公開される**。とくに「解像度は正しいが画像の区画がボタンの区切りと合っていない」「タブありなのに上 180px にタブが描かれていない」は誰にも検出されない（silent fail）

**画像はこちらで実測してから使う。** 「たぶん合っている」で進めない。

## 満たすべき条件

| 項目 | 条件 |
|---|---|
| 解像度 | 作成・更新後の `layout` に対応した **px 完全一致**（[menu-schema.md](menu-schema.md)） |
| ファイルサイズ | **1MB 以下** |
| 形式 | **JPEG または PNG**（WebP は枠の発行は通るが使えない） |
| 意匠 | ボタンの区切りと画像の区画が一致。タブありは上 180px に左右2つのタブを描く |

## 手順

### 1. 必要な解像度を確定する

**作成・更新後の `layout` で判定する**（レイアウト変更なら変更後。管理画面はサイズが変わると画像を自動でクリアするが、MCP にはその保護が無い）。

### 2. 手元の画像を実測する

```bash
sips -g pixelWidth -g pixelHeight "<画像パス>"   # 解像度
wc -c < "<画像パス>"                             # bytes
file --mime-type -b "<画像パス>"                 # 形式
```

### 3. 合っていなければ加工する

**引き伸ばし・切り抜き・余白追加はユーザーの意図を変えるので勝手に決めない。** 縦横比が違うときはどうするかを確認してから実行する。

```bash
sips -z <高さ> <幅> "<入力パス>" --out "<出力パス>"            # 指定 px ちょうどに（縦横比が違うと変形する）
sips -s format jpeg -s formatOptions 80 "<入力>" --out "<出力>.jpg"  # 1MB を超える PNG を JPEG にする
```

加工後は**手順2で再実測**し、px ちょうど・1MB 以下・JPEG/PNG を確かめる。

### 4. 識別子（`moshMediaId`）を得る

**(a) のアップロードは、作成・更新の承認を得た後に行う**（SKILL.md 承認の判定表）。承認前に済ませてよいのは手順1〜3（実測・加工）まで。却下された場合に使われない画像を残さないため。

次のどちらか。**識別子を推測・創作しない。**

**(a) 手元の画像を上げる（通常はこちら）**

1. `postCreatorMaterialImageUpload` に `fileName`・`mimeType`（`image/jpeg` か `image/png`）・`fileSizeBytes`（実測値）を渡し、`moshMediaId` と `uploadUrl` を受け取る
2. 本体を送る（`uploadUrl` は発行から15分で失効。切れたら1からやり直し、古い `moshMediaId` は捨てる）

   ```bash
   curl -sS -X PUT --fail-with-body -H "Content-Type: <mimeType>" --upload-file "<画像パス>" "<uploadUrl>"
   ```

3. 返った `moshMediaId` を `backgroundMoshImageId` に入れる

- **ファイル共有への登録（`postCreatorMaterialImage`）はしない。** リッチメニューには不要で、登録すると共有URLが発行された「ファイル共有」の項目が増える
- 送信直後は MOSH 側の準備が終わっておらず、作成・更新が「背景画像の取得に失敗しました。」になることがある。扱いは SKILL.md「エラーが返ったとき」

**(b) ファイル共有に登録済みの画像を使う**

`getCreatorMaterialImage` の返り値の `moshMediaId` を使う（準備は完了済み）。この場合も、返り値の画像URLから `curl -sSo` で手元に取得し、**手順2の条件を確かめてから**使う（ファイル共有の画像はリッチメニュー用の寸法とは限らない）。

### 5. 作成・更新に反映する

- 作成: 7項目の body の `backgroundMoshImageId` に入れる
- 更新: 詳細取得した body の `backgroundMoshImageId` だけを差し替え、他の5項目はそのまま（SKILL.md §A）。レイアウトも変えるなら `layout` と `areas` も合わせる（SKILL.md §B）

## ユーザーへの伝え方

- 「画像の識別子」「moshMediaId」を**見せない・控えさせない**
- 用意を依頼するときは**必要な条件を数値で伝える**（例:「1200×810ピクセル、1MB以下のJPEGかPNG。タブありの場合は上から180ピクセルの帯に左右2つのタブを描いてください」）。ここだけは数値をそのまま伝えてよい
- 加工した場合は**どう加工したか（変形・余白・切り抜き・形式変換）を報告に含める**
