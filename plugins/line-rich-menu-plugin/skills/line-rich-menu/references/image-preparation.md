# 背景画像の準備

背景画像を差し替えるとき、またはレイアウトのサイズ系統（大↔小）を変えるときに読む。**レイアウトごとに必要な解像度は [menu-schema.md](menu-schema.md) が正本**（本ファイルでは再定義しない）。ここは「その解像度の画像をどう用意し、識別子をどう得るか」を扱う。

## 大前提: 検証はブラウザの入力画面にしか無い

背景画像の**解像度・ファイルサイズ・形式のチェックは、MOSH 管理画面のブラウザ側だけ**に実装されている。MCP から更新するときは:

- **MOSH のサーバーは画像を検証しない。** 識別子で画像を取ってきて、そのまま LINE に転送するだけ
- したがって不一致は、拒否されるとしても **「LINEへのリッチメニュー操作に失敗しました。」という原因の分からない汎用メッセージ**としてしか返らない（[mcp-tools.md](mcp-tools.md)）
- **拒否されなかった場合はそのまま本番に公開される。** とくに「解像度は正しいが、画像の意匠の区切りがレイアウトの区切りと合っていない」ケースは誰にも検出できず、押した見た目と違う動作をするメニューが友だち全員に出る

**したがって、画像はこちら側で寸法を実測してから使う。** 「たぶん合っている」で更新に進まない。

## 満たすべき条件

| 項目 | 条件 |
|---|---|
| 解像度 | レイアウトのサイズ系統に対応した **px 完全一致**（[menu-schema.md](menu-schema.md) の対応表） |
| ファイルサイズ | **1MB 以下** |
| 形式 | **JPEG または PNG**（WebP は使えない） |

（管理画面の入力チェックと同じ条件。MCP 経由でも LINE 側の要件は変わらないため同じ条件を満たす必要がある。）

## 手順

### 1. 必要な解像度を確定する

更新後の `layout` から決まる。**レイアウトを変える依頼では、変更後のレイアウトで判定する**（変更前の画像をそのまま使い回すと不一致になる。管理画面はサイズ系統が変わると画像を自動でクリアするが、MCP にはその保護が無い）。

### 2. 手元の画像を実測する

```bash
# 解像度（幅 x 高さ）
sips -g pixelWidth -g pixelHeight "<画像パス>"
# ファイルサイズ（bytes）と形式
wc -c < "<画像パス>"
file --mime-type -b "<画像パス>"
```

### 3. 合っていなければリサイズしてから使う

**引き伸ばし・切り抜きはユーザーの意図を変える操作なので、勝手に決めない。** 縦横比が違う画像を渡されたときは、余白を足すのか切り抜くのかをユーザーに確認する。確認が取れたら実行する。

```bash
# 指定 px ちょうどにリサイズする（縦横比が違う場合は変形するので、上の確認後に使う）
sips -z <高さ> <幅> "<入力パス>" --out "<出力パス>"
```

リサイズ後は**手順2でもう一度実測して、目的の px ちょうどになっていること・1MB 以下であることを確認する**。

### 4. アップロードして識別子を得る（`file-share` スキルに委ねる）

**アップロード手順そのものは本スキルの担当ではない。** `file-share`スキルの手順に従い、画像をアップロードして登録まで完了させる。本スキルはその結果として得られる**画像の識別子（`moshMediaId`）**だけを受け取る。

- 登録まで完了させる理由は2つ。**識別子が確定すること**と、**登録が「画像の準備完了」を待ってから通るため、準備完了の確認を兼ねられること**
- 登録を省いて識別子だけを先に使うと、準備が終わる前に更新が走り「背景画像の取得に失敗しました。」になる
- **識別子を推測・創作しない。** アップロードの結果として得られた値だけを `backgroundMoshImageId` に入れる
- アップロードは `file-share` 側の承認ルールに従う（本スキルの承認の判定表とは別物なので、上書きしない）

### 5. 更新に反映する

`getCreatorLineRichMenu` で取得した body の `backgroundMoshImageId` だけを新しい識別子に差し替え、他の5項目はそのまま載せて `patchCreatorLineRichMenu` を呼ぶ（SKILL.md §A）。レイアウトも変える場合は `layout` と `areas` の件数も同時に合わせる（SKILL.md §B）。

## ユーザーへの伝え方

- 「画像の識別子」「moshMediaId」を**ユーザーに見せない・控えさせない**。使うのはこちらなのでユーザーが持つ必要は無い
- 適切な画像が用意できないときは、**必要なサイズ（例:「1200×810ピクセル、1MB以下のJPEGかPNG」）を伝えて用意を依頼する**。ここだけは数値をそのまま伝えてよい（ユーザーが作業するのに必要な情報のため）
- 勝手にリサイズした場合は、**どう加工したか（変形したのか余白を足したのか）を報告に含める**

## 補足: これらの条件の根拠

上記の解像度・ファイルサイズ・形式の条件、検証がブラウザ側にしか実装されていないこと、識別子の扱いは、動作確認済みの記述であり推測ではない。ただし仕様は変わりうる。実際のエラーメッセージや管理画面の挙動が本ファイルの記載と食い違う場合は、実際の挙動を優先する。
