# ファイル共有 MCP ツールのパラメータ・状態条件

呼び出す直前に、該当する操作の節だけを読む。**ツールの選び分けと承認の要否、共有URLの組み立て方は SKILL.md が正本**（本ファイルでは再定義しない）。ここは各操作のパラメータ・レスポンス・可否条件・不可逆性と、**エラーの読み方（正本）**を扱う。

> 本ファイルの制約・enum・上限は MOSH の API スキーマ定義とバックエンド実装で確認したもの（2026-08-21 時点）。
> 値を書き換えるときは、記憶や推測ではなくスキーマ定義・実装で裏取りする。

## 素材の3種別

| 種別 | 中身 | 一覧上の種別値 |
|---|---|---|
| 動画 | Mux で変換して配信する動画 | `video` |
| 画像 | JPEG / PNG / WebP | `image` |
| PDF | **PDF のみ**（他の文書形式は扱えない） | `file` |

**ID は3種で共通の連番。種別が違うツールに ID を渡すと 404 になる**（画像の ID で動画の詳細取得を呼ぶ等）。所有者が違う ID、素材IDと共有リンクIDの組み合わせ違いも同じ 404 になる。

## 一覧（`getCreatorMaterials`）

- **引数を取らない。全件返る**（ページネーション・フィルタ・並び替えの指定はできない）。並びは作成日の新しい順で固定
- 返る項目: ID / タイトル / 種別 / 処理状況 / 再生時間（秒。画像・PDFは 0）/ ファイルサイズ / サムネイルURL / 作成日時 / 更新日時
- **返らない項目: 共有リンクの識別子（slug）・PDF のファイル本体URL・ファイル本体の識別子（`moshMediaId`）**
- **処理状況は画像・PDF では常に `READY` を返す**（動画用の enum を流用しているだけで、実際の処理結果を表さない）。意味を持つのは動画のみ
- したがって**一覧を提示するとき、画像・PDF については状態を書かない。** 「使える状態です」「準備完了」等と書くと、根拠の無い断定になる（同じ応答内で「状態表示は実際の処理状況を表さない」と注意しながら表では「使えます」と書く、という自己矛盾が起きやすい）。状態を伝えるのは動画だけにする
- サムネイルURLの中身は種別で違う。**画像は画像本体URL そのもの**（詳細取得で返る本体URLと同じソース・同じ値）。**動画は OGP 画像の本体URL**、無ければ変換済みのサムネイル、変換前は空文字。**PDF は常に空文字**（一覧では固定のアイコンで表示される）
- したがって**一覧を呼ぶだけでもファイル本体のURLが手に入る**。配布用に渡してはならない対象に含まれる（下の「配布に使わないURL」）
- サムネイルURLの空文字は「画像が無い」とは限らない。取得に失敗したときも空文字になるため、**空文字から「画像が設定されていない」と断定してはならない**
- ファイルサイズは**作成時に申告された値**で、実体との一致は保証されない（画像・PDF では作成時に再計測しない）

処理状況の値: `WAITING_UPLOAD` / `PROCESSING` / `READY` / `ERRORED`

## 詳細取得（`getCreatorMaterialVideo` / `getCreatorMaterialImage` / `getCreatorMaterialFile`）

パスパラメータは素材 ID のみ。**更新はここから始める**（次節）。

| 種別 | 返る主な項目 |
|---|---|
| 動画 | タイトル / 処理状況 / 再生用の識別子とトークン群 / 再生時間 / ファイルサイズ / サムネイルURL / **OGP画像の識別子** / OGP画像URL / 作成・更新日時 |
| 画像 | タイトル / **ファイル本体の識別子（`moshMediaId`）** / ファイルサイズ / **画像本体URL** / 作成・更新日時 |
| PDF | タイトル / **ファイル本体の識別子（`moshMediaId`）** / ファイルサイズ / **ファイル本体URL** / 作成・更新日時 |

- **動画が `READY` でないときは、再生用の識別子・トークン・サムネイルURLがすべて `null` ではなく空文字になり、再生時間は 0 になる。** 空文字を「値がある」と読み違えない
- 返る URL のうち**配布に使ってはならないもの**があるので、次節を必ず読む

### 配布に使わないURL（対象と根拠。ルールの正本は SKILL.md §B）

| 対象 | 出どころ | 失効させられるか |
|---|---|---|
| 画像・PDF の本体URL | 詳細取得 | **できない**。素材の削除は MOSH のデータベース上のレコードを消すだけで、本体（Core Media 側の実体）を削除する経路が無い。URL 自体の有効期間は Core Media 側の仕様に依存し、MOSH 側では確認できていない |
| 動画の OGP 画像URL | 詳細取得 | 同上（Core Media 側の実体） |
| 動画のサムネイルURL | 詳細取得・一覧 | OGP 画像が無い場合は配信側（Mux）の**期限付きURL（数時間で失効）**。素材の状態に連動して止められるわけではない |
| 一覧のサムネイルURL | 一覧 | 画像は本体URLそのもの、動画は上の2つのいずれか。**一覧を呼ぶだけで手に入る** |

ツール説明との優先関係（説明は「公開 URL として配布可能」と書いている）と、配信側スキルへ渡す用途の禁止は **SKILL.md §B / When NOT to use** が正本。

## 更新（`patchCreatorMaterialVideo` / `patchCreatorMaterialImage` / `patchCreatorMaterialFile`）

**全項目必須の全置換。部分更新はできない。** タイトルだけ変える場合も、詳細取得で得た他の項目をそのまま送り直す。

| 種別 | 必須項目 | 補足 |
|---|---|---|
| 動画 | `title` / `ogpImageMoshMediaId` | **ファイル本体は差し替えられない。** OGP画像を消したいときだけ `ogpImageMoshMediaId` に**空文字**を渡す（`null` は使えない）。消す意図が無いなら詳細取得の値をそのまま渡す |
| 画像 | `title` / `moshMediaId` / `fileSizeBytes` | 本体を差し替えるときだけ `moshMediaId` と `fileSizeBytes` を新しい値にする |
| PDF | `title` / `moshMediaId` / `fileSizeBytes` | 同上 |

- `title` は1文字以上（空文字にできない＝タイトルを消す操作は無い）。**文字数の上限は無い**
- **画像・PDF の更新では、渡した `moshMediaId` が実際にアップロード済みかを検証しない。** 未アップロードや存在しない識別子を渡すと**エラーにならずに保存され**、表示できないファイルができる（無言の失敗）。ファイルサイズの上限も更新時は再検証されない
- 本体を差し替えたのにサイズを旧値のままにすると、表示されるファイルサイズだけが嘘になる（これもエラーにならない）
- **本体を差し替えるには、先にアップロード枠を発行して実体を送る必要がある**（[upload-guide.md](upload-guide.md)）

## 削除（`deleteCreatorMaterialVideo` / `deleteCreatorMaterialImage` / `deleteCreatorMaterialFile`）

- **物理削除で復元できない。** 発行済みの共有リンクは全て削除され、共有URL（`/materials/<slug>`）は開けなくなる
- **失効するのは共有URLだけ。** 画像・PDF の本体URLを配ってしまった場合は取り消せない（上の詳細取得の節）
- **参照中チェックは無い。** そのファイルがどこから参照されているかを調べる手段も無いため、「使われていないファイル」を MCP から判定することはできない
- 動画は配信側（Mux）のデータも削除される（失敗しても MOSH 側の削除は完了したままになる）

## 共有リンク（コンテンツリンク）

共有リンクは「1つのファイルに対して複数発行できる公開URLのレコード」。項目は 識別子(`id`) / `slug`（URL に埋め込む UUID）/ `expiresAt`（期限。`null` は無期限）/ 作成日時。**共有URLの組み立て方は SKILL.md §B が正本。**

### 一覧（`getCreatorMaterialContentLinks`）

- パスパラメータは素材 ID
- **期限切れのリンクも含めて全件返る。** 共有URLとして使えるのは `expiresAt` が `null` か未来のものだけ
- ただし**現状 `expiresAt` に値を書き込む経路がリポジトリに存在せず、実際に返るリンクはすべて無期限**（`null`）。仕様上は期限切れも返り得るという前提で書かれているが、期限切れを実際に見ることは今は無い

### 発行（`postCreatorMaterialContentLink`）

- パスパラメータは素材 ID のみ。**リクエストボディを取らない＝期限を指定できない。発行されるリンクは必ず無期限になる**
- 定義に無い項目（`expiresAt` など）を渡しても**エラーにならず黙って無視される**（MCP 側の検証が定義外の項目を捨てるため）。「期限付きリンクを作った」と誤認しない
- **ファイルを新規作成すると、共有リンクが1本自動で発行される**（動画・画像・PDF いずれも）

### 削除（`deleteCreatorMaterialContentLink`）

- パスパラメータは 素材 ID と 共有リンクの識別子の**両方**
- **物理削除。そのURLでの閲覧が即座にできなくなり、元に戻せない。** ファイル本体と他の共有リンクは残る
- 期限を後から設定する手段が無いため、共有URLの配布を止める唯一の方法がこのツール

## エラーの読み方（正本）

MCP のツール結果には HTTP ステータスコードが含まれず、メッセージだけが返る。

| 返ってくる内容 | 原因 | 対処 |
|---|---|---|
| 素材・リンクが見つからない | 種別違いのツールを呼んだ / 他人の ID / 素材IDとリンクIDの組み合わせ違い / 既に素材化した動画のアップロード枠を再利用した | `getCreatorMaterials` で種別と ID を確認し直す。動画は枠を発行し直す |
| アップロードが完了していません（画像・PDF の登録） | 送信直後で変換が終わっていない | **再試行してよいクラス**（SKILL.md「エラーが返ったとき」）。同じ値のまま数秒待って登録だけをやり直す（[upload-guide.md](upload-guide.md) の該当節。回数上限あり） |
| アップロードが完了していません（動画の登録） | 変換が `READY` に達していない | **同じ再試行クラス。** `getCreatorMaterialVideoUpload` で `READY` を待ってから登録だけをやり直す |
| ファイルサイズが大きすぎる / 対応していない形式 | 上限超過・許可されていない形式 | [upload-guide.md](upload-guide.md) の上限表。**同じファイルで再試行しない** |
| 必須項目が足りない | 更新で全項目を送っていない | 詳細取得の値を載せ直す |
| アップロード先URLでの送信が失敗する | 期限切れ | 枠を発行し直す（識別子も変わるので古い値は捨てる） |

上の表で「再試行してよいクラス」と書かれていないものは**再試行せず**、原因と対処をユーザーに平易な日本語で伝える（SKILL.md の提示規約）。
