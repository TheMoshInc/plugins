# トレース: 条件で選んだ顧客に、新しいタグを作って付けるとき

書き込みを伴う依頼の完全トレース。対象の確定 → タグの解決 → 承認 → 実行 → 読み戻し、の順で進める（SKILL.md Workflow 4、必須ルールD）。

## 発話

> 「オンライン英会話コースのサブスクを継続中の人に『英会話2026』ってタグを付けておいて」

## やってはいけない処理

- いきなり `postCreatorCustomerTags` を対象者の人数分呼ぶ（既存タグの付与は一括ツールで足りる。承認も取っていない）
- `postCreatorContactTags`（コンタクトタグ）で代用する
- 対象者を検索せずに「付与しました」と報告する
- 一覧に「英会話 2026」（半角スペース入り）があるのに、確認せず別タグ「英会話2026」を新規作成する

## 正しい処理

### 1. 対象の顧客を確定する

`product-navigator` で「オンライン英会話コース」の商品プランを特定し、`moshServiceId`（例: `"481"`）を得る。サブスク型なので `subscriptionIds: [481]`、継続中なので `subscriptionState: "active"` で `postCustomersSearch` を呼ぶ。

→ `totalCount: 132`。100 件ずつ `page: 1, 2` で `customers[].id` を全員分集める（件数を確かめたうえでの取得なので、名簿はユーザーに展開しない）。

### 2. タグを解決する

`getCreatorCustomerTags` を呼ぶ。「英会話2026」と**完全一致**するタグは無く、似た名前も無い → 新規作成になる。

### 3. 承認を取る

> 次の内容でタグを付けます。よろしいですか？
>
> - タグ: 「英会話2026」（**新しく作成**します）
> - 対象: オンライン英会話コースのサブスクを継続中の顧客 **132 名**
> - 付与のみで、ほかのタグは変更しません
>
> ※作ったタグの名前変更・削除は MOSH の管理画面からの操作になります。

ユーザー「OK」。

### 4. 実行

1. 1人目（`customers[0].id` = 1001）に `postCreatorCustomerTags`:
   ```json
   { "bodyParams": { "name": "英会話2026", "customerId": 1001 } }
   ```
   → `{ "id": "57", "name": "英会話2026" }`
2. 残り 131 名を 100 名＋31 名に分けて `postCreatorCustomerTagCustomers`:
   ```json
   { "pathParams": { "id": "57" }, "bodyParams": { "customerIds": [1002, 1003, "...100件まで"] } }
   ```

### 5. 読み戻し・報告

数名を `getCreatorCustomer` で確認し、`tags[]` に「英会話2026」があることを見てから報告する。

> オンライン英会話コースのサブスクを継続中の 132 名に、新しく作った顧客タグ「英会話2026」を付けました。

## 途中で失敗した場合

2回目の一括付与（31 名）が 404 で返った場合、その 31 名のうち途中までは付いている。

- 「顧客が見つからない」ので、対象から外れた人（直前に退会した等）がいる可能性を伝える
- 同じ 31 名で再実行しても二重には付かないが、見つからない顧客が含まれる限り同じ所で止まる。`getCreatorCustomer` で1人ずつ当たって原因の顧客を特定し、外して再実行する
- 報告は「101 名は付与済み、残り 31 名のうち一部で失敗」のように、確かな範囲だけを書く

## 外す依頼の場合

> 「さっきの人たちから『英会話2026』を外して」

`getCreatorCustomerTags` で id `"57"` を確認 → 人数を示して承認 → `deleteCreatorCustomerTagCustomer` を1人ずつ（`{ "pathParams": { "id": "57", "customerId": 1001 } }`）。一括解除のツールは無いので、人数が多いときは呼び出し回数が多くなることも承認時に伝える。タグ自体は消えない（消すのは管理画面）。
