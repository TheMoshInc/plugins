# トレース: タグ名で顧客を絞りたいと言われたとき

このスキルで最も間違えやすい依頼。顧客タグの ID は MCP から一覧できず、コンタクトタグの ID を代用すると**エラーにならずに間違った結果が返る**（SKILL.md 必須ルールA）。

## 発話

> 「VIPタグが付いてる顧客だけ一覧で出して」

## やってはいけない処理

1. `getCreatorContactTags` を呼ぶ → 「VIP」という名前のコンタクトタグが見つかる（id: `cta_8821`）
2. その id を `tagIds: ["cta_8821"]` に入れて `postCustomersSearch` を呼ぶ
3. `totalCount: 0` が返る
4. 「VIPタグの顧客はいませんでした」と答える

**何が起きたか**: 顧客タグとコンタクトタグは別のID体系なので、渡した id はどの顧客タグにも一致しない。実際には VIP 顧客がいても 0 件になる。エラーが出ないので、間違いに気づけないまま誤った報告をしてしまう。

## 正しい処理

### 1. タグの種類を確認する

顧客タグ（顧客一覧の絞り込み用）の話なのか、コンタクトタグ（LINE友だち・メール購読者につけるタグ）の話なのかを確認する。「顧客」と言われている以上は顧客タグとして扱うが、**どちらのタグかで対象がまったく別物になる**ことを踏まえて確認する。

### 2. 顧客タグの ID は取得できないことを踏まえて進める

`getCreatorContactTags` は**呼ばない**（別体系のため代用にならない）。ID をユーザーから得られない限り、`tagIds` は空配列のままにする。

### 3. 実行できる範囲で実行し、選択肢を提示する

タグ以外に絞り込める条件がなければ、条件なしで1ページ目を取得し、結果に含まれる顧客タグ（`customers[].tags[]`）を手がかりにできるか見る。ただしこれは**返ってきた顧客が持っているタグ**だけなので、「VIP」が出てこなくても存在しないとは限らない。

呼ぶツール:

```json
{
  "bodyParams": {
    "serviceIds": [], "subscriptionIds": [], "eventDateTime": null,
    "searchQuery": "", "subscriptionState": null, "paymentMethod": null,
    "paymentType": null, "paymentStatus": null, "isEmailReceivingAllowed": null,
    "tagIds": [], "excludeTagIds": [], "userIds": [],
    "page": 1, "limit": 10
  }
}
```

### 4. ユーザーへの応答

> 顧客タグでの絞り込みは、こちらからタグを一覧して選ぶことができないため、そのままでは実行できません。
>
> 進め方は2つあります。
>
> 1. MOSH の管理画面「顧客一覧」のフィルターで「顧客タグ」に VIP を選ぶと、その場で絞り込めます
> 2. 管理画面で VIP タグの ID が分かれば教えてください。こちらで絞り込んで一覧をお出しします
>
> なお、顧客全体は現在 248 名です。タグ以外（サブスクが継続中の方、メール受信中の方など）でよければ、その条件で絞ってお出しできます。

**ポイント**

- 「タグ一覧を取得するツールが無い」という仕組みの説明をしない（提示規約）
- 0 件と誤って報告しない
- 代わりにできること（管理画面の案内・他条件での絞り込み）を必ず添える
- 内部の値（`tagIds`・id 文字列・JSON）を応答に出さない

## 続き: ユーザーが ID を教えてくれた場合

> 「VIPタグのIDは 12 でした」

`tagIds: ["12"]` を入れて実行する（[search-body.json](search-body.json) の `tag-filter-with-known-ids`）。結果が 0 件だった場合は、ID の取り違え（コンタクトタグの ID を渡していないか）をユーザーと一緒に確認してから、条件を変えて再実行する。
